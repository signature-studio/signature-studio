## 何が起きたか

- 呼び先のスロットを RVA 0x3500A0 と書いた。正しくは RVA 0x3503A0。出典: 生成 C `work-r56e/gen2/src/m11-02.c:110847`(`L_92155ff: R[0] = fle_ld(UINT64_C(0x93503a0), 8)`)。PEQ2 の `mov rax,[rip+0x13ad9a]`(0x215606 の直前)は 0x215606 + 0x13AD9A = 0x3503A0 を指す。
- この誤った番地から、計測 2 と 3 の監視を作った(0x93500A0・0x933A2E4)。計測 2 の「書き込み 0 件」と「DllMain の後の float の値」は、呼び先の番地の結果ではない(evidence/R5-6f.md §6)。

## 原因(その時の判断)

- rip 相対の番地を手で計算し(0x215606 + 0x13AD9A)、0x3500A0 と書いた。計算の結果を、生成 C の番地と照合しなかった。
