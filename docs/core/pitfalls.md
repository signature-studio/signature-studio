## 2 設計判断(03 §5 の要約。規約と矛盾しない形)

| 場面 | 規則 |
|---|---|
| (a) の除去の実験 | **外した版を 1 つだけ**作り、症状の再現手順と P1〜P3 の該当測定を前後で比べる(コミット同士。旗を作らない)。壊れる物があれば (b) として API を拡充。外して P3 が戻るなら外す |
| 規則文と解釈が衝突 | 除去実験を先に出し、測定を添えて決定文書に分類・撤回条件・測定を書く(`fidelity-and-performance.md` §2 規則 4) |
| 「実際と違う値を返す」物 | (a) として撤回条件を書き、撤回した版を測る。DPI・時刻・Temp は (b) の拡充 |
| (b) の契約差分 | 見つけたターンに単独で取り込む(適用 → テスト → commit)。**逆スイッチ(`#ifdef`・マクロ)を付けない** |
| 依頼者の実機の症状(O1〜O20) | 1 件ずつ直さず、同型を Wine との系統的な差分テストで探す(0322・0323 の方法)。原因の帰属 (a)/(b) を確定してから先へ |
| PROVISIONAL | 期限を付け、一覧を機械生成 |
| `ladder`/`STATE` | 取り込みのたびに worker が更新する。旧 `progress.md` は 11-07 10:38 から更新が止まり、3 日停止した |

## 3 技術上の落とし穴(旧資料の事実)

- `FLENGINE_PE` を設定しない `cargo test` は実 DLL のテストが `SKIPPED` を出して**成功扱い**。設定し、`SKIPPED` の数を報告する。`plugins-ott.test.ts` も入力が無いと `describe.skipIf` でスキップ。**スキップは通過ではない**(実行 N・スキップ M を分ける)。
- e2e が、削除済みの `#standin-banner` を読んで打ち切られ、実エンジンの検査が空洞になった(11-07)。検査は**実エンジンの観測値**(`engineKind`・ログの `vfs seed:` 行)を見る。
- `document.title` や窓表は FL の事実であって、ページが決めない。
- libm は DLL の `sin/cos` と glibc で 1 ULP 違う。上流 Blend2D の置換は橋渡しが要る(0160)。
- 1 つの API の停止を直しても同型の停止が次に出る。**網羅(import の census)で進める**。
- `0322` の「クラス名分岐 0」は窓のクラス名だけ。仮想パス・ホストオブジェクトの定数は別([文書])。
- 注意: 依頼者への質問で止まる型の規則は無い(`AGENTS.md` §3・§7)。判断は main が「決定: X。根拠: Y」で下す。
