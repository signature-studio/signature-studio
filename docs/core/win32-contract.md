冒頭: (1) 下の表は**旧決定 0322 の静的な読み**で、実エンジンでの実行は 0。0322 自身が「読んだのは runtime 57k 行のうち数千行」と書く。**表の個々の行は未検証**。(2) 0323 の差分は Wine 10 との差の行数(130→48)で測った。実エンジン・実機 Windows では未実行。(3) 区分: (a) 余計な処理 / (b) 契約の実装・不足 / (c) 通信・変換の削減 / (d) 診断 / (?) 未決。

## 1 層の構成(`lift/runtime/`)

C 89 + ヘッダ 108 ファイル。ゲストが呼ぶ OS API の仮想実装。ホストの実環境は見せない。未知の API は黙って成功にせず、名前を付けて止める(fail-closed)。主な部品: `fle_win.c`(窓の状態モデル。7,042 行)・`fle_gdi.c`・`fle_raster.c`(描画)・`fle_desk.c`(合成。DWM 相当)・`fle_input.c`・`fle_thread.c`(協調スレッド)・`fle_vfs.c`・`fle_seh.c`。FL のクラス名・窓の種類・位置では分岐しない。

## 2 結論の範囲(0322 §0)

- **「窓のクラス名・題名・位置による分岐は製品経路に 0 件」は、窓のクラス名に限った結論**。アドレス・DLL 名・ファイル名・仮想パスへの依存は別([文書]。例: `fle_vfs.c` の `C:\Program Files\Image-Line\FL Studio 21\…`、ホストオブジェクトの `0xC0`)。読んでいない所の「問題なし」は言えない。
- 「余計な処理」の 3 群: (A) 診断を描画経路で毎回作る(`fle_desk.c` の `names_of`+`build_desc`) (B) 死んだ設定 `FLE_SCREEN_REMAXIMIZE`(読む側が無い。`main.ts:343` が今も送る) (C) 入力の合流が 2 段。差分案は A・B の 2 本。

## 4 場当たりな処理 (a) の候補(0322 表 5。差分なし。ROADMAP R3)

入力の合流 2 段(`S-move-merge`/`S-mousemove-coalesce`)、起動前入力の破棄、仮想時計の遅れ上限 1000 ms・進み上限 100 ms、描画の 100 ms 眠り、`INLINE_TRY_MS` 6 ms、表示 Hz の上限 120(0268)、フォーカス復帰(0260)、CPUID=SSE2 固定。画素の重複排除(`sh_trim`・`fle_r_changed`)は (c) と分類されたが規則文と衝突する。**除去して測り、結果を添えて決める**(`docs/ops/fidelity-and-performance.md` §2 規則 4)。
