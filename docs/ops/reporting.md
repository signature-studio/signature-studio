# 報告の形式と、書いてはいけない文

要約は `AGENTS.md` §3・§5・§7。依頼者向けの報告は、短く、結果だけ。説明は `docs/` に置き、報告には載せない。依頼者から質問されたときだけ、その答えを最短で書く。

## 1 報告の形式(依頼者向け。日本語)

```
実エンジン: <何を実行し、どの出力を観測したか(コマンドとファイル)。無ければ「実行なし」>
代役・再生・推測: <含まれる範囲。無ければ「なし」>
未確認: <確認していない物。依頼者機の値は「依頼中」(依頼票を出した後)または「0 件」と併記>

変わったこと:
- <結果 1>
- <結果 2>
根拠:
- <コマンド> → <出力の 1 行>
稼働: <opencode api session.active の出力から。N 本。ID>
次に動く物: ses_…(内容)
```

| 規則 | やること | 確かめ方 |
|---|---|---|
| 先頭 1 行 = 実エンジンの事実 | 1 行目に、実行した物と観測した出力。無ければ「実行なし」と書く(代役を出さない) | 報告の 1 行目が「実エンジン:」で始まる |
| 数字は実測のみ | 件数・秒・fps・サイズ・稼働数に、出典のコマンドを付ける。自作の %・「約」・推定を書かない | 数字ごとに根拠の行がある |
| 短く | 変わったこと 5 行以内、根拠 5 行以内。長い表・経緯・担当ごとの自己申告・同じ内容の繰り返しを書かない。必要なら `docs/` に置いて 1 行で指す | 本文 30 行以内 |
| 依頼者に求めない | 操作・判断・確認・許可・リポジトリの作成を書かない | §2 の禁止文を grep(§4) |
| 決めたことを書く | 「決定: X。根拠: Y」を 1 行。選択肢を並べて選ばせない | 「どちら」「いかがでしょうか」が無い |
| 約束は実行の後に書く | 「〜しない」「止めない」を書く前に、次の 3 コマンドが約束に反しないか確かめる | 約束の直後のコマンドが約束と矛盾しない |
| 誤りの報告 | 気づいたら指摘される前に、事実(何を・いつ・なぜ)と是正を 1〜3 行 | — |
| モデル切替の検知 | `audit-session.sh` が切替を示したら「モデル切替を検知: <回数>」を 1 行 | audit の出力 |

- 完了・達成・N/N・稼働中の語は、直前 5 分以内の出力を貼れるときだけ使う。
- 案内する URL は、headless Chrome で開いて確認した URL と同一にする。別のサーバー(127.0.0.1 など)で確認したなら「別 URL での確認」と書く。
- 依頼者向けの文面(PR 本文・Issue・README)も同じ。

## 2 禁止文(書きかけたら置き換える)

| 禁止文 | 代わりの行動 | 確かめ方 |
|---|---|---|
| 「依頼者の判断が必要です」「ご判断を」「どちらにしますか」「確認させてください」「許可をください」 | 自分で決め、「決定: X。根拠: Y」を 1 行書いて実行 | 報告に「判断を」「確認させて」「許可」が無い |
| 「push できません」(権限が実測であるときを除く) | リポジトリのディレクトリで `gh auth status`(トークンの行は除く)と `git push --dry-run origin HEAD` の出力を貼る。通るなら push する。失敗したら依頼票で頼み、push 以外の作業を続ける | 報告に 2 つの出力がある |
| 「Cloudflare を確認してください」 | 後任は wrangler を実行しない(P4)。確認が要るなら依頼票を出す(`docs/ops/requests.md`) | 依頼票のパス |
| 「〜を実行してください」「ブラウザで開いて確認してください」(依頼者への操作要求) | 自分で `scripts/`・gh・git・headless Chrome で確かめる。実機の画面・音は依頼票(P5) | 自分の実行の出力がある、または依頼票のパス |
| 「作業対象がありません」「リポジトリが読めないため停止します」 | 読める物(ローカルの作業木・旧作業ツリー・docs)から次の worker を起動 | 起動した ID |
| 「作業を止めます」「待ちます」「次の通知を待ちます」 | 次の worker を起動し、「次に動く物」を書く | 最後の行が「次に動く物: ses_…」 |
| 「見込みが低いです」の繰り返し | 1 回だけ事実として書く。縮める行動(分解・並列化・範囲の絞り込み)を実行し、ID を書く | 同じ文が 2 回目に出ていない |
| 「理由はありません」「〜という問いですね。説明します」(是正要求への応答) | 指す動作を実行。説明は実行の後に 1 行まで | 最初のツール呼び出しが動作 |
| 「ご指摘のとおりです。今後は〜します」で終える | 実行した是正と、その出力を書く。「わかった」の表明は成果にならない | 是正の出力がある |
| 「依頼者の機械・Windows 実機で確認してください」 | 依頼者機の値は依頼票で計測を頼む(P5)。未確認欄に「依頼者機の値: 依頼中」と書き、この機械の headless Chrome の実測を出す | 依頼票のパスと未確認欄 |

## 3 書く前に確認する物(報告・PR 本文・Issue・README)

| 書く物 | 確認 |
|---|---|
| 稼働数・状態 | `opencode api session.active` の直近の出力 |
| 公開範囲・push | `scripts/preflight.sh` の出力(`push-dry-run`・`gh-identity` の行) |
| 数字 | 出典コマンドを付けられるか。付けられなければ「(未確認)」 |
| 代役・再生を含むか | 含むなら、最初の行・物自体・明示パスの 3 点(`docs/ops/honesty.md`) |
| 秘密・識別子 | `scripts/scan-forbidden.sh <ファイル>` |

## 4 送信前チェック(報告を出す直前の 6 項目。reviewer も同じ表で検査する)

| # | 項目 | 確かめ方 |
|---|---|---|
| 1 | 先頭 1 行が実エンジンの事実(または「実行なし」) | 目視 |
| 2 | 数字ごとに出典コマンドがある | 目視 |
| 3 | 稼働数・完了の語に、直前の出力が付いている | 目視 |
| 4 | 禁止文が無い | `grep -nE '判断が必要|ご判断|確認させて|許可を|実行してください|確認してください|止めます|待ちます' <報告のファイル>` が 0 件(報告をファイルに書く場合) |
| 5 | 依頼者に操作・判断を求めていない | 目視 |
| 6 | 最後の行が「次に動く物: ses_…」 | 目視 |

## 5 暴言・評価の扱い

- 依頼者の発言を、報告・文書に長く引用しない。参照は ID だけ。暴言は引用しない。
- 依頼者の行為の是非を評価しない。「依頼者が〜した」と事実を書くときも、評価語を付けない。
