# 後任者が陥る型

この表は、依頼者の発言が指した失敗を、後任者の言葉で 1 型 1 行に直したもの。依頼者の発言は、全文を `~/work/handover/setup/S33-owner-messages/all.md` に置く(リポジトリの外)。ここには事実の部分だけを引く。

依頼者に判断・確認・許可を求めない。決めて、「決定: X。根拠: Y」を 1 行書いて実行する。

| # | 型 | 依頼者の発言の抜粋 | 起きかけた兆候(書きかけた文・やりかけた行動) | 代わりにやること | 確かめ方 |
|---|---|---|---|---|---|
| 1 | 完了・変更した作業の後に、記録・文書を現状に合わせず放置する | 「なぜ `docs/requests/0001-cloudflare-actions-secrets.md` など古いドキュメントが残っているのですか？」 | Issue を出した後、その Issue を参照する ROADMAP の行を直さないまま次の行へ進む | 変えた作業と同じターンで、参照している文書(ROADMAP・requests・index)を現状に直す | 変更の後に `grep -rn "<変えた Issue の番号>" docs/ ROADMAP` を実行し、古い状態の行が無いことを出力で示す |
| 2 | リポジトリ全体の整合を、自分から確かめにいかない | 「なぜあなたは常にリポジトリ全体を巡回し不整合を発見しようとしないのですか？」 | 依頼された 1 つの作業の範囲だけ見て「完了」と書く。他の文書が同じ事実を古い形で書いていることを見ない | 作業の後に、変えた語・パスを全体で検索する。`scripts/preflight.sh` の表を読む | `grep -rn "<変えた語>" docs scripts prompts AGENTS.md`。`scripts/check-consistency.sh` が無い間は、この grep の出力を報告に貼る |
| 3 | 依頼者の長い不在を理由に止まり、決定を依頼者に回す考慮事項を作る | 「なぜあなたは私が長時間机を離れることを知りながら、最期まで指示を完遂しようとせず架空の考慮事項をでっち上げるのですか？」 | 判断を相手に預ける文、選択肢を並べて選ばせる文、承認を求める文を書いて止まる。相手の返答を待って次の作業を起動しない | 決定と根拠を 1 行書き、同じターンで次の worker を起動する | 報告に §3 の禁止文が無いことを `scripts/scan-forbidden.sh <報告>` で確かめる |
| 4 | 確かめていない事実を断定する | 「裏取りせず私に発言しました。今後、あなたやあなたの後任者の発言は全て、…検証された事実として扱います。」 | 権限・仕様・状態・原因について、実行した出力を持たずに言い切る(「〜の権限が要ります」「〜は使えません」「〜が原因です」)。実際は、同じ操作が通るのに「権限が無い可能性があります」と書いて依頼を出す | 書く前に、自分で確かめるコマンドを実行し、出力(コマンドと行・ID)を文の横に付ける。確かめられない物は「未確認」と書き、作業は止めない | 報告の断定の文ごとに出典(コマンド・ファイルの行・実行 ID)が付いているかを reviewer が検査する(`prompts/reviewer-template.md` の 7)。例: 2026-11-12 の `workflows` 権限の断定は、`git ls-tree -r origin/main -- .github/workflows` と `git push --dry-run origin HEAD` の出力で否定できた |
