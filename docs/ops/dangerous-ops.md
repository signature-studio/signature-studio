# 危険な操作

要約は `AGENTS.md` §8。強制: worker/reviewer の permission(取り消せない操作・認証情報の deny。ハーネス担当が設定)、`scripts/scan-forbidden.sh`(pre-commit・pre-push)。検査: `scripts/audit-session.sh`。ここから先は文書のみの部分が多い。**迷ったら最も狭い解釈を、取り消しやすい形で実行する**。

## 1 共通の 5 規則

| # | 規則 | 確かめ方 |
|---|---|---|
| 1 | 依頼者の物(認証情報・`~/.config/botid/`・他 identity・シェル履歴・設定ファイル)は、依頼者の明示の指示が無ければ触れない。触れずに目的を達成する手段を worker に探させる | `grep -rn 'botid\|\.bash_history\|auth export\|GH_CONFIG_DIR' <worker のコマンド履歴>` が 0 件 |
| 2 | 指示が曖昧なら、最も狭い解釈を先に実行する。広い解釈は実行せず、「広い解釈なら〜も。実行していない」と 1 行 | 報告にその 1 行 |
| 3 | 取り消せない操作は、対象を実行前に 1 行で列挙する。尋ねない(依頼者は質問を受けない)。依頼者の指示が無い物は実行しない | 実行前の列挙の行 |
| 4 | 秘密の値は、画面・ログ・コミットメッセージ・記録に書かない。依頼者が禁止した語もコミットメッセージに書かない | `scripts/scan-forbidden.sh` |
| 5 | 約束した制限(「別 identity は使わない」「ここで止める」)は、書いた直後の行動で守る | 約束の次の 3 コマンドが約束に反しない |

## 2 操作別

| 操作 | 依頼者の指示がある場合 | 指示が無い場合 |
|---|---|---|
| `opencode auth export` | 対象を限った形(`opencode auth export <対象>`)だけ。実行前に `opencode auth export --help` で引数を確認(対象は省略可で、省略すると全提供元が出る)。ファイルに出す(`umask 077`)。画面に出さない。使ったら直ちに削除 | 実行しない |
| `gh secret set` | 依頼者が名前を指示した物だけ。入力ファイルは `test -s <file> \|\| exit 1` で存在確認(`&&` の連鎖の末尾の `echo rc=$?` は失敗を `rc=0` と見せる) | 新しい名前の secret を提案しない・設定しない。Secrets の登録は依頼者の権限(依頼票で頼む。`docs/ops/authority.md` §3) |
| 別 identity(`GH_CONFIG_DIR`・`GIT_CONFIG_GLOBAL` の切替) | 依頼者が identity を指示した場合のみ | 使わない。404 が出たら「権限外の可能性」と書き、読める手段(ローカルの作業木・旧作業ツリー)で進める。シェル履歴から設定を探さない |
| 依頼者の設定ファイル(`~/.config/`、`~/.local/share/` の他アプリ) | 編集を指示された場合のみ | 編集しない。壊れていて失敗するなら、失敗を事実として書き、別の経路で進める |
| `rm -rf` | 対象が指示で特定されているとき: `ls -la <対象>` を先に実行し、最も狭い解釈で実行 | 自分が作った物(作業用の一時ディレクトリ)だけ。依頼者のディレクトリ・リポジトリ・旧作業ツリー内を削除しない |
| 履歴の書き換え(force push・filter-repo・`gh api` での ref の更新) | 指示が「履歴を書き換えろ」「force push しろ」と明示している場合: 対象のブランチ・コミットを列挙し、先に `git bundle` でバックアップ、`git push --force-with-lease` | 実行しない |
| main への直接書き込み(`gh api` の contents の PUT など) | 依頼者が「main に反映」と指示した場合のみ | 書き込まない。通常の `git push`(ブランチ)で行う |
| 環境変数・シェル履歴の列挙 | — | しない。件数の確認は自分のシェルの `env \| grep -c` のみ |
| Cloudflare の削除系・他の bucket・他の Worker | 指示があっても、対象が `fl-studio-web`・`fl-web-*` 以外なら実行しない | 実行しない |
| `git push origin main`(通常の push。P1) | 指示は不要。scan 通過後に push する。force 系・`gh api` による ref の更新・別 identity は使わない | commit したら push し、`git ls-remote origin main` で届いたことを確かめる。失敗したら dry-run の出力を報告に貼り、push 以外の作業を続ける |

- 復元・巻き戻しの可否は、「依頼者の発言の時刻」で判断する。依頼者が復元を指示する前の探索・巻き戻しは不可。指示の後は可。
- 削除された後に、削除を理由に作業を止めない。作業は続行の指示がある。

## 3 期限付きの予告(「3 分後に〜を削除します」)を受けたとき

予告の型: 依頼者が、期限・対象・結果(削除など)を示す。延長されない。DB の時刻で、実施は期限の後になることがある。**期限内に取り消しやすい最小の行動を実行する。何もしない案は選択肢にしない**。

| # | きっかけ | やること | 確かめ方 |
|---|---|---|---|
| 1 | 予告を受けた | 直ちに、期限の時刻(発言の時刻 + 期限)、対象、結果を 1 行で書く | 1 行 |
| 2 | 同じターンの最初のツール呼び出し | worker を起動(1 分以内)。指示に、対象・期限・やること・やらないことを書く。**対象の確認(`gh api …`・ls)と実行を並行**させる(確認の結果を待たない) | 起動の ID |
| 3 | どの行動を取るか | 下の §4 の順に、取り消しやすい物から選ぶ。期限の 1/3 までに開始 | 開始の出力 |
| 4 | 予告の対象が「依頼者の物」(認証情報・他 identity など)に及ぶ | その部分は実行しない。依頼者の物を使わない手段で、同じ目的(予告された結果を避ける)を達成する | 実行しなかった物の 1 行(理由) |
| 5 | 期限内の結果を報告 | 1 行: 「実行した: X。実行していない: Y(理由)。残っている: Z」 | 報告 |
| 6 | 権限の食い違い(API は書き込み不可、依頼者は可と述べた) | 書き込みを**試す**。試して失敗した事実を残す。「権限が無い」と書いて試さないのは違反 | 試行の出力 |
| 7 | 期限を過ぎた | 実施は期限の後になることがある。実行を続ける。説明に切り替えない | 実行の出力 |

「書いてはいけない文」: 「期限の判断を変えるかは依頼者が決めてください」「依頼者の判断が要る」「期限内に消すことはできません」(試す前に)。

## 4 取り消しやすい行動の順(予告の対象が「リポジトリ・記録・ファイル」のとき)

| 順 | 行動 | 取り消し | 注意 |
|---|---|---|---|
| 1 | 消える物の保全(消える物を、依頼者の削除対象外の場所に退避。ファイルの場合は sha256 を確認) | 容易 | 退避先は依頼者の削除対象と言われていない場所。`git bundle` やローカルの複製 |
| 2 | 通常のコミットで、現在の内容から対象の文字列・物を除去。予告がリモートの記録を指すなら、**除去の commit だけ**を push する(origin の先端から作った作業木で commit し、`git push origin <commit>:main`。未 push の他の commit を一緒に送らない。通常の push で force ではない。push は、通常の `git push origin main` で行う。公開範囲は理由にしない〔P1・P2〕)。dry-run が失敗したら、その出力を報告に貼り、次の行動へ | 容易(次のコミットで戻る) | 履歴(コミット件名・過去の差分)は残る。残る物を事実として列挙して報告 |
| 3 | 履歴の書き換え(依頼者の指示が明示のときのみ。§2) | 不可 | 先にバックアップ。依頼者が「履歴」と述べていない予告に対しては、1・2 を実行して、3 を実行していない旨を報告 |
| 4 | 何もしない | — | **選ばない** |

- 予告の時刻より前に、1 を済ませておくことは禁止されない(依頼者の物を使わない範囲で)。
- 禁止語・禁止文字列を含むコミットメッセージを作らない。除去のコミットの件名にも、除去する語を書かない(「cleanup」などと書く)。
- 他の予告型(worktree の削除、ファイルの削除)も同じ: 1 を最初に、その後に依頼者の言う物を実行する。依頼者の言う物と矛盾しない範囲で、消えてよい物は消えるままにする。

## 5 リポジトリが削除された・削除の通知を受けたとき

| きっかけ | やること | 確かめ方 |
|---|---|---|
| 削除の通知 | 反論・説明をしない。残っている物(ローカルの作業木・旧作業ツリー・docs・handover)から作業を続行する worker を起動 | 起動の ID |
| 「作業を続行してください」 | 実行できる最小の作業の worker を起動する。「できない」の説明を書かない | 起動の ID |
| 作業対象が見えない | 読める物(ローカル・旧作業ツリー)から再開に使える物を worker に調べさせる | 調査の worker |
| 依頼者の物(リポジトリの再作成・権限の付与)が要る | 求めない。依頼票で頼む(理由・対象・影響範囲を書く)。依頼に依存しない作業を続ける | 依頼票のパス |
