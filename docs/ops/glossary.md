# 用語集(言葉の決まり)

この文書の語を使う。依頼者が使う語を優先する。**この表にない言葉を作らない。** 迷ったら、依頼者の使う語か、標準の英語(Issue、push、コミット、ワークツリーなど)を使う。
`scripts/forbidden-terms.tsv` に入っている語は、`scripts/scan-forbidden.sh` が止める(コミットと push の前)。

## 使う語

依頼者の発言か、業界の標準の表記を根拠にした語だけを載せる。

| 概念 | 使う語 | 例 | 根拠 |
|---|---|---|---|
| この仕事の持ち主 | 依頼者 | 依頼者の指示に従う | 依頼者の回答(中継) |
| Web アプリを使う人 | ユーザー | ユーザーが画面で操作する | 依頼者の回答(中継) |
| エージェントから依頼者への頼み | 依頼 | 依頼の Issue を出す | 依頼者の回答(中継) |
| 依頼者からエージェントへの指示 | 指示・要求 | 依頼者の指示を実行する | 依頼者本人が「要求」を 10 件使う |
| GitHub の Issue | Issue | Issue を作る | 依頼者本人が英語の Issue を 5 件使う |
| 作業場所(Git のワークツリー) | ワークツリー | `gwq add` でワークツリーを作る | 依頼者の回答(中継)。本人は英語の worktree を使う |
| 自動の確認(実行して結果を見る) | テスト | `bash tests/harness/run.sh` のテスト | 依頼者本人が「テスト」を 5 件使う |
| 作業を任せる別の実行者 | サブエージェント | 作業用・検証用を区別するときは下の 2 行 | 依頼者本人が英語の subagent を 19 件、サブエージェントを 1 件使う |
| 同じ物を別の場所に作ること | コピー | 旧資料からコピーする | 依頼者本人が「コピー」を 2 件使う |
| Git の操作 | コミット・push・branch | `git push origin main` | 依頼者本人が使う |

## 区別が要るときだけ使う語

- 作業を作る実行者: 作業用サブエージェント
- 作業を確かめる実行者: 検証用サブエージェント

依頼者の使用はない。サブエージェントと区別する必要があるときだけ使う。

## まだ決まっていない言葉

依頼者が使った例がない。使うときは、意味が通じる普通の日本語で書く。

- 旧資料がある場所の呼び名(「旧ワークツリー」と書く)。
- 禁止事項、許可一覧、規則の文章、記録・一覧、依頼者の環境、差分の確認。

## 注意

- 「要求」は、依頼者からエージェントへの指示の意味で使ってよい。エージェントから依頼者への頼みには「依頼」を使う。
- 「テスト」は、動作の確認の意味だけに使う。熟語で言い換えられる場合は、意味に合う語を使う(「実験的な」「暫定の」など)。
- 「worker」「reviewer」は、エージェント向けの規約(AGENTS.md)の役割名。依頼者向けの報告・文書には、サブエージェント(作業用・検証用)と書く。
- 技術用語の用法(「rAF を要求する」「要求面積」など)は、この表の対象外。
- 旧資料(`docs/archive/`)は、用語だけ現在の語に置き換えてある。それ以外は原文のまま。
