# ROADMAP(次の一手の表)

## 使い方(main が機械的に使う)
1. **次の一手 = 下の表を上から見て、状態が `todo` で、依存がすべて `done` の最初の行。** 無ければ、`doing` の行の worker を確認し、`blocked` の理由を 1 行調べる。
2. worker への依頼 = その行の「入力・やること・完了条件」を、そのまま `prompts/task-template.md` に写す(1 行 = 1 依頼。要約・追加をしない)。先頭に `prompts/worker-rules.md`。
3. **状態の更新は worker に頼む。`done` にする条件: `evidence/<ID>.md`(実行したコマンドと出力の記録)が存在し、完了条件の各コマンドの出力が貼られていること**。自己申告・「完了」の語だけでは `done` にしない。reviewer を起動して検査してから。
4. 区分: `a`=除去 / `b`=API 拡充 / `c`=通信・変換の削減 / `測定` / `整備`。見積り(時間)は [未確認] の目安で、約束ではない。**新しい `#ifdef`・`getenv`・URL パラメータ・ビルド変数を足さない**(`AGENTS.md` §6)。
5. 旧資料の場所は `docs/ops/lessons.md`。差分(`patches/`)・旧文書(`docs/archive/`)・検証キット(`tools/verify-kit/`)・`lift/`・`app/`・`ci/`・`tools/` は旧資料の持ち込み後に存在する(**存在しなければ、R0-0 の worker がその旨を `evidence/R0-0.md` に書き、読める旧資料から進める**)。人間に頼む物は Issue(`docs/requests/`。雛形 `docs/requests/TEMPLATE.md`、規則 `docs/ops/requests.md`)で出す。
