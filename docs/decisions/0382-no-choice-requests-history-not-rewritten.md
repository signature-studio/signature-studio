## 決定
- 決定 1: 公開リポジトリの履歴は書き換えない。force push・filter-repo・rebase による書き換えは行わず、依頼者にも頼まない。根拠: `AGENTS.md` §4 は force 系の push を禁じる。書き換えは対象より後の全 commit の SHA を変え、他の clone・fork・Actions の参照を古い履歴に向けてしまう。書き換えても現在のツリーの値は消えず、別の commit で除去する必要がある。
- 決定 2: 現在のツリーの追跡ファイルから、実在のホスト名の値を除き、プレースホルダ(`example.com` の形)に直す。直すのは値だけで、他の文は変えない。根拠: 履歴に残る値を消せない以上、以後の記述に値を置かないことが残る手段。`AGENTS.md` §8 は、コミット・ファイル・ログに Cloudflare のホスト名を書かないことを求める。
- 決定 3: 検査を足す(`scripts/scan-forbidden.sh`)。(i) `choice`: `docs/requests/*.md`(`TEMPLATE.md` を除く)に、依頼者に選ばせる・判断させる・埋めさせる言い回し、内部用語(`gh secret`・`gh variable`・`rc=`。禁止の説明の行は除く)があれば検出する。(ii) `hostval`: 追跡ファイルの `"pattern"` の値が、プレースホルダの語を含まないドット区切りのホスト名なら検出する。(iii) `byok`: 決定 6。テストは `tests/harness/t04_scan.sh`。
- 決定 4: 依頼者に選択・判断を求める Issue は出さない。Issue に出すのは、依頼者にしかできない 1 つの操作(トークンの発行・Secrets の登録・権限の付与・実機での計測)だけにする。方式や扱いの選択肢は、自分で決めて「決定: X。根拠: Y」と書き、実行する。根拠: 依頼者は最大 7 日席を外し、選択に答えられない。Issue 0003 は (a)(b) の選択肢を並べ、依頼者が閉じた。
- 決定 5: Issue 0003(GitHub の #2)は閉じたままにする。同じ依頼を新しい Issue として出さない。`docs/requests/0003-history-routes-value.md` は取り下げの記録にする。
- 決定 6: モデルの認証は、依頼者が opencode の console に登録した BYOK だけを使う。AWS の認証情報(IAM・アクセスキー・Bedrock の API キー)・ローカルマシンの認証ファイル・プロファイル ID・リージョンを、スクリプトでも Actions でも要求しない。依頼者に作らせない。根拠: 依頼者からの事実(モデルの認証は console の BYOK だけ。AWS の IAM・アクセスキー・Bedrock の API キー・ローカルの認証ファイルは、モデルの呼び出しに使わない)と、依頼者の指摘。検査(`byok`): `docs/requests/*.md`(TEMPLATE を除く)で、IAM・アクセスキー・AWS_ で始まる名前・Bedrock の API キー・推論プロファイルを検出する。対象外は、Cloudflare または R2 を含む行と、先頭 5 行に取り下げの状態(`状態: 取り下げ` の行)がある記録。Issue 4(Bedrock の認証情報の登録)は、別の worker が取り下げる。
- 決定 7: `opencode auth export` と `opencode auth import` は実行しない(前者は認証情報の中身が出力され、後者は認証情報の保存先に書き込む)。方法を決める前に、自分の道具のヘルプと `~/work/handover/setup/S16-intent/catalog.md` を先に読む(`docs/ops/intent.md`)。根拠: 依頼者の指摘。
- 決定 8: 依頼者に頼む前に、自分の道具の help・ソース・docs と、過去の方法の指定の記録を先に読み、その出力を Issue の「自分で試した記録」に貼る。検査(`trial`): 依頼本体(TEMPLATE、取り下げ・完了の記録を除く)で、この節が無い・空・help の行もパスも URL も無い場合に検出する。根拠: 依頼者が、試していない確認を依頼者の作業として回されることを是正の対象にした。
