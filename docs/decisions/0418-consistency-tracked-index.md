# 0418: 整合性の検査は追跡ファイル(index)だけを読む
分類: 検査の道具の直し(製品の処理ではない。AGENTS §6 の a・b・c の対象外)
撤回条件: 追跡ファイルだけを読む検査が、ワークツリーで見れば実在する参照を commit 後も誤って指摘し続けると確かめられたとき。または、文の単位の規則の後で、実在しない参照が 0 件で通るとテスト(t10)か実測で確かめられたとき。その規則を戻す
日付: 2026-11-17   ROADMAP: R6-40   一覧: docs/ROADMAP.md の表   コミット: 33cbcc12(検査と直し)、d12bb2e4(ROADMAP・決定・記録)、後続(規則の追加と直し)
## 決定
決定: scripts/check-consistency.sh は git の index(追跡ファイルと staged の中身)だけを読む。根拠: ワークツリーにだけ在る実体(未追跡・.gitignore の生成物)へのパスを、存在する物として通していた(R6-39 の報告。evidence/R6-40.md §1 で再現)。index は次の commit が持つ中身で、clean な木では HEAD と同じ。フラグ・環境変数・引数は足さない。未 add の編集は読まない(文書を直したら git add してから実行する)。
決定: 語は文(。と表の |)の単位で見る。コード片の中とパス名の中の語は数えない。語は語の境界で見る(ダウンロードの ロード は数えない)。場所の語(旧ツリー・docs/archive など)は、コード片の中でも同じ文の語として数える。根拠: 行全体で見ると、同じ行の別の文の語が参照を隠す(0408 の 21 行。`置く` は VFS の契約の文の語で、host path の文の語ではない)。
決定: .gitignore が名前を挙げるトップレベル(artifacts/・binaries/)は、リポジトリの木の名前として検査する。根拠: 追跡されない名前で始まる参照を、規則が素通りさせていた。
決定: コマンドの中の語は、すべて検査する(先頭の語だけでなく)。根拠: 先頭語だけの規則では、コマンドの引数の履歴から消えた参照が通った(0351 の 17 行の `bash …/build-engine-bundle.sh`)。
決定: commit 付きの参照(`<commit>:<path>`・`<commit>^:<path>`)は、どの語の位置でも `git cat-file --batch-check` で存在を確かめる。根拠: 履歴の版を指す参照が、先頭語でないと検査されず、存在しない版を指していても通った。履歴の無い木では「その commit に無い」と出る(検査は履歴を読む)。
決定: 規則で見えた参照は、git の履歴から消えた物なら、その物が最後に在った commit を指す `<commit>^:<path>` に直す(追跡された出典)。生成物・旧ツリーの物は事実の語(ビルドの出力・出力先・旧ツリーの出力・抽出の出力・作成から除去までの履歴・npm 導入で作成)で書く。語ごとの根拠は evidence/R6-40.md §5 に 1 行ずつ書く。文の意味は変えない。除外語は足さない。

## 読み(解釈。実行していない)
- ワークツリーを読む検査は、生成物や未追跡の実体があると、その実体へのパスを存在するものとして通す。R6-39 の 9 件は、commit された中身で読むと見つかった。index を読めば、commit される中身と同じ判定になる。
- 文の単位にすると、語の見落としは減るが、文書の書き方(語を同じ文に置く)に依存する。直した参照は、出典を確かめた事実を文に書いた。
- 履歴から消えた物の参照に commit 付きのパスを使うのは、履歴を書き換えずに出典を示す方法。`git cat-file` で存在を確かめられる。
## 残る穴(規則の限界。件数は evidence/R6-40.md §6 の再現コマンドで出る)
- 同じ文に事実の語(出力・ビルド・作る・置く・作成 など)があると、その文の参照は存在しなくても通る(規則の意図。語が事実かは文の書き手の責任)。
- 省略の記法(`…`・`<名>`・`*`・`$` など)を含む語は見ない(BAD)。
- 先頭の語がリポジトリの追跡されたトップの名前でない語は見ない(TOPNOT)。外部の名前・URL・`lift/` の下の省略形(`two/`・`parity/run.sh`)・HOST_ROOT の下の相対パス(`out-plugins/...`)が入る。
- 追跡されていないトップ(中身が無視された物だけの `app/` など)の下の参照は、先頭語が木の名前でないため見ない。
- 未 add の編集は読まない。履歴の無い clone では commit 付きの参照が「その commit に無い」と出る。
- 系譜の外の commit(origin/main から到達できない commit。ローカルの object にのみ在る)は、clone に無いため検査できない。その commit を本文に書くときは、commit 付きの参照(バッククォートの `<commit>:<path>`)にせず、「commit … (origin/main の系譜の外)」と書く(R6-41)。系譜にある同じ内容の commit があれば、その commit に直す。
## 未確認
- ワークツリーにだけ在る物を、文書が「存在する」と書いた箇所の意図は、文書の作者に確かめていない。語を足したのは、evidence/R6-40.md §5 の出典で確かめた事実だけ。
- `HOST_ROOT` の下の相対パス(`out-plugins/...`)は、リポジトリの木の名前ではないため規則の対象外。直していない。
