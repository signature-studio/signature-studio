# 0384: 作業用エージェントのモデルは Variable OPENCODE_MODEL で指定し、設定は最初の opencode の前に書く
分類: (b) API 拡充(opencode の設定の読み方の契約: サーバーは起動時に読んだ設定を保つ。設定は、ワークフローの最初の opencode の前に書く)。固定値の削除は (a) 除去として、下の決定の 2 行目に分けて書く
撤回条件: (1) Variable の登録の後の run で、check-agents が Variable の値との不一致を報告したら、その run の順序とサーバーの状態を実測し直す。(2) 設定を最初の opencode の前に書いても不一致が出たら、この順序の決定を取り消し、設定の再読込みの手順に切り替える
日付: 2026-11-16   ROADMAP: R9-1   一覧: —   コミット: ac4db9b(モデルの指定と順序)、後続の commit(Issue 0006 と文書)

## 決定
- 決定: 作業用エージェントのモデルは、GitHub の Variable `OPENCODE_MODEL`(形は `<提供元>/<モデル>`)で指定する。`runner-config.sh` は、ワークフローの最初の opencode の前に設定を書く。根拠: 依頼者の指摘(下の出典)。提供元の切り替えを、コミットなしで行えるようにする。
- 決定: コミットに書いていた既定の提供元・モデル ID を削除する。Variable が空なら、設定を書かず、`check-agents.sh` が取り込みの後で「Issue 0006 を参照」と出して止まる。根拠: 隠れた既定値を持たない。取り込みと提供元の件数の出力を、止まる前に出す。
- 決定: 検査は提供元を固定せず、Variable の末尾が `claude-haiku-5-5`・`#` 無しで、5 つの agent が同じ値を使うことを確かめる。根拠: worker・reviewer は Haiku 5.5 の役割(AGENTS.md §1)。

## 実測(コマンド・条件・日付・n)
- run 43791988553(commit ddd8c6c。設定を取り込みの後に書いた旧順序)と、run 43792496714(commit 24a8424。同じ順序)の検査が、5 agent すべて不一致で rc 1。`gh run view <番号> --log-failed` の出力は agent 名だけ(n=2)。両方とも取り込みは成功し、提供元の件数は表示された(n=2)。
- 同じ順序を、この機械で隔離した XDG(一時ディレクトリ。opencode 2.2.6)で再現: `opencode models` → 設定を書く → 直後に `opencode debug agents`。検査は 5 件不一致(n=2)。直後の `debug agents` の提供元は、リポジトリの追跡されている設定の提供元を返した(n=1)。数秒後の `debug agents` は、書いた設定の提供元を返した(n=1)。
- 逆の順序: 設定を書く → `opencode models` → `debug agents`。検査は 5 件一致、rc 0(n=1)。新しい `runner-config.sh`・`check-agents.sh` で、ワークフローと同じ順序(設定 → 取り込み相当 → 検査)を実行すると rc 0(n=1)。Variable が空なら、設定は書かれず、`check-agents.sh` が rc 1 で止まり、不一致の文言は出ない(n=1)。
- run 43793599375(commit ac4db9b)は、タスクの無い push のため、計画のジョブだけ success、タスクのジョブは skipped(`gh run view <番号> --json jobs`。n=1)。
- 管理サービス(`opencode serve --service`)は、XDG を別にしても、既定のポート(127.0.0.1:49374)を共有する。一時の XDG から起動したサービスが残ると、別の XDG の起動は「ポートが使用中」で失敗した(n=1)。実験の後は、起動した PID を、その XDG の環境で確かめてから止めた。

## 読み(解釈。実行していない)
- 管理サービスは、最初の opencode の呼び出しで起動し、起動時に読んだ設定を保つ。後から書いた設定は、しばらくの間、そのサーバーに反映されない(上の逆順の実測から。反映までの正確な時間は未確認)。
- 設定を最初の opencode の前に書けば、サーバーは書かれた設定を読む。worker の実行(`opencode run`、ci/agents/run-task.sh(削除済み))も同じサーバーを使うため、同じ設定になる(読み。`run-task.sh` は既定の接続で呼ぶ)。
- Variable が空のときは、取り込みと提供元の件数の出力が先に出て、検査の段階で止まる。タスクのジョブには届かない(run ジョブは検査の後に続くため)。
