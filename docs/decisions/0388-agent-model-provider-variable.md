# 0388: 作業用エージェントのモデルは Variable OPENCODE_PROVIDER(提供元)で指定し、モデル ID は提供元の一覧から選ぶ(0384 を置き換える)
分類: (b) 契約の実装(GitHub は Variables の値を伏せない。env に渡すと、値が PUBLIC のログに 1 行出る)。(a) 除去は、同じ決定の 2 行目に分けて書く(Variable にモデル ID を持たせない)
撤回条件: (1) GitHub が Variables の値を env の表示でも伏せるようになったとき。(2) 依頼者が提供元の指定を退けたとき。(3) 提供元の一覧に、作業用の型の掲載が 1 件でない状態が続き、run が「候補が N 件」で止まるとき(提供元の指定を直す)
日付: 2026-11-16   ROADMAP: R9-3   一覧: —   コミット: 本決定の commit(後続の commit で記録)

## 決定
- 決定: 作業用エージェントのモデルは、GitHub の Variable `OPENCODE_PROVIDER`(提供元の名前 1 語)で指定する。`runner-config.sh` は、その提供元の掲載(`opencode models --standalone`)から、ID が作業用の型(`haiku-5-5` で終わる)の 1 件を選び、5 つの agent の設定に書く。根拠: 依頼者の指示(出典の発言 ID)。依頼者が選んだ「Variable で指定する」を保つ。モデル ID の文字列(ベンダー名を含む)は、Variable にもリポジトリにも入れない。
- 決定(a 除去): 旧 Variable `OPENCODE_MODEL` は、ワークフローとスクリプトから参照しない。依頼者は削除しなくてよい(参照されなければ、値はログに出ない)。根拠: 旧の値は `<提供元>/<モデル>` の形で、run 43804191981 のログに env の表示として 1 行出た(evidence/R9-3.md)。参照の件数は evidence/R9-3.md。
- 決定: 候補が 0 件・2 件以上、または Variable が空・1 語でないときは、`runner-config.sh` が exit 1 で止まる。出すのは件数と「Issue 0007 を参照」だけ。提供元の名前もモデル ID も出さない。
- 決定(整備。分類: (a) 除去): ログの「提供元の件数」の行(提供元の名前を出していた行)と、「作業用の型の掲載件数」の行を削除し、件数だけを `runner-config.sh` に出す。
- 決定: 順序は、取り込み → 設定 → 検査。取り込み(`opencode auth import --standalone`)と掲載の一覧(`opencode models --standalone`)は、私有のサーバー(`--standalone`)で行い、背景のサービスを起動しない。背景のサービスは、設定を書いた後の最初の呼び出し(`opencode debug agents`)で起動する。根拠: 決定 0384 の実測(背景のサービスは起動時に読んだ設定を保つ。設定を書く前の呼び出しで起動すると、後の設定が効かない)。

## 順序の確認(main の見込みとの違い)
- 旧の順序は、設定(agent.yml の「実行用のモデルの設定を書く」)→ 取り込み → 検査 だった。「取り込み → 設定」ではない。出典: `.github/workflows/agent.yml` の旧版の段の順(決定 0384 の実装)。
- 取り込みの後に設定を書く形にすると、取り込みの段が背景のサービスを起動する可能性がある(取り込みの段の挙動は、この機械で実行して確かめられない。依頼者の全体の規則で auth の取り込みは実行しない)。そのため、取り込みに `--standalone` を付けた。
- 掲載の一覧を、取り込みの後・設定の前に得るには、私有のサーバーで行う必要がある。この機械で、私有の一覧と背景の一覧の出力は一致した(行数 380、cmp の結果が一致。n=1)。
