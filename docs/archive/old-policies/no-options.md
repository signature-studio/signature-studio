# 方針: オプトイン/オプトアウトの処理を持たない(2026-11-05、依頼者の指示)

依頼者の指示(原文): 「今後、一切のオプトイン/オプトアウト処理を禁止します。デフォルトで全てのオプションを有効とし、既存ソースも修正してください。」

## 1. 定義

**オプション** = 製品またはビルドの振る舞いを、複数の選択肢から切り替えるスイッチ。次のどれも含む。
- ページの URL パラメータ(`?present=…`、`?packsource=…`、`?audio`、`?scale=…` など)、localStorage の設定、manifest の選択フィールド
- 製品の runtime/ハーネスが読む環境変数(`getenv`)
- C の `#ifdef FLE_…` / `-D…` で「無効側」の経路を持つもの
- ビルドスクリプトの変数・プリセット名(`SHIP_PRESET`、`NO_FS`、`EXTRA_IMPORTS`、`RT_OPT`、`HYBRID_SETS` …)
- `fe-lift` / `fe-wasmgen` の「旗」で、無効側の出力を持つもの(`--sse-int`、`--mx-packed`、`--static-calls` …)
- CI の `workflow_dispatch` の入力

**オプションではない**もの:
- パラメータ(入力・出力のパス、並列数、サイズの上限などの数値)
- データ(関数のリスト、import 行、フォントなど。『どれを含めるか』のデータであり、スイッチではない)
- 環境の能力検出による自動の別経路(例: WebGL2 が無い環境で 2D)。ただし、利用者や設定が選ぶ形にしない。1 か所に決定論的な条件で書き、決定文書に条件と理由を記録する。
- 製品のコードに入らない、別の入口を持つ試験・計測の道具(別のファイル・別のプログラム)。製品のコードの中に『試験用のスイッチ』を置かない。

## 2. 規則

1. **新しいオプションを作らない。** 新しい機能は、最初から唯一の経路として入れる。
2. **既存のオプションは、(a) 有効側を唯一の経路にして旗と無効側のコードを削除する、(b) 実験・診断・未完成の物は旗ごと削除する、のどちらかにする。** 『既定で無効』のまま残さない。
3. **互いに排他の選択肢(同時に有効にできない物)は、契約に合う方、または測定が良い方を 1 つ選び、他を削除する。** 選んだ理由と測定を決定文書に書く。依頼者に選ばせない。
4. **未完成の機能は、無効で出荷しない。** 完成するまで取り込まず、成果物(作業木・差分)の中に置く。
5. **有効にして受け入れ条件(P1〜P3、S1、画素/行の同一性)を壊す場合**は、旗を戻して逃げず、コストを下げる作業で直す。測った数字を報告に書く。
6. **比較測定が必要なときは、コミット同士(別ビルド)で比べる。** 比較のための切り替えを製品のコードに残さない。
7. 同じ理由で、**プリセット名(`F2xH7` など)は廃止する。** 製品は 1 つの構成だけを持つ。
8. 診断・トレース出力(`getenv("…_TRACE")` など)も、製品の runtime の中のスイッチとしては持たない。必要な診断は、試験用の別の入口(規則 1 の例外の項)に置く。

## 2.1 運用の補足(決定 0243 opt1 の段階 1 で、一覧を作って規則では足りなかった所。PM の承認で本文になる)

1. **否定形は肯定形と同じオプション。** `FLE_NO_X`、`--no-x`、`X=0` は、`X` が働く側を有効側とする。出荷が否定形を常に渡している場合(`fe-wasmgen --no-elide`)は、字義どおりの有効側を試し、出力の同一性と費用を測ってから決める。
2. **契約に合う側が『診断・停止・検査』の無効側にある場合は、診断の旗ごと削除し、契約に合う側を残す。** 有効にして製品を止める/遅くするのは規則 5 の対象ではない(例: `FLE_DISPATCH_STOPS_ON_DEAD_WINDOW`、`FLE_CHECKED_MEM`、`FLE_SOFT_STOP`)。
3. **注入口は選択と同じ。** 自由な文字列を受けて選択を持ち込む変数(`RT_DEFS`、`RT_EXTRA_CFLAGS`、`LINK_EXTRA`、`WEBLINK_EXTRA`、`WASMOPT_EXTRA`、`WASM_EXTRA_STAGES`、`BUNDLE_NOTE`、`CI_EXTRA_CONFIG_VARS`、`?env=`)は削除する。
4. **部品間のパラメータはオプションではない。人が URL・環境・設定で指定する経路は消す。** 例: ページが測った画面の大きさを `FLE_MONITOR_W/H` で渡すのはパラメータ。`?audiolead=` のように URL から人が数値を変える経路は定数にする。
5. **実行中に人が押すボタン(パネルの開閉)は機能であり、オプションではない。** 再読み込みや再起動をまたいで残る選択(localStorage、URL)はオプション。
6. **ターゲットの判別は 1 か所に決定論的に書く。** 製品は wasm、native は試験と基準の生成のターゲット。`__EMSCRIPTEN__` から導く(`FLE_WASM32`、`FLE_VMEM_ARENA`、`FLE_LOWREGS` の選択、`FLE_THREAD_WASM`)。`-D` を手で渡さない。native だけの経路は試験の入口に属する。
7. **ビルドの段の指定(`gen`、`wasm`、`weblink` …)は、同じ出力へ至る手順の分割であり、オプションではない。** 出力を変える段を足す口は 3 のとおり。
8. **データのファイルが複数ある場合(import 行、prune の表、hybrid のリスト、hot unit の一覧)は、使う 1 つだけを残す。** 使わない版は git の履歴にある。
9. **製品の wasm にリンクされるハーネスのコード(`fruity.c`、`fruity_g3.c`、`hybrid_glue.c`、`b2d_swap.cpp`)は製品のコード。** ここにある診断(`getenv`)は規則 8 の対象で、製品の中のスイッチとして持たない。呼ぶだけで振る舞いを変えない検査用の関数(窓の一覧、面の情報などのエクスポート)はオプションではないので残してよい。
10. **セキュリティの無効化(`ACCESS_REQUIRED=false` など、認証を飛ばす口)は持たない。** 試験は設定の側(試験用のチーム/AUD と鍵の URL)で書く。

## 3. 進め方

- 決定 0243(opt1)が全オプションの一覧と処分の表を作り、層ごとの差分(ページ・CI、runtime の C、ビルドスクリプト/プリセット、lifter/wasmgen の旗)で畳む。
- 実行中の担当(gpu1、mt3、ship6、aud1、pick1)は、新しいオプションを作らない。取り込み済みの opt-in は opt1 が畳む。
- 畳むと FLEngine の生成 C の sha256、16 スナップの期待表、wasm の大きさが変わる場合は、変わった理由を 1 件ずつ説明し、新しい基準を記録する。
