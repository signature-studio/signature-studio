対象(読むだけ): lift/runtime/fle_gdc.c, lift/runtime/fle_layered.c, lift/runtime/fle_dwm.c(GetDC と ReleaseDC は fle_win.c の L48・L59 にもある)。`git grep -n -E "fle_imp_(GetDC|GetWindowDC|GetDCEx|ReleaseDC|GetDeviceCaps|UpdateLayeredWindow|UpdateLayeredWindowIndirect|SetLayeredWindowAttributes|GetLayeredWindowAttributes|DwmIsCompositionEnabled|DwmExtendFrameIntoClientArea|DwmGetCompositionTimingInfo)\b" lift/runtime` で定義と呼び出し元を探す。関連決定: 0053-virtual-screen-dc.md, 0140-layered-windows.md, 0171-user-operation-walls.md, 0302-dwm-timing-info.md。調査: docs/investigations/getdc-caller.md, docs/investigations/lay1/。定義の位置(task 作成時に実測。行が動いていたら grep し直す): fle_dwm.c: DwmIsCompositionEnabled@L19, DwmExtendFrameIntoClientArea@L32, DwmGetCompositionTimingInfo@L64; fle_gdc.c: GetDC@L297, GetWindowDC@L316, GetDCEx@L340, ReleaseDC@L369, GetDeviceCaps@L414; fle_layered.c: UpdateLayeredWindow@L250, UpdateLayeredWindowIndirect@L256, SetLayeredWindowAttributes@L271, GetLayeredWindowAttributes@L293; fle_win.c: GetDC@L48, ReleaseDC@L59。

1. Learn の各 API のページ(learn.microsoft.com。URL を記す)を読み、契約を要点にする(戻り値、失敗時の GetLastError、副作用、メッセージ、引数の検査)。

完了条件: 対象の全 API に行がある。判定ごとの行数の合計が表の行数と一致する。『不足』『違反』の各行に、契約に基づく最小の直し方(文章。コードは書かない)がある。
