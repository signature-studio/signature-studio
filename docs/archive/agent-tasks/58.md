# Task 58: app の unit 試験の質の点検(skip・期待値の固定・弱い検査)

目的: app/test/unit の試験の中の、skip(条件つきを含む)、固定の期待値(ハッシュ・数値)、弱い検査(toBeTruthy、`expect(x).toBeDefined()` だけ)を洗い出し、試験が何を守っているかの穴を表にする。
対象(読むだけ): app/test/unit/*.test.ts(PM の測定: 69 ファイル、vitest は 1313 pass・7 skipped)。`git grep -n -E "skipIf|\.skip\(|\.todo\(|toBeTruthy\(|toBeDefined\(" app/test/unit`(件数を数える)、`git grep -n -E "toBe\('[0-9a-f]{16,}'" app/test/unit`(固定ハッシュ)。
手順:
1. skip の全件を表にする: ファイル:行 | 条件 | Actions(リポジトリのみ)で skip になるか。(例: plugins-ott.test.ts は lift/out-mt1/data が無いと skip、files-zip-read.test.ts は ~/ダウンロード/serina1-serum2.zip が無いと skip)。
2. 固定の期待値の試験ごとに、その値の出所(決定番号・測定)がコメントにあるかを表にする。
3. 弱い検査の各件を、直すべきか(何を検査すべきか)を 1 行で書く(試験は書かない)。
完了条件: skip・固定値・弱い検査の 3 つの表がある。Actions で skip になる試験の数(自分の数)がある。
出力: ci/agents/out/58/report.md(日本語)。

規則(3 行。全 task 共通):
1. 報告の先頭に『実際に実行した物』(コマンドと終了コード)と『読んだだけの物』を分けて書く。数は実ファイルで自分が数えた物だけ。推測を事実と書かない。代役・モック・固定データの再生を実エンジンの結果として書かない。
2. lift の忠実性(docs/policies/lift-fidelity.md): バグの原因は (a) 余計な処理か (b) 外部 API の契約の不足・違反の 2 つだけ。提案は『除去』『契約に基づく API の拡充』『通信・変換の削減』だけで、性能・設計の新しい分岐は足さない。
3. この job にあるのは repo とネットだけ(Wine・実 Chrome・インストーラ・DLL・~/work は無い)。ci/agents/out/58/ の外は変更しない・commit しない・push しない。sleep/timeout/nohup/&/while/git stash を使わない。環境変数と資格情報を出力しない。
