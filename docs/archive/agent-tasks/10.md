# Task 10: app/ の unit テストの追加案(テストが無い純ロジックの洗い出しと、書いて走らせる)

目的: app/src の純ロジックのモジュールで、app/test/unit に対応するテストが無い物を洗い出し、5 本のテストを書いて vitest で走らせる。

対象: app/src(読む)、app/test/unit(PM の測定: 69 ファイル。数え直す)、app/vitest.config.ts(`include: test/unit/**/*.test.ts`)。

手順:
1. app/src の .ts を列挙し、各ファイルの import 名が app/test/unit のテストのどれかに現れるかを `git grep` で調べる(式を記す)。テストの無いモジュールを、純ロジック(DOM・Worker・ネットワークに触れない)かどうかで分ける。
2. 純ロジックのうち 5 本を選び、app/test/unit/<name>.test.ts として書く(既存のテストの書き方に合わせる。モジュールの実際の挙動を読んで期待値を決める。実装に合わせて期待値を作らず、名前・コメント・型から読める契約に対して書く。契約が読めない物は選ばない)。
3. `cd app && npm ci --no-audit --no-fund && npm test` を実行する(`npm test` は `vitest run`。ci/stage-app.sh の check と同じ呼び方)。失敗したら出力をそのまま report に貼る(テストを弱めて通さない。実装の不具合に見えるなら、そう書く)。vitest 自体が動かないなら、そのエラー全文と終了コードを貼って止める。

完了条件: テストの無いモジュールの一覧(純ロジックか否か)、新しい 5 本のファイル名、vitest の実行結果(コマンドと終了コード、Test Files / Tests の行)が report にある。新しいテストファイルは app/test/unit/ に未 commit で残す(job が changes.patch に保存する)。

出力: ci/agents/out/10/report.md(日本語)。

共通の規則: 先頭に『実際に実行した物』(コマンドと終了コード)と『読んだだけの物』を分ける。数は実ファイルで数えた物だけ。この job にあるのは repo とネットだけ。app/test/unit/ と ci/agents/out/10/ の外は変更しない・commit しない・push しない。製品のコード(app/src)は変更しない。代役・推測を結果として書かない。sleep/timeout/nohup/&/while/git stash を使わない。環境変数と資格情報を出力しない。
