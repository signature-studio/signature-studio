# Task 7: スレッド模型の文書と実装の照合(静的)

目的: docs/investigations/thread-model.md と、実スレッド版の決定(docs/decisions/0312e-s3-host-cpus-and-worker-count.md, 0315-rt1-real-thread-candidate.md, 0315f-pthread-mutex-and-gil.md)が述べるスレッド模型を要約し、lift/runtime/fle_thread.c と fle_thread_wasm.c の実装と照合して、『文書にあるが実装に無い』『実装にあるが文書に無い』『古くなった記述』を洗い出す。

対象(読むだけ): 上の文書 4 本、lift/runtime/fle_thread.c, fle_thread_wasm.c, fle_ctx_tls.c, fle_event.c(`git grep -n -E 'pthread|GIL|TlsAlloc|CreateThread|ExitThread|SuspendThread|ResumeThread' lift/runtime`)。

手順:
1. 文書の模型を 60 行以内で要約する(スレッドの種類、GIL の範囲、TLS、CreateThread の扱い、Worker との対応)。
2. 文書の各主張を、実装のファイル:行で裏付ける。裏付けが無い主張、実装にある振る舞いで文書に無い物、決定の日付より後に変わった物を表にする。
3. Win32 の契約(CreateThread / ExitThread / Suspend/ResumeThread / TLS)に照らして不足と思う所があれば、別表に(文章。直し方は契約に基づく最小の物)。

完了条件: 要約、照合表、(あれば)契約の不足の表がある。表の行はファイル:行を持つ。

出力: ci/agents/out/7/report.md(日本語)。

共通の規則: 先頭に『実際に実行した物』(コマンドと終了コード)と『読んだだけの物』を分ける。数は実ファイルで数えた物だけ。この job にあるのは repo とネットだけ(Wine・実 Chrome・インストーラ・DLL は無い)。ci/agents/out/7/ の外は変更しない・commit しない・push しない。性能・設計の新しい分岐を提案しない。代役・推測を実エンジンの結果として書かない。sleep/timeout/nohup/&/while/git stash を使わない。環境変数と資格情報を出力しない。
