対象(読むだけ): lift/runtime/fle_load.c と lift/runtime/fle_modules.c。`git grep -n -E "fle_imp_(LoadLibraryW|LoadLibraryA|LoadLibraryExW|FreeLibrary|SetDllDirectoryW|GetModuleHandleW|GetModuleHandleA|GetModuleHandleExW|GetProcAddress)\b" lift/runtime` で定義と呼び出し元を探す。関連決定: 0055-msctf-loadlibrary.md, 0233-loadlibrary-paths.md, 0238-api-set-loadlibrary.md, 0015-virtual-modules.md, 0082-two-module-load-semantics.md。調査: docs/investigations/loadlibrary-names-classification.md, docs/investigations/import-GetModuleHandleW.md, docs/investigations/getprocaddress-null-impact.md。定義の位置(task 作成時に実測。行が動いていたら grep し直す): fle_load.c: LoadLibraryW@L476, LoadLibraryA@L485, LoadLibraryExW@L508, FreeLibrary@L529, SetDllDirectoryW@L558; fle_modules.c: GetModuleHandleW@L252, GetModuleHandleA@L259, GetModuleHandleExW@L265, GetProcAddress@L369。
手順:
1. Learn の各 API のページ(learn.microsoft.com。URL を記す)を読み、契約を要点にする(戻り値、失敗時の GetLastError、副作用、メッセージ、引数の検査)。

3. 表にする: API | 契約(要点と URL) | 実装(ファイル:行) | 判定(一致/不足/違反/不明/停止) | 根拠。

完了条件: 対象の全 API に行がある。判定ごとの行数の合計が表の行数と一致する。『不足』『違反』の各行に、契約に基づく最小の直し方(文章。コードは書かない)がある。
