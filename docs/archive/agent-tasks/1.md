# Task 1: カーソル・キャプチャ・クリップの契約の静的監査(lift/runtime)

目的: lift/runtime が実装する ShowCursor / SetCursor / ClipCursor / GetClipCursor / SetCapture / ReleaseCapture / GetCapture / GetCursorPos / SetCursorPos と、関連メッセージ(WM_SETCURSOR、WM_CAPTURECHANGED、WM_NCHITTEST)の挙動を、Microsoft Learn の契約(戻り値・副作用・送られるメッセージ)と突き合わせ、不足・違反を洗い出す。lift 忠実性の方針(docs/policies/lift-fidelity.md)の (b) 外部 API の不足の発見が目的。

対象(読むだけ): lift/runtime/fle_cursor.c, fle_cursor.h, fle_input.c, fle_win.c(`git grep -n -E 'ShowCursor|SetCursor|ClipCursor|SetCapture|ReleaseCapture|GetCapture|GetCursorPos|SetCursorPos|WM_CAPTURECHANGED|WM_SETCURSOR|WM_NCHITTEST' lift/runtime` で探す)。関連決定: docs/decisions/0319-pointer-lock-stage2.md, 0323-contract-fixes.md, 0325-cursor-pictures.md。

手順:
1. 各 API の契約を Learn(learn.microsoft.com の該当ページ。URL を記す)から読む。
2. 実装の場所(ファイル:行)と、戻り値・副作用・送るメッセージ・スレッドの規則(キャプチャは入力キューを持つスレッド単位、など)を読む。
3. 表にする: API | 契約(要点と URL) | 実装(ファイル:行) | 判定(一致/不足/違反/不明) | 根拠。

完了条件: 上の 9 API と 3 メッセージの全ての行がある。『不足』『違反』の各行に、契約に基づく最小の直し方(文章。コードは書かない)がある。

出力: ci/agents/out/1/report.md(日本語)。

共通の規則: 先頭に『実際に実行した物』(コマンドと終了コード)と『読んだだけの物』を分ける。数は実ファイルで数えた物だけ。この job にあるのは repo とネットだけ(Wine・実 Chrome・インストーラ・DLL は無い)。ci/agents/out/1/ の外は変更しない・commit しない・push しない。性能・設計の新しい分岐を提案しない。代役・推測を実エンジンの結果として書かない。sleep/timeout/nohup/&/while/git stash を使わない。環境変数と資格情報を出力しない。
