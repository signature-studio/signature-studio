# Task 57: app の unit テストのカバレッジの穴の表(src の各モジュール × テスト)

目的: app/src・app/worker・app/shared の各 .ts モジュールについて、どのテストファイルがそれを import するかを表にし、テストの無い・薄いモジュールの一覧を作る。
対象(読むだけ): app/src, app/worker, app/shared, app/tools の .ts(PM の測定: 88 モジュール、そのうち basename がどの unit/worker/helper のテストにも import されない物が 15: shared/headers.ts, main.ts, engine/worker.ts, files/engine-dialog.ts, files/explorer.ts, files/mount.ts, files/ops.ts, perf/display-host.ts, plugins/driver-worker.ts, plugins/ott-host.ts, plugins/plugin-worker.ts, ui/desktop.ts, ui/panels.ts, ui/progress.ts, worker/index.ts。数え直す)。テストは app/test/unit(69 ファイル)、app/test/worker、app/test/helpers。
手順:
1. モジュールごとに、import しているテストの一覧と、export の数(`git grep -c -E "^export " <file>`)を表にする。
2. テストが無い物は、DOM・Worker・ネットワークに触れない純ロジックかどうかを読んで分ける。
3. 純ロジックのうち、テストを足す価値の高い順に 10 件を選び、各 1〜2 行で『何を検査すべきか』(名前・型・コメントから読める契約。実装に合わせた期待値は作らない)を書く。
完了条件: 全モジュールの表と、テストの無い物の一覧(純ロジックか否か)と、10 件の提案がある。テストは書かない(task 10 が 5 本を書く。task 10 と重なる物は『task 10』と注記)。
出力: ci/agents/out/57/report.md(日本語)。

規則(3 行。全 task 共通):
1. 報告の先頭に『実際に実行した物』(コマンドと終了コード)と『読んだだけの物』を分けて書く。数は実ファイルで自分が数えた物だけ。推測を事実と書かない。代役・モック・固定データの再生を実エンジンの結果として書かない。
2. lift の忠実性(docs/policies/lift-fidelity.md): バグの原因は (a) 余計な処理か (b) 外部 API の契約の不足・違反の 2 つだけ。提案は『除去』『契約に基づく API の拡充』『通信・変換の削減』だけで、性能・設計の新しい分岐は足さない。
3. この job にあるのは repo とネットだけ(Wine・実 Chrome・インストーラ・DLL・~/work は無い)。ci/agents/out/57/ の外は変更しない・commit しない・push しない。sleep/timeout/nohup/&/while/git stash を使わない。環境変数と資格情報を出力しない。
