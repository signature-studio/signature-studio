# Task 38: fle_res.c のリソース API の契約監査(FindResourceW / LoadStringW ほか)

目的: lift/runtime/fle_res.c の 6 個の API(FindResourceW, LoadResource, LockResource, SizeofResource, FreeResource, LoadStringW)を Microsoft Learn の契約(戻り値、失敗時の GetLastError、副作用、送られるメッセージ、引数の検査)と突き合わせ、不足・違反を洗い出す(lift 忠実性の (b) 外部 API の不足の発見)。実装は変更しない。
対象(読むだけ): lift/runtime/fle_res.c。`git grep -n -E "fle_imp_(FindResourceW|LoadResource|LockResource|SizeofResource|FreeResource|LoadStringW)\b" lift/runtime` で定義と呼び出し元を探す。関連決定: 0025-resource-apis.md, 0062-load-image-missing-resource.md。調査: docs/investigations/loadimage-caller.md。定義の位置(task 作成時に実測。行が動いていたら grep し直す): fle_res.c: FindResourceW@L247, LoadResource@L271, LockResource@L289, SizeofResource@L311, FreeResource@L330, LoadStringW@L349。
手順:
1. Learn の各 API のページ(learn.microsoft.com。URL を記す)を読み、契約を要点にする(戻り値、失敗時の GetLastError、副作用、メッセージ、引数の検査)。
2. 実装(ファイル:行)を読む。契約が開いている所を実装が選ばずに `fle_stop` で止める分岐は『停止』と書き、不足とは別に数える。
3. 表にする: API | 契約(要点と URL) | 実装(ファイル:行) | 判定(一致/不足/違反/不明/停止) | 根拠。
4. MAKEINTRESOURCE と文字列名(`#123` 形式を含む)の扱い、言語(MAKELANGID、LANG_NEUTRAL のフォールバック順)、LoadStringW の nBufferMax が 0 のとき(リソース内の文字列へのポインタを返す)と終端 NUL の扱い、文字列テーブルのブロック(16 個ごと)の規則を別表にする。`fle_stop` の件数(PM の測定: 55 個)を数え直し、どの入力で止まるかを分類する。
完了条件: 対象の全 API に行がある。判定ごとの行数の合計が表の行数と一致する。『不足』『違反』の各行に、契約に基づく最小の直し方(文章。コードは書かない)がある。
