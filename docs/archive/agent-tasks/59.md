# Task 59: getenv・FLE_ 環境変数・診断スイッチの一覧と、OFF のときの負荷の読み(lift/runtime・lift/harness)

目的: lift/runtime と lift/harness(web を除く)の診断・トレースのスイッチ(`getenv("FLE_…")`、`FLE_…` の #ifdef、診断用のカウンタ・ログ出力)を一覧にし、スイッチが OFF のときにホットパスに残る負荷(分岐・カウンタ更新・文字列組み立て)を、コードの読みで評価する。
対象(読むだけ): `git grep -n -o -E "getenv\(\"FLE_[A-Z0-9_]+\"\)" -- lift/runtime lift/harness ":(exclude)lift/harness/web"`(変数名の頻度の上位: FLE_FRUITY_VIRTUAL_SECONDS、FLE_DEC1_TRACE、FLE_HYB_STATS、FLE_HYB_DBG、FLE_FRUITY_TRAP 等。PM の測定。数え直す)、`git grep -c -E "^\s*#\s*(if|ifdef|ifndef|elif)\b.*FLE_" -- lift/runtime`(PM の測定: 全体で 136 ファイル・251 行)。lift/runtime の getenv は fle_screen.h と fle_thread.c(FLE_DWM_HZ、FLE_DISPLAYSETTINGS_FREQUENCY)と fle_test_env.h。
手順:
1. 変数名ごとに表にする: 名前 | 読む場所(ファイル:行) | 何が変わるか | 製品にリンクされるか(根拠) | OFF のときの負荷(ホットパス上か、起動時 1 回か)。
2. 診断が入ったホットパスの候補(`git grep -n -E "diag|trace|stats|count\+\+" lift/runtime/fle_win.c lift/runtime/fle_gdi.c lift/runtime/fle_input.c lift/runtime/fle_thread.c` で探す。式と件数を記す)の中から、OFF でも毎回実行される加算・分岐を 10 件選んで表にする。
3. 『読み』と『測定』を分ける。この task は測定しない(負荷の数字は書かない)。
完了条件: 変数の表と、ホットパスの 10 件の表がある。製品の経路にある診断で『除去』『テストの別の入口へ移す』べき物の一覧(docs/policies/no-options.md の項番つき)がある。
出力: ci/agents/out/59/report.md(日本語)。

規則(3 行。全 task 共通):
1. 報告の先頭に『実際に実行した物』(コマンドと終了コード)と『読んだだけの物』を分けて書く。数は実ファイルで自分が数えた物だけ。推測を事実と書かない。代役・モック・固定データの再生を実エンジンの結果として書かない。
2. lift の忠実性(docs/policies/lift-fidelity.md): バグの原因は (a) 余計な処理か (b) 外部 API の契約の不足・違反の 2 つだけ。提案は『除去』『契約に基づく API の拡充』『通信・変換の削減』だけで、性能・設計の新しい分岐は足さない。
3. この job にあるのは repo とネットだけ(Wine・実 Chrome・インストーラ・DLL・~/work は無い)。ci/agents/out/59/ の外は変更しない・commit しない・push しない。sleep/timeout/nohup/&/while/git stash を使わない。環境変数と資格情報を出力しない。
