# Task 60: g9_hook ほか mt3 の診断 diff(docs/investigations/mt3w)が製品に入っていないことの確認

目的: docs/investigations/mt3w/ にある診断 diff(`diag-g9-hook.diff`、`diag-g9-count.diff`、`diag-g9-gui.diff`、`diag-g9-loadlib.diff` など)の内容(何を増やすか)を要約し、それらの診断が lift/runtime・lift/harness の現行の製品コードに入っていないことを確かめる。
対象(読むだけ): docs/investigations/mt3w/0313/impl/*.diff と docs/investigations/mt3w/0315/impl, tools。`git grep -n -E "g9_hook|fle_g9|g9mix" -- lift app ci`(PM の測定では docs と diff の外に g9_hook は無い。数え直す)。決定: docs/decisions/0315d-rtb-native-tests.md(g9_hook の診断の記述)、0319-owner-observations-contract-reading.md、0309-g9-entry-estimate.md。
手順:
1. 各 diff を 3 行で要約する(どのファイルのどの関数に何を足すか。diff のヘッダと hunk の関数名を読む)。
2. diff が足す識別子(関数名・変数名・ログの接頭辞)を取り出し、現行の lift/runtime・lift/harness・app・ci にそれらが存在するかを `git grep -n -F` で確かめる(各識別子について件数)。
3. 存在する物があれば、それが製品の経路か試験専用かを読んで判定し、docs/policies/no-options.md 規則 8 の項番で処分を書く。
完了条件: diff ごとの要約と識別子の存在の表がある(全て 0 件なら『0 件』と、実行したコマンド)。
出力: ci/agents/out/60/report.md(日本語)。

規則(3 行。全 task 共通):
1. 報告の先頭に『実際に実行した物』(コマンドと終了コード)と『読んだだけの物』を分けて書く。数は実ファイルで自分が数えた物だけ。推測を事実と書かない。代役・モック・固定データの再生を実エンジンの結果として書かない。
2. lift の忠実性(docs/policies/lift-fidelity.md): バグの原因は (a) 余計な処理か (b) 外部 API の契約の不足・違反の 2 つだけ。提案は『除去』『契約に基づく API の拡充』『通信・変換の削減』だけで、性能・設計の新しい分岐は足さない。
3. この job にあるのは repo とネットだけ(Wine・実 Chrome・インストーラ・DLL・~/work は無い)。ci/agents/out/60/ の外は変更しない・commit しない・push しない。sleep/timeout/nohup/&/while/git stash を使わない。環境変数と資格情報を出力しない。
