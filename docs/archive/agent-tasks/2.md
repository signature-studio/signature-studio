# Task 2: メニューの契約の静的監査(TrackPopupMenu / WM_CONTEXTMENU ほか)

目的: lift/runtime のメニュー関連の実装を Microsoft Learn の契約と突き合わせ、不足・違反を洗い出す。対象: CreatePopupMenu, AppendMenuW, InsertMenuItemW, GetMenuItemInfoW, TrackPopupMenu, TrackPopupMenuEx(TPM_RETURNCMD / TPM_NONOTIFY / TPM_LEFTBUTTON などの旗の意味)、EndMenu、メッセージ WM_CONTEXTMENU, WM_INITMENUPOPUP, WM_ENTERMENULOOP, WM_EXITMENULOOP, WM_MENUSELECT, WM_COMMAND。lift 忠実性の方針(docs/policies/lift-fidelity.md)の (b)。

対象(読むだけ): lift/runtime/fle_crash1_menu.c, fle_crash1_menu.h, fle_win.c(`git grep -n -E 'TrackPopupMenu|WM_CONTEXTMENU|INITMENUPOPUP|ENTERMENULOOP|EXITMENULOOP|MENUSELECT|EndMenu' lift/runtime`)、lift/runtime/test/menu_battery.inc と menu_battery_wine10.txt(Wine 10 で取った参照。リポジトリにある)、docs/decisions/0322-lift-fidelity-audit.md, 0323-contract-fixes.md。

手順:
1. 契約を Learn から読む(URL を記す)。WM_CONTEXTMENU は DefWindowProc が WM_RBUTTONUP / VK_APPS / Shift+F10 から作る、という契約が実装にあるかを確かめる。FL の lift 済みコードがやるべきことを runtime が代行していないかも見る(代行があれば『余計な処理』として別表に)。
2. 実装(ファイル:行)と、menu_battery の期待との差を読む(実行はしない。読むだけ)。
3. 表: API/メッセージ | 契約 | 実装 | 判定(一致/不足/違反/不明) | 根拠。

完了条件: 上の全ての API・メッセージに行がある。不足・違反の行に、契約に基づく最小の直し方(文章)がある。『余計な処理』の表(無ければ『無し』と、探した grep の式)がある。

出力: ci/agents/out/2/report.md(日本語)。

共通の規則: 先頭に『実際に実行した物』(コマンドと終了コード)と『読んだだけの物』を分ける。数は実ファイルで数えた物だけ。この job にあるのは repo とネットだけ(Wine・実 Chrome・インストーラ・DLL は無い)。ci/agents/out/2/ の外は変更しない・commit しない・push しない。性能・設計の新しい分岐を提案しない。代役・推測を実エンジンの結果として書かない。sleep/timeout/nohup/&/while/git stash を使わない。環境変数と資格情報を出力しない。
