# Task 56: docs/investigations の表(.tsv・表形式 md)の形式の点検

目的: docs/investigations/ にある表(.tsv と、md の表)の形式の揺れ(列数・区切り・見出し・空欄・日付の書式・数値の桁区切り)を洗い出す。
対象(読むだけ): `git ls-files "docs/investigations/**/*.tsv"`(件数を数える)と、md の表を持つ文書(`git grep -l -E "^\|[-: |]+\|$" -- docs/investigations`)。例: docs/investigations/wall-census-1.tsv, wall-census-2.tsv, wall-census-2-single.tsv。
手順:
1. tsv ごとに、行ごとの列数が一定か(`awk -F"\t" "{print NF}" <file> | sort | uniq -c`)、見出し行の有無、空行・末尾の空白を表にする。
2. md の表は、見出し行と区切り行(`|---|`)の列数が各行と一致するかを、スクリプト(python3 または awk。自分で書いて実行し、そのコマンドを報告に貼る)で全ファイル検査する。
3. 列数が揺れるファイルの一覧(ファイル:行)を出す。直しの diff は書かない。
完了条件: 検査したファイル数・不一致のファイル数・不一致の行の一覧がある(0 件なら『0 件』)。検査のスクリプトの全文が報告にある。
出力: ci/agents/out/56/report.md(日本語)。docs/ は変更しない。

規則(3 行。全 task 共通):
1. 報告の先頭に『実際に実行した物』(コマンドと終了コード)と『読んだだけの物』を分けて書く。数は実ファイルで自分が数えた物だけ。推測を事実と書かない。代役・モック・固定データの再生を実エンジンの結果として書かない。
2. lift の忠実性(docs/policies/lift-fidelity.md): バグの原因は (a) 余計な処理か (b) 外部 API の契約の不足・違反の 2 つだけ。提案は『除去』『契約に基づく API の拡充』『通信・変換の削減』だけで、性能・設計の新しい分岐は足さない。
3. この job にあるのは repo とネットだけ(Wine・実 Chrome・インストーラ・DLL・~/work は無い)。ci/agents/out/56/ の外は変更しない・commit しない・push しない。sleep/timeout/nohup/&/while/git stash を使わない。環境変数と資格情報を出力しない。
