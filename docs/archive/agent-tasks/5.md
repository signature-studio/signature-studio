# Task 5: lift/harness の getenv の棚卸し(製品に入る物と試験の入口を分ける)

目的: docs/policies/no-options.md の節 2.1 の項 8・9(製品の wasm にリンクされるハーネスのコードの診断 getenv は、製品の中のスイッチとして持たない。試験・計測の別の入口は残してよい)に従って、lift/harness の getenv を分類する。

対象(読むだけ): `git grep -n 'getenv(' -- 'lift/harness/*.c' 'lift/harness/*.cpp' 'lift/harness/*.h' ':(exclude)lift/harness/web'`(PM の測定: 92 行。数え直して実数を書く)。製品にリンクされるファイルは、docs/policies/no-options.md 節 2.1 項 9 の `fruity.c`, `fruity_g3.c`, `hybrid_glue.c`, `b2d_swap.cpp`。リンクされるかは app/scripts/build-engine-bundle.sh と ci/stage-wasm.sh の読みで確かめる(ビルドは実行しない)。

手順:
1. 全ての getenv を表にする: ファイル:行 | 変数名 | 読んだ値で何が変わるか | 製品にリンクされるか(根拠のファイル:行) | 誰が設定するか(`git grep` で試験・スクリプトを探す)。
2. 製品にリンクされる物だけを別表にし、処分(旗ごと削除/契約に合う側を唯一の経路にする/試験の別の入口へ移す)を、規則の項番を付けて書く。コードは書かない。
3. 試験専用(製品にリンクされない)物は『残してよい』として数だけ書く。

完了条件: 全行が分類されている。製品にリンクされる物の変数名の一覧と、その処分がある。実数は自分の grep と一致している。

出力: ci/agents/out/5/report.md(日本語)。

共通の規則: 先頭に『実際に実行した物』(コマンドと終了コード)と『読んだだけの物』を分ける。数は実ファイルで数えた物だけ。この job にあるのは repo とネットだけ(Wine・実 Chrome・インストーラ・DLL は無い)。ci/agents/out/5/ の外は変更しない・commit しない・push しない。新しいオプションや分岐を提案しない。代役・推測を実エンジンの結果として書かない。sleep/timeout/nohup/&/while/git stash を使わない。環境変数と資格情報を出力しない。
