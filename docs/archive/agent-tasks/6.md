# Task 6: タイマー・メッセージキュー・同期の契約の静的監査

目的: lift/runtime のメッセージ・タイマー・同期の API を Microsoft Learn の契約と突き合わせ、不足・違反を洗い出す(lift 忠実性の (b))。対象: SetTimer / KillTimer と WM_TIMER(最小間隔、メッセージの優先順位、WM_PAINT・WM_TIMER が最後に配られること)、GetMessage / PeekMessage(PM_REMOVE、フィルタ、WM_QUIT)、PostMessage / SendMessage(別スレッド宛ての扱い)、MsgWaitForMultipleObjects(Ex)、WaitForSingleObject(Ex)、SetEvent / ResetEvent / CreateEvent(自動・手動リセットの意味)。

対象(読むだけ): lift/runtime/fle_timerq.c, fle_event.c, fle_thread.c, fle_win.c, fle_proc.c, fle_time.c(`git grep -n -E 'SetTimer|KillTimer|WM_TIMER|GetMessage|PeekMessage|PostMessage|SendMessage|MsgWaitForMultipleObjects|WaitForSingleObject|SetEvent|ResetEvent|CreateEvent' lift/runtime`)。関連: docs/decisions/0050-event-sync.md, docs/investigations/event-sync-run.md。

手順:
1. 契約を Learn から読む(URL を記す)。
2. 実装(ファイル:行)を読み、表にする: API | 契約(要点と URL) | 実装(ファイル:行) | 判定(一致/不足/違反/不明) | 根拠。
3. 不足・違反の行に、契約に基づく最小の直し方(文章)を書く。性能のための近道が入っていれば『余計な処理の候補』として別表にする。

完了条件: 上の全ての API に行がある。不足・違反の行に直し方がある。『余計な処理の候補』の表(無ければ『無し』と、探した grep の式)がある。

出力: ci/agents/out/6/report.md(日本語)。

共通の規則: 先頭に『実際に実行した物』(コマンドと終了コード)と『読んだだけの物』を分ける。数は実ファイルで数えた物だけ。この job にあるのは repo とネットだけ(Wine・実 Chrome・インストーラ・DLL は無い)。ci/agents/out/6/ の外は変更しない・commit しない・push しない。性能・設計の新しい分岐を提案しない。代役・推測を実エンジンの結果として書かない。sleep/timeout/nohup/&/while/git stash を使わない。環境変数と資格情報を出力しない。
