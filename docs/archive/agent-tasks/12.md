# Task 12: fle_win.c の窓の生成・破棄・属性の契約監査(CreateWindowExW ほか)

目的: lift/runtime/fle_win.c の 7 個の API(CreateWindowExW, DestroyWindow, SetWindowLongPtrW, GetWindowLongPtrW, SetWindowTextW, GetWindowTextW, DefWindowProcW)を Microsoft Learn の契約(戻り値、失敗時の GetLastError、副作用、送られるメッセージ、引数の検査)と突き合わせ、不足・違反を洗い出す(lift 忠実性の (b) 外部 API の不足の発見)。実装は変更しない。関連メッセージ: WM_NCCREATE, WM_CREATE, WM_NCDESTROY, WM_DESTROY, WM_CLOSE, WM_GETTEXT, WM_SETTEXT, WM_GETTEXTLENGTH。
対象(読むだけ): lift/runtime/fle_win.c。`git grep -n -E "fle_imp_(CreateWindowExW|DestroyWindow|SetWindowLongPtrW|GetWindowLongPtrW|SetWindowTextW|GetWindowTextW|DefWindowProcW)\b" lift/runtime` で定義と呼び出し元を探す。関連決定: 0071-virtual-windows.md, 0070-virtual-window-classes.md, 0122-cooperative-threads.md。調査: docs/investigations/window-design.md。定義の位置(task 作成時に実測。行が動いていたら grep し直す): fle_win.c: CreateWindowExW@L920, SetWindowLongPtrW@L1162, GetWindowLongPtrW@L1259, SetWindowTextW@L1300, DefWindowProcW@L1328, GetWindowTextW@L3784, DestroyWindow@L4385。
手順:
1. Learn の各 API のページ(learn.microsoft.com。URL を記す)を読み、契約を要点にする(戻り値、失敗時の GetLastError、副作用、メッセージ、引数の検査)。
2. 実装(ファイル:行)を読む。契約が開いている所を実装が選ばずに `fle_stop` で止める分岐は『停止』と書き、不足とは別に数える。
3. 表にする: API | 契約(要点と URL) | 実装(ファイル:行) | 判定(一致/不足/違反/不明/停止) | 根拠。
4. DefWindowProcW が WM_ごとに何を既定処理するかを別表にし、Learn の既定処理の記述との差を書く(FL の窓クラスで分岐する処理が見つかれば『余計な処理』として別表)。
完了条件: 対象の全 API に行がある。判定ごとの行数の合計が表の行数と一致する。『不足』『違反』の各行に、契約に基づく最小の直し方(文章。コードは書かない)がある。
出力: ci/agents/out/12/report.md(日本語)。
