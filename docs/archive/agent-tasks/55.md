# Task 55: docs/investigations の孤立した調査文書の洗い出し

目的: docs/investigations/ 直下の .md(PM の測定: 210 ファイル)のうち、他のどの文書・コードからもファイル名で参照されない物を洗い出し、何についての文書かを 1 行で書く。
対象(読むだけ): `ls docs/investigations/*.md`。参照の探し方: ファイルごとに `git grep -l -F "<ファイル名>" -- docs app ci lift README.md`(自分自身は除く)。PM の概算では、参照が 0〜1 回の物が 26 個(`a6-a12-run.md`、`a9-a10-run.md`、`bulk-table-895.md`、`callsite-0x41ce10.md`、`cpuid-run.md`、`seed-pdata-852.md`、`test-etxtbsy.md`、`ver-run.md` など)。数え直す。
手順:
1. 全ファイルについて参照元の数を数え、孤立(参照元 0)の一覧を作る。
2. 孤立した各ファイルの冒頭を読み、題名・日付・対応する決定の番号(本文にあれば)を表にする。
3. 孤立のうち、対応する決定の索引の行(docs/README.md、docs/decisions/INDEX.md)から辿れる物と辿れない物を分ける。
完了条件: 孤立の件数(自分の数)と表がある。推測した関連は『推測』と明記する。
出力: ci/agents/out/55/report.md(日本語)。docs/ は変更しない。

規則(3 行。全 task 共通):
1. 報告の先頭に『実際に実行した物』(コマンドと終了コード)と『読んだだけの物』を分けて書く。数は実ファイルで自分が数えた物だけ。推測を事実と書かない。代役・モック・固定データの再生を実エンジンの結果として書かない。
2. lift の忠実性(docs/policies/lift-fidelity.md): バグの原因は (a) 余計な処理か (b) 外部 API の契約の不足・違反の 2 つだけ。提案は『除去』『契約に基づく API の拡充』『通信・変換の削減』だけで、性能・設計の新しい分岐は足さない。
3. この job にあるのは repo とネットだけ(Wine・実 Chrome・インストーラ・DLL・~/work は無い)。ci/agents/out/55/ の外は変更しない・commit しない・push しない。sleep/timeout/nohup/&/while/git stash を使わない。環境変数と資格情報を出力しない。
