## 機構

### OS 側(`lift/runtime/fle_seh.c`、569 行)

- `fle_seh_raise`(kernel32!RaiseException の中身。`fle_proc.c` の `fle_imp_RaiseException` が**弱参照**で呼ぶ。`fle_seh.c` を持たないリンクは従来の名前付き停止のまま): EXCEPTION_RECORD(0x98 バイト)を作り、呼び出し元のフレーム(スタブに入った時点の R[]、`[R[4]]` の戻りアドレス、`R[4]+8`)から、マップ済みイメージの `.pdata` の UNWIND_INFO で**仮想 unwind** する(PUSH_NONVOL・ALLOC_SMALL/LARGE・SET_FPREG・SAVE_NONVOL(_FAR)・SAVE_XMM128(_FAR)、連鎖 UNWIND_INFO。Learn の手順どおり)。UNW_FLAG_EHANDLER を持つフレームごとに、DISPATCHER_CONTEXT と CONTEXT を作って、ゲストのハンドラを `fle_call_guest(handler, rec, EstablisherFrame, ctx, dc)` で呼ぶ(pass 1)。返りは 1(ExceptionContinueSearch)だけを受け付ける。
- `fle_seh_unwind_ex`(ntdll!RtlUnwindEx。ハンドラが一致のとき自分で呼ぶ): 送出点から TargetFrame まで再び仮想 unwind し、UNW_FLAG_UHANDLER を持つフレームのハンドラを UNWINDING(目標のフレームでは TARGET_UNWIND も)つきで呼ぶ(pass 2。ゲストの finally funclet はこの中でゲストのハンドラが呼ぶ)。目標のフレームの**登録**を (関数の RUNTIME_FUNCTION の開始, 入口の rsp) で探し、callee-saved(rbx rbp rsi rdi r12–r15、xmm6–15)を unwind した値、rsp = 目標フレームの呼び出し点の rsp、rax = ReturnValue にして、`fle_callback_depth`・`fle_landing_top`・影スタックの深さを登録時の値に戻し、`_longjmp` する。
- 名前付き停止(実測のテストあり): ハンドラが無い(「N frames searched」)、ホストのコールバック(`fle_call_guest` の戻りアドレス 0xCB000000)に当たる、登録の無い目標フレーム、目標を通り過ぎる、ディスパッチ中の送出(入れ子)、ExceptionContinueExecution の返り、ほかの disposition、別スレッドの登録、prologue の中の戻りアドレス、version 1 でない UNWIND_INFO、UWOP_PUSH_MACHFRAME(出典なしの選択の表の S-seh-* のとおり)。

### 着地側(生成 C。`fe-lift --seh-handler`)

- `fe_decode::seh::delphi_landings`: ハンドラ RVA(引数。FLEngine は 0x112c0)を名前に持つ UNWIND_INFO の LSDA(`{u32 count; count × {begin, end, f2, f3}}`)の scope を読み、except の着地(f2 == 2 の f3、f2 > 2 の `on` 表の着地)を列挙する。範囲はすべて関数の内側であることを検査し、外れは**誤りにする**(推測しない)。
- `fe-lift`: 着地を最後の seed に足し(関数入口 `f_L` になる)、着地を持つ関数 `f_P` には**入口ラッパー**を出す(本体は `fb_P`、`no_instrument_function`):
  ```
  void f_P(void) { fle_seh_reg sr; fle_seh_enter(&sr, P); if (FLE_SEH_SETJMP(&sr) == 0) { fb_P(); } else { fle_seh_land(&sr); } fle_seh_leave(&sr); }
  ```
  `fle_seh_enter` は登録(関数 VA、入口の R[4]、`fle_landing_top`、`fle_callback_depth`、影スタックの深さ、スレッド番号)を連鎖に積む。`_setjmp` は**ラッパー自身の C フレーム**に置く。`fle_seh_land` は文脈を復元して `fle_dispatch(TargetIp)` で `f_L` を同じ C フレームの中で呼ぶ。`--seh-handler` が無ければ出力は**バイト単位で同一**(テストで確認)。
- スレッド: 登録の連鎖 `fle_seh_top` とディスパッチ状態 `fle_seh_cur` は `fle_thread.c` の `gctx` に載せて切り替える(`fle_landing_top` と同じ作り)。登録を作ったスレッドと現在のスレッドが違えば名前付き停止。決定 0100 の着地の `longjmp` は登録の連鎖も戻す(`fle_dispatch.h`)。
- wasm の読み(**未測定**): `fle_seh.c` は同期の C で JSPI の中断を挟まない。着地への `_longjmp` は `SJLJ=wasm` の `try/catch`(決定 0124)。wasm では `FLE_LANDING_NOJUMP`(`__EMSCRIPTEN__` の既定)で着地に当たると名前付きで停止し、`FLE_LANDING_FORCE` と `-sSUPPORT_LONGJMP=wasm` を付ければ着地できる。着地を持つ 2,816 関数が setjmp フレームを持つ wasm の大きさ・速度・V8 のコンパイル時間への影響は**未測定**。`emcc` で runtime の 52 ファイルすべて(`fle_seh.c` を含む)がコンパイルできることだけ確認した(`FLE_LANDING_FORCE` つきの `fle_seh.c`・`fle_thread.c`・`fle_proc.c` も)。
