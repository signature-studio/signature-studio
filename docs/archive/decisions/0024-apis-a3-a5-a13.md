## 決定（仕様が決めない値）

1. **GMEM_MOVEABLE のハンドル**: ページは「メモリオブジェクトへのハンドル」としか書かない。値は `0x7FFA50000000 + 16 * (i + 1)`（`FLE_GLOBAL_HANDLE_BASE`、i は 0 始まりの通し番号）。トークンで、そこには何もマップされない。再利用しない（解放後の誤用を検出するため）。GMEM_FIXED は malloc のポインタそのもの（ページ: ハンドル = ポインタ）。
2. **ハンドル領域の配置**: 決定 0018 の `0x7FFA00000000`（ファイル）、`0x7FFA10000000`（検索）、`0x7FFA20000000`（レジストリキー）の上に、`0x7FFA50000000`（グローバルメモリ、A3）、`0x7FFA60000000`（DuplicateHandle の process/thread、A5）、`0x7FFA70000000`（ファイルマッピング、A13）を、各 `0x10000000` 取った。`0x7FFA30000000`、`0x7FFA40000000` は他の担当者の予約の可能性があるので空けた（grep で他に使用がないことは確認した。予約の有無は未確認）。重なりは各テストで確認する。
3. **アトムの値**: ページは「文字列アトムは 0xC000〜0xFFFF」「ユニーク」としか書かない。新しい文字列アトムには、0xC000 から順に空きを割り当て、最後に与えた値の次から回る。ローカル表とグローバル表は別々で、どちらも空で始まる。**値は選択**。
4. **アトム名の限界**: ページは「255 バイトまで」。NUL を含むかが書かれていないので、126 UTF-16 単位（252 バイト）までを受け、それを超えたら止める。**選択**。空の名前もページが定めないので止める。ASCII 外の文字を含む名前は、大文字小文字の折りたたみがページにないので止める（ASCII だけ折りたたむ。`fle_env.h` と同じ方針）。
5. **ボリューム**: 唯一のドライブは仮想ボリューム `C:`（`fle_vfs.h`: 空の `C:\`）。種別は DRIVE_FIXED（3）、ラベルは空、ファイルシステム名は `FAT32`、シリアル番号は 0x464C4531、最大コンポーネント長は 255（ページは「長い名前をサポートする FAT では 255」と書く）、フラグは 0x6（FILE_CASE_PRESERVED_NAMES | FILE_UNICODE_ON_DISK）。**ページは形だけを決め、これらの値はすべて選択**。`FAT32` にした理由は、NTFS を名乗るとフラグ（ACL、圧縮、ストリームなど）の主張が増えるため（推測を含む選択）。
6. **QueryDosDeviceW**: `C:` は `\Device\HarddiskVolume1`（ページの例の形。番号は選択）。他のドライブ文字は 0 を返す。
7. **GetStdHandle**: プロセスは標準ハンドルを持たない（決定 0018: GetStartupInfoW は標準ハンドルを 0 とした）。ページが「標準ハンドルがなく、リダイレクトもされていない場合は NULL」と書くので、3 つの有効な値はすべて NULL を返し、最後のエラーは触らない。
8. **DuplicateHandle の仮想ハンドル**: 擬似ハンドル（GetCurrentProcess、GetCurrentThread）は実ハンドルに変換される（ページ）。値は `0x7FFA60000000 + 4 * (i + 1)`。アクセス権は実装全体でモデル化していないので、`dwDesiredAccess` と `bInheritHandle` は受けて無視する（ページの意味では値が効くが、検査する側がない）。
9. **ファイルマッピング**: 実体は匿名の memfd（プロセス内メモリで、ホストのファイルではない）。ビューは割り当て粒度（65536）に揃えた新しいアドレス範囲。ファイル（仮想ファイル）のマッピングは、作成時点の内容のスナップショット。**書き戻しはしない**。ページが「マップしたファイルと ReadFile/WriteFile は必ずしも一貫しない」と書くので、一貫性を求めない実装は仕様の範囲内。PAGE_READWRITE のファイルマッピングは書き戻しが要るので止める。
10. **VirtualProtect の失敗コード**: ページは失敗を「0 を返す」としか書かない。範囲がコミット済みでない、または領域をまたぐときは ERROR_INVALID_ADDRESS（487）、旧保護の出力先が NULL のときは ERROR_INVALID_PARAMETER（87）。**ページにない選択**。
11. **VirtualQuery**: 追跡しているメモリ（VirtualAlloc の領域とここで作ったビュー）だけを記述する。それ以外（ロードしたイメージ、ホストのスタックとヒープ、未使用の空間）は、ランタイムが追跡していないので止める（偽の MEM_FREE などを作らない）。最高アドレス（`FLE_MAX_APP_ADDR`、`GetSystemInfo` と同じ値。これもページにない選択）を超える場合は ERROR_INVALID_PARAMETER（ページ）。`PartitionId` は 0（ページは意味を書かない）。FILE_MAP_COPY のビューは PAGE_WRITECOPY と報告する（ページが可能な値として挙げる。**推測**）。

## 実装しなかった（止める）もの

- GlobalAlloc: 数値がページにないフラグ（0x2000 以外の廃止フラグ、およびページに数値がない未知のビット）。GMEM_FIXED で 0 バイトの扱い（ページが定めない）は 1 バイトとして確保（LocalAlloc と同じ。選択）。GlobalReAlloc、GlobalSize、GlobalFlags は応答していない（閉包にこの 11 件の外）。
- GlobalFree / GlobalLock / GlobalUnlock: 確保済みでない値（解放済み、他のアロケータ、ストレイ）。
- アトム: 空の名前、126 単位超の名前、非 ASCII の名前、満杯の表（16384 件）、検索での範囲外の `#dddd`。GlobalDeleteAtom、GetAtomName は閉包にない。
- GetStdHandle: 3 つの有効値以外（ページは失敗の条件を書かない）。
- ドライブ: `X:\` 以外の形（末尾のバックスラッシュなし、UNC、相対）。GetVolumeInformationW の小さすぎるバッファ（ページは挙動を書かない）。QueryDosDeviceW の NULL（全デバイス名の列挙）、`X:` 以外のデバイス名。
- DuplicateHandle: 仮想ファイルのハンドル（`fle_vfs.c` のハンドル表に触れる必要がある）、他のプロセス、DUPLICATE_CLOSE_SOURCE と擬似ハンドル、`dwOptions` の他のビット、発行していないハンドル。
- VirtualProtect: `dwSize` 0、PAGE_GUARD などの修飾、PAGE_WRITECOPY、CFG のフラグ、ビューと追跡外メモリ。
- VirtualQuery: 追跡外のアドレス、構造体より小さいバッファ。
- CreateFileMappingW: 名前つきオブジェクト、セキュリティ属性、PAGE_READONLY と PAGE_READWRITE 以外、SEC_COMMIT 以外の SEC_*、サイズ 0 の匿名オブジェクト、1 GiB 超（ランタイムの上限）、仮想ファイル上の PAGE_READWRITE、読み取り権のないファイルハンドル、ファイル長を超える最大サイズ。
- MapViewOfFile: FILE_MAP_EXECUTE、大きなページ、CFG、オブジェクトの保護が許さない要求（ページが失敗コードを書かない）、粒度に揃っていないオフセット、範囲外のオフセットと長さ。

## 既存ファイルへの変更

- `fle_sys.c`: 領域の各ページに、コミット済みなら現在の PAGE_* の値を持たせた（以前は 1 バイトの COMMITTED 印）。領域に `alloc_protect`（予約した呼び出しの `flProtect`）を足した。VirtualProtect、VirtualQuery 用に `fle_sys_region_at`、`fle_sys_set_protection` を追加した（領域表は static のまま）。`FLE_MIN_APP_ADDR`、`FLE_MAX_APP_ADDR` を `fle_sys.h` に移した（値は同じ）。VirtualAlloc の動作は変えていない（`tests/sys.rs` 18 件が通る）。
- `fle_vfs.c/.h`: `CloseHandle` が、他のランタイムファイルが発行したハンドル（DuplicateHandle の複製、ファイルマッピング）を先に問い合わせる登録口（`fle_vfs_add_close_hook`）と、`CreateFileMappingW` が開いた仮想ファイルの内容を読む `fle_vfs_file_info` を追加した。ファイル系の動作は変えていない（`tests/vfs.rs` 22 件が通る）。

## 限界

- Windows 実機との照合はしていない（ホストが Linux）。期待値は Microsoft Learn のページと、テスト内で独立に書いたモデル（MulDiv は i128 の厳密計算）による。
- ページが書かないエラー番号（87、6、2、3、487 など）、ボリュームの値、アトムの値は選択で、実機と一致する保証はない。
- 上の「実装しなかった」入力にゲストが来れば、その時点で止まる。ゲストの呼び出し引数を静的に全部調べたわけではない（呼び出し箇所のうち数か所の引数を逆アセンブルで読んだだけ）。
