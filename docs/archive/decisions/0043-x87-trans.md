# 0043: x87 の f2xm1 と fsincos を、ホスト非依存の「正しく丸めた」ソフト実装で埋める

状態: PM の決定（f2xm1 = 案 A、fsincos = 案 D2）に従った実装。実装中の細部（範囲外入力の扱いなど）は作業者の判断で、各節に明記する。実行記録は `docs/investigations/x87-trans-run.md`。調査（到達性、案の比較）は `docs/investigations/f2xm1-fsincos-reach.md`。0033 の「実装しなかった」節のうち f2xm1 と fsincos は、この決定で置き換わる（0033 自体は変更していない）。

実装: `lift/runtime/fle_x87.c`（`fle_x87_f2xm1`、`fle_x87_fsincos` と 256 bit の演算部。+427 行）、`fle_x87.h`（宣言 2 つ）、`lift/crates/fe-lift/src/x87.rs`（`F2xm1`、`Fsincos` の生成 2 行と PROTOS 2 行。`lib.rs` は触っていない）。テストは `lift/crates/fe-lift/tests/x87_trans.rs`（新規 9 件）と `tests/x87_trans/`（`gen_ref.py`、`check_bf.py`）。`tests/x87.rs` と `tests/x87ctl.rs` は「未対応のまま」の確認から f2xm1・fsincos を外しただけ。

## 決定

1. **f2xm1**: 入力が −1.0 ≤ x ≤ +1.0 のとき、2^x − 1 を RC（最近偶数、−∞、+∞、0 方向）に従って 64 bit 仮数に**正しく丸めた**値を返す。±0 は入力のまま。±1.0 は厳密値（+1 → +1.0、−1 → −0.5）で PE を立てない。非正規化入力は DE。NaN は quiet 化して返し、SNaN は IE。未サポート形式は IE と実数不定値。
2. **f2xm1 の範囲外（|x| > 1、±∞）**: SDM は「結果は未定義」。**実装依存として、名前付き abort にする**（`fle: x87: F2XM1: operand outside -1.0 .. +1.0 (the SDM leaves the result undefined); not modelled`）。値を作らない。理由は §範囲外。
3. **fsincos**: SDM の疑似コード（Vol.2、FSINCOS）どおり。ST(0) に sin、TOP を 1 減らして新しい ST(0) に cos を置く（結果は ST(0)=cos、ST(1)=sin）。|x| < 2^63 のとき C2=0。|x| ≥ 2^63 のときは C2=1 にして ST(0) 不変、push しない、PE なし。引数は SDM の Pi（66 有効ビット、`0x3243F6A8885A308D3 × 2^-64`、Vol.1 §8.3.8）で `x = k·Pi/2 + r`（k は最近整数、|r| ≤ Pi/4）に**厳密に**縮約し、r の sin/cos を正しく丸め、k mod 4 で回す。縮約は 128 bit 整数の除算で、丸めは入らない。
4. 丸めは「256 bit 仮数の級数で値を求め、真値は計算値の ±2^16 単位（256 bit 仮数の最下位から 16 bit 上）の範囲に入る、その両端が**同じ丸め結果・同じフラグ**になることを確認する」方式。両端が違う（真値が丸め境界の 2^-239 以内にある）ときは `fle: x87: ...: rounding is not decided at 256 bits` で abort する。実測では 19,308 行の参照表と 280,000 回のホスト比較で一度も起きていない。
5. 標準 C のみ（ISO C + `unsigned __int128` は既存の `round_pack` と同じ使い方）。256 bit の演算は 32 bit の肢の整数演算だけ。`long double`、`__float128`、libm、x86 asm、intrinsic は使っていない。

## PM の決定の理由

- 最終目的は C → emcc → wasm。x86 ホストの f2xm1/fsincos を隔離実行する案（D1）は wasm で動かないので採らない。
- fsincos の Pi(66 bit) 縮約（D2）は、ホストが SDM どおりの Pi で縮約していることの実測（`pi66-out.txt`、p=+1.0 で cos がホストの 6.1230317691e-17 になる）に基づく。縮約を省いて真の π で計算すると、到達しうる入力域で p=+1.0 の 1 点が float32 で違う（調査 §3）。今回も `pi66-last-bit`、`pi-as-double` の変異をテストが検出した。
- f2xm1 を含む `f_6a2a10` は静的に到達しない（調査 §1.3）ので、ホストとの bit 一致は目標にしない。

## wasm を考慮した設計

- ホスト FPU に触れない（決定 5 の通り: `long double`、`__float128`、libm、x86 asm、intrinsic を使わない）。結果は入力・RC・CW だけで決まる決定的な値。
- 依存は整数演算（`unsigned __int128` の shift・乗算・除算・剰余を含む）と `memset`/`memcpy`/`fprintf`/`abort`。`unsigned __int128` は clang の wasm32 でコンパイラ-rt（`__ashlti3` ほか。emscripten は付属）を使う。これは `round_pack` など既存のコードが既に使っている依存で、新しい種類ではない。
- **実測**: `clang --target=wasm32 -ffreestanding` で `fle_x87.c` と `fle_x87ctl.c` を警告なし（既存の `fle_flags.h` と fscale の 1 件を除く）でコンパイルし、128 bit の補助関数を自前のスタブで補ってリンクし、node（v24.19.0）で同じ参照表 19,308 行を実行した。**不一致 0、trap 0**（`out-x87c/wasm-check.txt`）。emcc はこの環境に無い（未確認）。スタブは `out-x87c/wasm_driver.c`（テスト用の簡易実装で、実機の compiler-rt ではない）。
- 速度は測っていない。256 bit の級数（最大約 300 項、各項が 8×8 肢の乗算）なので、ホストの命令より大幅に遅い（推測）。f2xm1 は到達せず、fsincos は 1 呼び出し当たり 1 回なので、影響は小さいと見ている（推測、未測定）。

## ホストとの突合を目標としない

- 突合は**参考値**として記録する（テスト `differs_from_the_host_by_less_than_the_sdm_error_bound`）。bit 一致は要求しない。要求するのは、最近偶数で 1 ulp 以内（ULP 差 ≤ 1 刻み）、他の RC で 2 刻み以内、タグ語と TOP が一致、の 3 つ。
- 結果（テスト既定 280,000 回、x86_64 のホスト AMD Ryzen 9 9950X）: f80 結果が違うもの **4,254 件（1.52%）**、最大差 **1 刻み**（最近偶数でも 1）、C1 が違うもの 1,890 件、それ以外のステータスビット（PE、UE、DE、IE、C2）の差 0、タグ語の差 0、TOP の差 0。別の 700,000 回ずつの測定（`diff_host2-out.txt`。fsincos はスタック満杯の約 1/8 を除く）では f2xm1 13,698 件（1.96%）、fsincos 6,219 件（0.89%）が違い、最大差は 1 刻み。以前の記録の 5,696/200,000 と 26,840/200,000 は RC=最近偶数のみ・別の入力分布なので、件数は直接比べられない。

### 許容範囲であることの SDM の文言

SDM Vol.1 §8.3.10: 「…the worst case error on transcendental functions is less than 1 ulp when rounding to the nearest (even) and less than 1.5 ulps when rounding in other modes. The functions are guaranteed to be monotonic…」。誤差は「真値 − 計算値」を 2^(k−63) で割った値（k は真値の指数）。

- 正しく丸めた値の誤差は、最近偶数で 0.5 ulp 以下、他の RC で 1 ulp 未満。どちらも上の上限の内側（実測は `errulp-out.txt`: ソフトの最大誤差は f2xm1 0.5000／1.0000 ulp、fsincos 0.6460／1.1445 ulp。fsincos の 0.65 と 1.14 は縮約を使う領域を含み、縮約のない |x|<Pi66/4 では 0.5000／1.0000）。
- ホストの最大誤差は f2xm1 で 0.6200（最近偶数）、1.10〜1.14（他の RC）、fsincos で 0.6507、1.03〜1.16。つまりホストも SDM の上限内で、**ホスト自身も正しく丸めた値ではない**。正しく丸めた値と 1 刻み違うことは、仕様の許容誤差から説明される。
- ただし、SDM は「どの値を返すか」を規定しないので、「正しく丸めた値が仕様の唯一の答え」ではない。これは PM の選択（案 A/D2）であって、仕様からの導出ではない。
- 注意（誤差の測定範囲）: 上の誤差測定は f2xm1 が 2^-60 < |x| < 1、fsincos が 2^-8 ≤ |x| ≤ 1.4 の領域のみ。SDM は π の倍数付近で fsincos の誤差が大きくなることを書いており、そこは測っていない（ただし縮約に使う Pi が SDM の 66 bit なので、ホストと同じ縮約誤差を持つ。ホストと一致するかは、π/2 の倍数の近傍でテストに入れ、参照表（同じ Pi66 で計算）と一致している）。

### ホストとステータスワードが違う点（実測）

- **C1**: ホストは、結果が一致していても C1 が違うことがある（f2xm1 の 0.7%、fsincos の 0.2〜0.3% 程度、`diff_host2-out.txt` の「C1 differs with equal results」）。C1 の意味は SDM では「結果が切り上げられたとき 1」。実装は「sin（f2xm1 では結果）を切り上げたとき 1」。fsincos では ST(0) に残る sin と push する cos のどちらの切り上げか SDM が書いていない。ホストの C1 が sin の切り上げに追従する割合を測ると、RC=0・|x| が 2^-8〜1 の領域で、結果が一致した入力のうち 195,640/197,566（99.0%）。cos の切り上げへの追従は 98,773/197,566（50%）。実装は sin に合わせた。他の領域・RC では測定の一部のみ（`exp_model4` の出力は記録していない）。残りの 1% の**原因は調べていない**（推測: ホストの内部丸めの形）。
- **x = ±1.0 の f2xm1**: ホストは PE を立てる（+1、RC=0 で 0x220、他 0x020 など）。結果は厳密（+1.0、−0.5）なので、SDM の「#P: 値が正確に表現できない」に従い、実装は PE を立てない。この差は `pm1-out.txt`。
- C0、C3（f2xm1 は C2 も）: SDM は Undefined。ホストは変更しない（`swprobe-out.txt`）ので、実装も変更しない。

## 範囲外入力の扱い（f2xm1）

- SDM Vol.2: 「The value of the source operand must lie in the range –1.0 to +1.0. If the source value is outside this range, the result is undefined.」（`sdm-vol2.txt` 20620 行付近）。
- ホストは範囲外でも値を返す: 実測（`probe_host`）で 2.0 → 2.0、2^63 → 2^63（PE）、+∞ → +∞、−∞ → −1.0、いずれも例外はない。2^x − 1 の値ではない（2.0 で 3.0 ではない）。この「入力をそのまま返す」はホスト固有（AMD）の振る舞いで、仕様ではない。
- 決定: 名前付き abort。理由: ① 仕様が結果を定義していないので、どの値も根拠にできない。② 閉包で f2xm1 を呼ぶ `f_6a2a10` は `f = y − round(y)`（|f| ≤ 0.5）を渡す（調査 §1.2、静的）ので範囲内で、abort には到達しない（推測を含む。静的読みで、実行では未確認）。③ 止めれば、将来別の呼び出し元が範囲外を渡したとき、気付ける。SDM の「結果は未定義」に従った値を作ると、誤った値を静かに通す。代わりに「ホストと同じく入力を返す」案も可能だが、ホスト固有なので採らなかった。
- ±∞ も範囲外として abort（ホストは +∞ → +∞、−∞ → −1.0 を返す。数学的な極限としては妥当だが、SDM の表 3-18 に入力 ±∞ の行がなく、範囲外なので同じ扱い）。
- 範囲外判定は「|x| > 1」で、x = ±1.0 ちょうどは範囲内。

## 未マスク例外・スタック

0033 と同じ流儀（モデル化しない、名前付き abort）: 未マスクの PE/DE/IE が起きる場合、命令開始時にマスクされていない例外フラグが残っている場合、スタックのアンダーフロー（空の ST(0)）とオーバーフロー（fsincos で ST(7) が空でない場合。|x| ≥ 2^63 のときもホストは先にオーバーフローを報告して実数不定値を 2 つ置くので、同じく abort）。|x| ≥ 2^63 の fsincos は結果も PE もないので、PE が未マスクでも止まらない（テストで確認）。

## Intel と AMD の差は確認していない

- 実機はこのホスト（AMD Ryzen 9 9950X）だけ。Intel の CPU での f2xm1/fsincos の値、ステータスワードは未確認。
- 外部の公開例（調査 §2.2）では f2xm1 の値が AMD と Intel で異なる。1 例（Monakov）で、正しく丸めた値は Intel の値と一致したが、Intel が常にそうであるという意味ではない。本実装は仕様の許容誤差内で「正しく丸めた値」を選んだものであり、**Intel 実機と一致することは確認していない**。

## 確認できていないこと

- Intel 実機との一致。ホストの C1 が結果と食い違う入力の原因。
- fsincos の π/2 の倍数付近・大きな引数（2^40 以上など）での誤差の大きさ（縮約が Pi66 で厳密なので、正しく丸めた値は「Pi66 で縮約した式の値」であって「真の sin x」ではない。ホストが同じ縮約をしていることは p=+1.0 の 1 点と π/2 の倍数の近傍の突合で確認したが、全域の証明ではない）。
- emcc でのビルド。128 bit の補助関数（`__ashlti3` など）は emscripten に付属のものを使う前提（このリンクでは自前スタブで代替した）。速度。
- f2xm1 の呼び出し元 `f_6a2a10` の実行時の到達性（静的に読み手 0。実行は x87 に未到達）。fsincos の実行時の到達。
- 変異テストで検出できる範囲外: 級数の項数の上限（f2xm1 300 項、sin/cos 200 項）に達して abort する経路（`series did not converge`）は、通常の入力では到達しない。
