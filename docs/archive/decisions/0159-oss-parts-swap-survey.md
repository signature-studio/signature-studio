# 0159: 同梱 DLL のうち上流から作り直せるもの(FreeType、Blend2D)と、置き換えの価値の判断。仮の決定

状態: **仮の決定**。きっかけは依頼者の問い(2026-11-03、原文): 「Blend2Dやfreetypeといったライブラリをliftする必要はあるのか？そもそもオープンソースなのでは？」。調査は作業者(`swap1`)が行った(静的調査と、公開 OSS の小さなビルド、実 DLL 3 本を Wine 10.0 で単体として呼ぶ小さな exe。**FL Studio は実行していない。進捗ではない**)。調査の本文は `docs/investigations/swap-survey.md`(`tables/`、`tools/`、`sources.tsv` は `docs/investigations/swap-survey/`)。判断は PM。

区分の凡例は決定 0121〜0158 と同じ。**実測**＝作業者のコマンドの出力を見た事実(PM は下記の数字を再測定していない)。**読み**＝解釈。**未確認**。

## 0. 事実(依頼者の問いへの答え)

1. **lift は必須ではない。** 同梱 DLL のうちオープンソースなのは 2 つで、上流から作り直せる(実測)。
   | DLL | 上流と版 | 確度 | 実 DLL(Wine)との照合 |
   |---|---|---|---|
   | `freetype_x64.dll` | FreeType **2.4.10**(2012-06-15)。`FT_New_Library` の即値 2/4/10 が根拠。ビルドは MSVC 2005(リンカ 8.0)で、「MSVC 2012」は誤りだった | 高 | 4 フォント × ロードフラグ × 描画モードの 43 組合せで、ビットマップ・アウトライン・メトリクス・cmap・カーニングが DLL、native、wasm -O2/-Oz で一致 |
   | `Blend2D.dll` | Blend2D **a7f9476(0.11.1、2024-05-31)** + AsmJit(ABI 1.13)を静的リンク。直前の 7e32ebf との差は JIT の 1 行で、SRC_OUT のアンチエイリアス画素で区別できた | 高 | プロジェクトの 6 手順の FNV 値が lift 版の記録値と一致。ランダム 100 万手(6 種)の 1 万点の全画面ハッシュが、実 DLL、上流 native、上流 wasm で一致 |
   ただし `Blend2D.dll` のうち **Agg2D ラッパー(vtable 130 スロット、実体約 77)は Image-Line 製で上流にない**。
2. **`dsp_ippv2_x64.dll` は Intel IPP 2021.7(oneAPI 2022.3 相当、2022-11-04 ビルド)の静的リンク版で、オープンソースではない**(ISSL の下で再配布は可)。export は 446 個(`ipps*` 366、`ippi*` 71、core 8、`AggCreateInstance` 1。「449」は足し算の誤り)。dsp の `AggCreateInstance` は Blend2D 版と別の、AGG 2.x 系らしい実装で、FLEngine は引かない(死んだコード、確度は中)。**置き換え先が無い**(結果ビット同一の OSS が無い)。HLE でしか触れない。
3. **ILTools と QFC は Image-Line の Delphi コード**でオープンソースではない。QFC は AggPas(AGG 2.4 の Pascal 移植)と FreeType 結合ユニットを内蔵する。FreeType を呼ぶのは QFC だけで、271 個のうち 14 個。
4. **置き換えが効くのは大きさ(S1)で、起動(P1)と UI(P2)にはほぼ効かない。** 上流の wasm は Blend2D 全 API(no-JIT)で 1.0 MB(lift 版 44.0 MB)、FreeType 0.37 MB(同 2.9 MB)。合計で約 45 MB(全体 322 MB の約 14%)減り、S1 は 4.54 倍 → 約 3.9 倍で 2 倍には届かない(読み)。起動の CPU(perf3、native の lift 実行)でモジュール別の最寄り関数の割合は、FLEngine 56.4%、**dsp 36.6%**、QFC 3.7%、Blend2D 2.8%、FreeType 0.5%。3〜10 秒の窓では dsp が 90.8%、Blend2D は 0.7%。**P1/P2 の本命は dsp の熱い関数**(`ippiWarpAffineQuad_8u_C4R` が dsp の標本の 68〜74%。決定 0151)。
5. **決定 0120(Blend2D の JIT 無効)の主張のうち弱くなる部分。** 固定パイプライン(JIT 無し)が描ける合成演算は、29 種のうち **4 種**(SRC_OVER、SRC_COPY、DST_COPY、CLEAR)だけ。残り 25 種は `BL_ERROR_NOT_IMPLEMENTED` を返し、何も描かない(上流の issue #182 は Open。作者は全演算版に時間を割いていない)。決定 0120 の「138 テスト全部が done」「画素が実機と同じ」は、この 4 種を超えては成立しない。FL が使う合成演算は、静的な下限で SRC_OVER・SRC_COPY・OVERLAY の 3 種(OVERLAY は「線形グラデーション + OVERLAY + パスを線として描く」の 1 か所)。**固定パイプラインに自前のテンプレートを足すと、PLUS(4 行)と OVERLAY(約 35 行)は実 DLL(JIT)とビット同一になった**(solid と線形グラデーション、30〜60 シーンで不一致 0)。強くなる部分: JIT 無効が効いていること、6 手順とランダム手の画素一致。
6. **グラデーションのずれの原因は、`Agg2D::attach` が設定する `setHint(GRADIENT_QUALITY=DITHER)` を上流のテストに入れていなかったこと。** 設定すると実 DLL と完全一致した。ラッパーを lift したまま使う案では、この設定はラッパーが自分で行う。

## 1. 決定(仮)

| # | 項目 | 決定 |
|---|---|---|
| 1 | 置き換えの位置づけ | **S1 のための手段であり、P1/P2 の手段ではない。** 作業量が週の桁になる。dsp の対策が進まないなら、割に合わない場合がある(swap1 の撤退条件)。 |
| 2 | Blend2D | 決定 0160(b2d1)の**ハイブリッド案**(オブジェクトモデルは lift のまま、コンテキストだけ上流 wasm)を、実装して測る。b2d1 の 1.5 時間の区切りで走査 138 テストが通らなければ、案 ii(ラッパーの意味を上流の上に再実装)に切り替えるかを PM が決める。swap1 は案 ii を第 1 候補と推奨した(ラッパーは薄く、DllMain・CRT・コアの lift を外せる)。 |
| 3 | HLE の定義の読み替え | 案 ii はゲストの関数でなく DLL ごと置き換える。**ゲストの関数と結果が完全に同一**の定義の代わりに、**実 DLL(Wine、x86-64 の実機械語)とのビット同一を、乱数 10^6 手以上と、実エンジン 16 スナップの面 SHA 不変で示す**ことを条件に認める。ただし実機 Windows との照合は 0 件のまま。 |
| 4 | Wine の実 DLL を基準にする | **認める。** 実 Windows ではないが、x86-64 の実機械語を実行する。lift 版の記録値と全部一致した。lift 版の native ビルドとの差分テストを主、Wine の実 DLL を副の基準にする。dsp の HLE の差分テストにも使う(swap1 が `ippiWarpAffine/Perspective/FilterBoxBorder/Copy` の入出力ハッシュの表を作った)。 |
| 5 | FreeType | **最後にする**(0.9%)。置き換えるときは、QFC が読むフィールド約 20 個を呼び出し後にゲスト配置へ写す shadow struct 方式で。素の 2.4.10 の wasm は、オートヒンターの関数型の不一致(2 か所)を直す必要がある。 |
| 6 | 合成演算 | b2d1 が `blendMode` の頻度を実エンジンで測る。16 スナップの範囲では `blendMode`(スロット 15)は 0 回(実測)。JIT 専用の演算が出た時は、必要な物だけテンプレートで足す(1 演算あたり半日の桁、読み)。**決定 0120 の「画素が実機と同じ」は 4 種の合成演算に限る**と、この決定で改める。 |
| 7 | **P1/P2 の本命** | **dsp の熱い関数の HLE** と、**`fle_dispatch`(間接呼び出しの二分探索)の高速化**に移す(決定 0162、0163)。起動の最大の項 `f_33d6e70`(`ippiWarpAffineQuad_8u_C4R` の内側)は、結果が同一であることを検証済みの参考実装がある(決定 0151)。 |
| 8 | dsp の枝刈り | dsp の実行された関数は 25,370 のうち 335(0.9%)。死んだ AGG と、引かれない export(26 個)と、読み手のない 273 個を lift の対象から外す案、および実行された関数だけの遅延取得は、S1 に直接効く(dsp は 54%)。決定 0157(wasmgen1)の設計文書の結果と合わせて判断する。 |

## 2. 訂正

- 「DLL ごとの置き換えを評価した記録は無い」は、Blend2D については誤り(決定 0158 に記録済み)。
- 第 1 報の「5 種」は誤り。正しくは 4 種(DST_OVER は背景が不透明で偶然一致していた)。
- FreeType の wasm の修正は 1 行でなく 2 か所(`aftypes.h` の typedef と `afdummy.c` の第 3 引数)。
- swap1 が取得した blend2d.com のページ末尾に、依頼者でも PM でもない自動メッセージ風の文が付いていた。従っていない。

## 3. 未確認

- lift した FreeType/Blend2D の同じ負荷の実行時間(Blend2D を含む native の 6 モジュール実行ファイルが `lift/out-*` に無かった)。
- FL が実行時に `blendMode` へ渡す値の頻度(決定 0160 が測る)。
- コアの不明関数 2 個(0x76030、0x75f20)の役割。ラッパーがコアの impl を直接読むこと(決定 0160 の第 1 報で、読むと判明)。
- radial/conic グラデーションと pattern での自前演算の一致。
- 実機 Windows との照合(0 件)。

## 4. 撤回条件

- 決定 0160 のハイブリッドと案 ii の両方で、実 DLL との画素差が原因不明のまま残る場合(置き換えをやめ、現状の lift に戻す)。
- FL が JIT 専用の演算を多数(目安: 5 種超)使い、テンプレートがビット同一にならない場合(混成 M8 の実行時 x86→wasm か、依頼者への画素差の報告を選ぶ)。
