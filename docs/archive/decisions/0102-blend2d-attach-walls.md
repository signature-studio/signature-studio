## 要約

Blend2D の `DllMain(DLL_PROCESS_ATTACH)` は、**決定 0095（swapped 形の MSVC switch）の取り込みだけで最後まで通った**（このために直した壁は 0 個）。読み取り専用の gdb の記録（`run/g0-imports.txt`）: `call_dllmain(idx=1, reason=1)` が 0x1 を返し、`LoadLibraryW("Blend2D.dll")` が 0x4700000 を返し、`GetProcAddress(0x4700000, "AggCreateInstance")` が 0x4759a60 を返して、unit 150 以降が動いた。3 モジュール測定構成は **init_count 150 → 159 / 942**（0095 の効果。HEAD a951ecc の PM のコミット文と一致）で、次の停止は unit 158 の `LoadLibraryW "QuickFontCache_x64.dll"`（外部モジュール）。

その先（依頼の「壁ごとのループ」）は、QFC（基底 0x1d00000）と freetype_x64.dll（基底 0x4b00000）を 3 つ目・4 つ目の実在モジュールとして載せた測定構成（**測定用の値で、決定ではない**）で続け、**13 個の壁**を通した（下の表）。**init_count は 159 のまま動いていない**（unit 158 の QFC の DllMain の中を進んだだけ）。最終の停止は `SystemParametersInfoW: uiAction 0x200a is not answered`（SPI_GETFONTSMOOTHINGTYPE。止まる条件 (d): ページは値の候補 2 つを挙げるだけで既定を書かない、機械の設定）。

凡例: **実測** = コマンドの出力を見た値、**読み** = ソース・逆アセンブルを読んだ結果で実行して確かめていないもの、**未確認** = 確かめていないこと。

## 解釈が分かれた点

1. **W1 の綴り**: 表の名前（小文字）を使った。ディスク上の綴り（`QuickFontCache_x64.dll`）を返すには、表に表示名を持たせるか、最初の `LoadLibraryW` の綴りを覚える必要がある。ページは大文字小文字を決めないので小さい方を選んだ。
2. **W2 で `LockResource` の探索を足した**: 引数にモジュールが無い。到達した証拠はない（`LoadStringW` だけが届いた）が、`FindResourceW`／`LoadResource`／`SizeofResource` と同時に直さないと不整合になる。
3. **W3 の run の長さ**: ガードから N を導けない（`size` の符号付き比較 3 つの合成）ので再配置の連続にした。FLEngine の注釈（8 スロット）と違い、QFC では 9 スロット（index −8 の分が 1 つ多い）になる。過大側で、余計な case は取られない。
4. **W7 の先取り 2 つ**（`GetEnvironmentStrings`、`FreeEnvironmentStringsA`）は実行されなかった。最小の修正の原則からは外れる。テストはある。
5. **W11 の `HeapSize`** は、別のヒープのブロックを停止にした（ページは undefined）。
6. **W8 の `EncodePointer`** は、決定 0078 が名前付き停止にしていたものを置き換えた。0078 の読み（「例外処理だけ」）が freetype の CRT には当てはまらなかった。
7. **freetype の基底**（0x4b00000）は、QFC と dsp の間の隙間に入らないために選んだ。割り付けは 0086 の「決めないこと」のまま。

## 限界

- **init_count は 159 のまま**。QFC の DllMain（unit 158）は SPI `0x200a` で止まっていて、戻っていない。unit 159 以降は届いていない。
- 4 モジュール構成は `fle_realmod` の上限（4）を使い切る。5 つ目（Elastique、ILTools など）は runtime の上限の変更が要る。
- `GetModuleFileNameW` の綴り（W1）、`EncodePointer` の秘密（W8）、`SetHandleCount` の戻り（W10）、`0x200C` の値（W13）は実機と比べていない。
- 先取りの 2 API（W7）、`LockResource` の実在モジュール対応（W2）は、このゲストでは実行されていない。
- native だけ。wasm、ブラウザは測っていない。FLEngine の thunk 1 つ（`0x423910`）が `HeapCreate` の呼びになった（W6）。
- 全体テストの 1 回目は、ディスクが満杯になって（`No space left on device`）途中で切れた。`test-ws.txt` は 949 行で終わっている（無効）。2 回目の結果は「検証」の最後。
- init_count の変化だけを A4 の進捗として数える。停止点が進んだことは進捗ではない。
