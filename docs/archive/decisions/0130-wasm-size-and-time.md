3. **-O1 と -O2 の差は小さい**(エンジン 32.1〜32.7 s と 30.4〜31.1 s、3〜5%)。ビルドは -O2 の方が 12% 長い。
4. **ビルドの難所は時間と RAM の取り合い**。-O1/-O2 は units 段が 52〜59 分(JOBS=2、ピーク 5.2〜5.4 GB)。JOBS を増やすと 7 GB の枠を超える。1 単位の emcc は -O1/-O2 で最大 3.2 GB。
5. **隔離 Chrome の HTTP キャッシュは 6 MB 超の応答を 2 回目に使わない**。0128 の記録の「Cache Storage の `put` は 22 MB 以上で失敗」は今回の Chrome 156 では再現せず、**128 MB は成功、復号後 300 MB 以上で失敗**(`Unexpected internal error`)だった(新しい context、quota 10 GB)。
6. **wasm-opt は 450〜530 MB の入力に対して RSS 6 GB 以上を要する**。同じ機械で、-O1 は 35 s、-O2(C3 に対して)は 24 s だが、B への -O2 は OOM、-O3 は 59 分で終わらなかった。
7. **フック無しの -O1 は最大の関数で 540 s かかる**(フック付きは 15 s)。原因は未調査。

## PM の未決の点(決めない。推奨は書く)

1. **どの変種を本番の基準にするか。** 候補: **C2(-O2)** = 時間最良(最初の画素 30 s、idle 33 s)、brotli 22.6 MB、生 526 MB(1 GiB の 49%)、ビルド 59 分(JOBS=2、RAM 5.4 GB)。**C3/D2(-Oz)** = 大きさ最小(brotli 12〜13.6 MB、生 215〜249 MB)、時間は 1.5〜1.6 倍(45.8〜49.2 s)、ビルド 7 分(RAM 2.8 GB)。**推奨: 基準は C2(時間)、開発中の反復には C3(ビルドが 8 倍速い、実行は 1.6 倍遅い)**。G9 で 1 GiB を超えることが確実なので、-Oz 系への切り替えと分割は C2 を基準にした上で別途の判断にする。-O1(C1)は C2 に対して時間が 3〜5% 遅いだけでビルドが 7 分短いが、renderer のピークが 200〜300 MB 大きい(1,745 MB)。
2. **実行時間の目標。** 現状は idle まで 33 s(C2、loopback)。ネットワークが加わると 25 Mbit/s で 44 s。**何秒を「許容」とするか**(例: 初回 60 s 以内/再訪 30 s 以内)を PM が決める。エンジン実行 30 s が 90% を占めるので、次の桁(10 s 以下)は最適化レベルではなく**初期化の仕事そのものを減らす**(CreateFruityInstance の 135M 入口。スナップショット等 = 未検討)必要がある。推奨: 目標を決める前に、**ゲストの何が 135M 入口を要するか**(0129 の延長の idle1 側の調査)を見る。
3. **wasm 分割の要否。** G9 は**必要**(共有なしなら 1.5〜4.7 倍)。現段階(6 モジュール、20〜49%)では**不要**。推奨: G9 に着手する前に、共有 import か動的リンクの設計調査(M-8)を先に行う。判断材料は「プラグインのコードの 89〜99% が既存 3 モジュールと共有できるか」(データ(アドレス)の扱いが未検討)。
4. **配信形式。** brotli を前提にする(gzip は wasm 単体で 2.4〜2.7 倍の転送量)。2 回目の起動の保存は Cache API(gzip のバイト+`DecompressionStream`)を使う案があるが、総時間への効果は小さい(転送の節約が主)。標準の HTTP キャッシュに頼らない(6 MB 超は効かない)。推奨: 配信設計は G4/G5 の UI の形が決まってから。
5. **計測用フック付きビルド(A 相当)を残すか。** 入口数が要る診断(0128 の 2 入口差の追跡、census)には必要。推奨: `HOOKS=1` を既定のままにして残し、本番相当のビルドは `HOOKS=0 GEN_OPT=O2` として分ける(今回の変数のとおり)。
6. **最適化版の正しさの基準。** 面の SHA だけでは未定義動作の露出を検出できない。推奨: 最適化版と -O0 版を、スレッド表・窓表・面の SHA に加えて、**G3 以降の経路(入力後の再描画)が通るようになったときも**毎回突き合わせる。入口数は -O0+フックでだけ取る。
7. **ビルドの並列度と RAM の枠。** -O1/-O2 を 1 時間以内に作るには JOBS=2(RAM 5.4 GB)が上限。CI を別機にするなら JOBS を上げられる(未測定)。推奨: 枠を維持するなら現状のまま(59 分)。
8. **o1 段の遅さ**(B の 49 分、最大の関数の -O1 が 540 s)。-O1 以上を基準にするなら o1 段は要らない。-O0 を基準にするなら調査が要る(原因は未調査)。
