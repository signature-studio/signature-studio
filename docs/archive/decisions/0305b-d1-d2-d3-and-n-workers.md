### 1.1 D1 = (b)『実行時の判断で協調を残す。判断は ホストが返す論理 CPU 数の事実に限り、旗・環境変数は作らない』

**判断の入力**: `navigator.hardwareConcurrency` を **host import**(環境変数でなく、`EM_JS` の関数で wasm が呼ぶ。`fle_real_epoch_ms` と同じ形)で受け取り、(i) `GetSystemInfo` の `dwNumberOfProcessors`/`dwActiveProcessorMask` と `GetLogicalProcessorInformation` の RelationProcessorCore の記録数 n に返す、(ii) Worker 数 N を決める。(i) は **Win32 の契約の実装**(Learn: 論理プロセッサの数)で、0034 と 0234n §4 が設計済み、`fle_sysinfo.c` は n 個の記録を返す形に既になっている(足場、第 1 報の I3/I4)。FL はこの n から**自分で**補助ミキシングスレッドの数を決める(FL の挙動。我々は触らない)。= **入力は方針に適合**。

**出力(N = 1 のときの協調経路)を コードで確かめた事実**(読み):
- 協調と実スレッドの違いは Worker 数だけでなく**時計**: 協調は仮想時計(『1 つのプロセッサの仕事の時計』。`fle_sys.c` の virtual clock、`advance_to` で期限を即座に進める、page の IdleDriver が壁時計に pacing〔0170〕、0279 の課金 k=4)。実スレッドは `fle_sys_clock_real_enable()`(`wk_start(1)` で呼ばれる = **最初に Worker 1 を作った時点**)から**実時計**(`performance.timeOrigin + performance.now()`、期限は待って迎える)。= **仮想時計と実時計の切り替えが Worker 数と結びついている**(`rt_mode = nworkers_cfg >= 2`)。
- N = 1 の経路は『既存のコード』なので、**新しく足すコードは N を決める 1 か所**(`nworkers_cfg` の計算)だけ。この点は『新しい処理を足さない』に反しない。

**方針の 3 条件(契約の実装 / 余計なロジックの除去 / 変換・通信の削減)への当てはめ**:

| 要素 | 3 条件 | 判定 |
|---|---|---|
| n をホストの事実から返す(GetSystemInfo / GLPI) | (b) 契約の実装 | 適合 |
| ゲストスレッド → Worker の割り当て(min(スレッド数, N)) | CreateThread の契約は『スレッドが並行に走る』。1 スレッド 1 Worker が忠実で、N で頭打ち(資源の事実)は契約の近似 | 適合に近い(割り当ての方針は契約に無いが、忠実な方向) |
| **N = 1 のとき仮想時計 + pacing + 課金の協調モードに切り替える** | **どれにも当たらない**。Windows の契約に仮想時計は無く、ホストの事実で時計の種類を変えるのは我々の方針 | **独自の分岐(抵触の疑い)** |
| **2 つの時計・2 つの scheduler を製品が持ち続ける** | 『唯一の構成』の逆(経路が 2 本。第 1 報の D1 = b の注意) | 抵触 |

## 3. I15: Worker 数を『FL がホストの CPU 数から作るスレッド数に応じた N 本』に一般化する

### 3.1 なぜ必要か(PM の前提と既存の測定から)

- **読み(0234s、mt3 の実測)**: FL は n = 1 では補助ミキシングスレッドを作らず、n ≥ 2 で CreateSemaphoreW を呼んで補助スレッドを作る。Chrome の E 版(当時の足場)の実測: n = 1 のミキサー 42〜67% に対し、**n = 2: ミキサー 33〜36% + 補助 45〜48%、n = 4: ミキサー 28〜31% + 補助 16〜20% × 3**。= ミキシングの仕事は**補助スレッドに実際に分かれる**(ミキサーの critical path が 1/2〜1/3)。当時は『総 CPU が増えない』=同期の待ちに律速されていたため書き込み率が 0.33〜0.52 → 0.42〜0.66 にしか伸びなかったが、**GIL の護送の修正と lock-free の import(0234q)、E11 の速度の後の n ≥ 2 は未測定**。
- **PM の前提 (a)**: G9 の後は仕事が増え、単一のミキサー thread では足りない可能性が高い。**FL 自身の並列ミキシングが忠実な出口**(実機の FL は論理 CPU 数に応じた補助スレッドで回る)で、それには n > 1 を返し、補助スレッドに Worker を割り当てることが要る。
