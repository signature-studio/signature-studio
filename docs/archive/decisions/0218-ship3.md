## 1. 出荷用プリセット F2xH4(F1xH4)の定義

`app/scripts/build-engine-bundle.sh` に `SHIP_PRESET=F1xH4|F2xH4` を足した(opt-in。既存のプリセットの意味は変えていない。`F1xH3|F2xH3`〔anim1〕・`F1xH2|F2xH2`〔ship2〕・`F1xH|F2xH`・`F1x|F2x` は無変更)。中身は、各変数が未設定のときだけ入る既定として:

## 2. RT_OPT=O2 と RT_O2_EXTRA だけの構成の優劣(parity ゲートの node の CPU 秒)

比べた 2 つ(どちらも F2xH4 の他の部分は同じ、混成なし): **A** = `RT_O2_EXTRA=fle_raster fle_sse_more`(anim1 の F2xH3 のまま。wasm 128,043,642 B)、**B** = `RT_OPT=O2`(runtime 全体を -O2。wasm 128,069,323 B、+25,681 B、brotli +6,223 B)。ゲート `lift/harness/parity/run.sh` の node ドライバーは glue の MEMFS に書くので `NO_FS=1` の glue では動かない(`FS` が無い)。**同じオブジェクトを `NO_FS=0` でリンクし直した物**(wasm は node リンクの物とバイト単位で同一であることを A で確かめた)を A・B とも使い、セッション 9 本(ui-menu は §6 の壁で止まるので除く)、全 85 行、`wasm_main_cpu_ms`(主スレッドの CPU)を測った。**A B A B の交互で 2 組**(load 最大 4.6〜5.4)。先に順次で測った 1 組(A は load 最大 13、B は 7)は load が違うので採らない。
