## 1. 混成の作り方の現状(調査。コードを読んだ事実)

混成 = fe-wasmgen が x86-64 の関数を C を経由せず wasm に直接生成し、C 経由の wasm とつなぐ構成(決定 0157 の試作 → 0169・0179・0181・0185 の同一性 → 0189 ship1 の出荷候補 SHIPH → 0200・0208 ship2 → 0227 hyb5 の `--sse-int` で 977 → 1,009 関数)。

**HEAD 25e01e23(基準)での作り方**:
- `app/scripts/build-engine-bundle.sh` にも `ci/` にも**混成の段は無かった**。`ci/stage-wasm.sh` の `WASM_EXTRA_STAGES`(「混成の段などはここ」とコメントされた空の変数)は一度も使われていない。ship3(決定 0218 §3)も『混成の手順は ship2・parity1 の作業ディレクトリに依存し再現していない』と書いている。
- 混成の手順は `docs/investigations/{ship1,ship2,parity1,hyb5}/tools/hyb.sh`(各担当が自分の作業ディレクトリの絶対パスを書き換えて複製した物)にあった: `prep`(C の単位から選択関数の本体を外す `strip_units2.py`、`hybrid_glue.c` をコンパイル)→ `n0`(ダミーのアドレスで fe-wasmgen を走らせ、直接部が呼ぶ C の関数 `c.*` を数えて `exports.rsp` にする)→ `weblink`(変わった単位だけ再コンパイルし、`--allow-undefined` と `exports.rsp` と `-Map` で C 部をリンク)→ `nodelink`(node 用の別リンク)→ `opt`(**node リンクの**wasm に wasm-opt -Oz)→ `gen`(リンクマップから `fle_teb`・`fle_mxcsr`・`fle_hyb_buf`・`fle_progress_count` のアドレスを読み、実アドレスで fe-wasmgen)→ `merge`(`wasm-merge` で直接部 6 本を 1 本に、次に C 部へ)→ `webprep`(glue から未定義関数の stub を削る `strip_glue_stubs.py`)。
