## 見つかったこと: 3 状態の 97〜99% は『見えないロゴ』の描画(実測)

- **誰が**: スレッド 2 が、仮想 **+24 ms**(最初の `timeGetTime` の 1 回目)から**毎ティック(16 ms)`f_7205c0` を呼ぶ**。`f_7205c0` はクラス `TLightweightLayeredControl`(レイヤード窓 lid 18、決定 0140)の描画メソッド(this = rcx)。同じ this(`0x78382593acc0`、ASLR で変わる)を全走行で使う。Enter の前(S1)にも同じ頻度(62.5 回/秒)で呼ばれ、**`UpdateLayeredWindowIndirect` は Enter の後にだけ**呼ばれる(62.5 回/秒)。
- **何を計算するか**: 1 ティックの流れは `f_6c1190`(`ippiWarpAffineQuad_8u_C4R`、1 ティック 155 ms)→ 枠(`f_6c7350`)→ `f_6c1260`(合成。中で `ippiWarpPerspectiveQuad_8u_C4R` = `f_344fcf0`)→ **`f_6c8d00(bitmap, rect, α)`(IPP MulC。全バイトに α を掛ける)**。α(xmm2)は v 0.8 から 44 s まで**常に 0.00198813**(`f_6c8d00` の入口で 64 回に 1 回記録。最初の 2 回、v 0.001 s は別の呼び元で 0.6667)。**ULW に渡る面(lid 18)は Enter の +3 s・+6 s の両方で非 0 バイト 0**(`FLE_G3_DUMP_DIR` で採取した 493,488 B・440,352 B の全バイトが 0)= 完全な透明。
- **α の式(読み、0x720ef4〜0x720f4e の定数を読んだ)**: 制御の種類 `[this+0xf0]` = 3 のとき、`α = 0.5 + (2/3)·(2.5^(1 − 2.5·t) − 1)`(t = `[this+0xe4]`、途中で float に丸める)、[0, 1] に切る(α ≥ 1 なら MulC を呼ばない)。**t = 1.0 のとき 0.5 + (2/3)(2.5^-1.5 − 1) = 0.001988 = 観測した 0.00198813 と一致**。つまり α が小さいのは『フェードアウトが終わった状態』(t = 1)。t < 0.156 なら不透明、t = 0.4 で 0.5。
- **制御の状態(実測、最初の描画から v 148 s まで変わらない)**: t = 1.0、`[this+0xe8]`(速度)= 0、`[this+0xec]` = 1.0、`[this+0xf0]`(種類)= 3、`[this+0xfc]`(走行中)= 0、`[this+0xb0]` = 0x100。Step(`f_7204b0`)は `[+0xfc]` が 0 だと何もしない(読み)。**フェードは動いていない**(『Step の呼び出しが 0 回』とは言えない: `f_7204b0` は隣の `f_720560` から**直接**呼ばれる(生成 C の行 702279。同じ 10 MB 単位に入っていれば私のリンク時の包みでは見えない。単位は未確認)ので、包みの計数 0 は『呼ばれない』の証拠にならない)。
- **状態遷移(gdb の実測 `logs/g3/G-states.gdb-trace.txt` + 読み)**: ロゴの制御は**エンジンの初期化(`CreateFruityInstance` → `f_13751e0` の中)の最中**に作られ、**そのすぐ後で隠される**。順序: (1) `f_722200` → `f_721bb0`(作成。this の `[+0x9c]` = 0)が `f_720460` = SetState(1) を呼ぶ → `[+0xe0]` = 1、**t = (float)1 = 1.0**、`[+0xe1]` = 0(= フェードインの予約: 次のティックで `f_720560` が `[e1] ≠ [e0]` を見て t を 1.0 → 0 へ動かす = α が上がって見える)。(2) 続いて同じ初期化の中で `f_11be0a0` → `f_13712e0` → `f_136d030`(『ロゴがあれば隠す』= `if (Logo) Logo.f_722800(False)` の 8 命令)→ **`f_722800(this, 0)`**(HideLogo。`[+0xec]` = 1.0、kind = 3、`f_720460` = SetState(0))。このとき `[+0x9c]` = 1 なので t は直接変わらず `[+0xe0]` = 0 になる。(3) **スレッド 2 の最初のティック(仮想 +24 ms)の時点で `[+0xe0]` = `[+0xe1]` = 0 = 『変化なし』**なので、`f_720560` は遷移を始めず、t = 1.0(α = 0.002)のまま、`OnDone` も呼ばれない。HideLogo は仮想 +7 ms、スレッド 2 の最初のティックは +24 ms。**初期化の約 30 秒(実時間)の間、仮想時計は +7 ms しか進まず(時計は読みと idle でしか進まない設計。決定 0017・0122)、スレッド 2 の 16 ms の期限が来ない**ので、実機のように(実時間が進んでフェードインが進んだ後に HideLogo が来る)順序にならない(読み。次節の what-if がこの読みを支持する)。

#### 『結果ビットまで同一でなければならないか』(読み)

- **面の SHA(統合した木の golden)**: f_351b5a0・f_33da8f0・f_27ad5f8・f_344fcf0 の出力は `MulC` → 合成を経て面になる。この 4 つは**ビットまで同一**でないと SHA が変わる。許容誤差(±1 LSB)は『画像が見た目で同じ』を別の道具(画素差の上限)で確かめる必要があり、既存の golden SHA の回帰が使えなくなる。ホストは IEEE(double/float の SSE2)なので、**命令の順序を保てば同一性は構成上取れる**(0143 の差分テストが `fle_mx_*` で示した道)。ゆえに**許容誤差は勧めない**。
- **音声ブロック**: 今のミキサーの出力はほぼ無音(peak 0、決定 0139)で、これらの関数は音声に触れない。将来の非ゼロの音声(G8c)では、FLEngine の浮動小数点の混合を HLE する場面が来る。float → PCM16 の丸めで ±1 LSB は聞こえないが、golden のブロック SHA を使うなら同じくビットまで同一が要る(未実装・未測定。この作業の範囲外)。
- **MXCSR の旗**: 実エンジンの MXCSR は PE が立ったまま・全例外マスク(0143 の測定)で、PE が立っている限り、HLE の中で PE を足し忘れても最終値は変わらない(0143 の S-fp1-sticky)。ただし他の旗(OE/UE/ZE/IE/DE)が出るはずの入力(ゼロ割り、オーバーフロー、非正規)は元の実装にフォールバックする条件を入れること。

0. **(HLE ではない)ロゴの制御の寿命を直す**。無改造の S1・S2 の 97〜99% を占める見えないロゴの描画が消え、S3 は実時間の 6〜28 倍(native)になる(what-if の実測)。必要なのは仮想時計の進め方と `PostThreadMessageW` の応答行(前節)。HLE の 4 本(約 5% のコストにして ×10、計算)よりずっと大きく、実装も小さい(と読む。未実装)。

## 限界(確認できなかったこと)

- **S3 は観測できなかった**(v 148 s まで)。止める契機は未確認。実機の Windows でロゴが止まるかは不明。
- **wasm・Chrome は測っていない**(規則)。wasm の倍率は 0143 の 1 対の比 2.7 を当てた計算で、状態が違う。
- **同時走行**: Y・X・L・P を 2〜3 本同時に走らせ、さらに NOFAST の単位ビルド(3 ジョブ)や他の担当の走行(ロードアベレージ 5〜12)と重なった。較正は 2.1〜2.7 ms で安定(外れ値 1 回)だが、窓の速度に±数% の揺れはある。最後の FAST 対 NOFAST の対(Z)は 2 本同時で、a4 の `JOBS=1` ビルドと重なった。**3 状態に使った実時間の合計(逐次換算)は 40 分を超える**(Y 5.8 + X 5.9 + L 18.3 + P 13.5 = 約 44 分。Y・X・L を同時に走らせて壁の経過は 18 分、P は Z と同時に 13 分 = 計 約 31 分)。
