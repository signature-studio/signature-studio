## 12. PM の判断点

1. **既定の入口を SHIP2(F2xH2)に切り替えるか**。切り替えの利点は実測: S1 を満たす唯一の構成、FILE の 32 回目の停止が消える、File>Open のページの箱が出る(依頼者が『ファイル選択画面が出ない』と報告)、Export が WAV を出す、転送量 −1.96 MB(−6.3%)。切り替えで利用者に見える変化: File>Open でページの箱が出る(ZIP は選べない)、Export が止まらない、Blend2D の OVERLAY 等が実 DLL に合う。切り替え後も Sampler の Envelope タブなど未実装 API の停止は残る。手順は `MERGE-NOTES.md`。
2. 退避は `fl-engine-ship2-F1xH2`(S1 は満たさない)と現行の `fl-engine-ship1-SHIPH`。M の abort の stop note は `?bundle=<F1xH>` と案内するので、PM が note の文面を `fl-engine-ship2-F1xH2` に直すか決める(S-ship2-stopnote)。
3. size2(決定 0197)の brotli の数字(9.64 MB など)は過小。`brsize.mjs` は修正版を `docs/investigations/ship2/tools/brsize.mjs` に置いた(size2 の物は変更していない)。S1(生の大きさ)の判断は変わらない。
4. 混成は brotli を +392,728 B(+3.6%)増やす(転送量の実測は §7)が、Worker の CPU −30%(ship1 の測定)と引き換えなので、混成込みを推す。混成なし F2xH2(wasm 130,225,915 B、brotli 10,946,486 B)は S1 の側の保険として残る(bundle は作っていない)。
5. `shell32!DragAcceptFiles`(Sampler の Envelope タブ)は crash1(決定 0209)へ。runtime に行・関数を足す変更は fe-lift/runtime の変更で、SHIP2 の再ビルドが要る。
6. `ia2-imports.txt` に exp1 の 6 行が欠けている(`ship2-imports.txt` を以後の出荷用の rows にする)。
