## 文脈

- 対象は `docs/investigations/remaining-unsupported.md` §5.1 の A6（LoadLibraryA、LoadLibraryW、LoadLibraryExW、FreeLibrary、SetDllDirectoryW。5 API・7 thunk）と A12（ImageNtHeader。1 API・1 thunk）。同節の一覧が対象で、GetModuleFileNameW は決定 0018 で実装済み（`fle_vfs.c`）。
- 仮想モジュール表は決定 0015（PM の決定）。N = 1〜25 の名前と `0x7FF800000000 + 0x10000 × N` のハンドル。遅延 import だけの 9 DLL（dwmapi、imm32、msimg32、propsys、rpcrt4、shcore、uxtheme、windowscodecs、wtsapi32）は表に入れず、GetModuleHandleW が 126 を返す。
- 決定 0010 は「符号拡張、IDIV、1 オペランドの IMUL」で、外部モジュールを扱う文書ではない。依頼文の「ADR-0010」「external-modules.md 相当」に当たる文書はリポジトリに見つからなかった（`docs/` を `ADR-0010`、`M2`、`external-modules`、`外部モジュール` で grep。`import-GetCurrentThreadId.md` が「ADR-0010 が採らないとする『名前付き既定値』」と書いているだけで、本文は無い）。したがって「外部モジュールは M2 の対象で、仕様が確認された応答だけを返し、未知は fail-closed」は依頼文の指示として扱った。

## 判断

### 1. ロードの結果の 3 区分（LoadLibraryW/A/ExW）

1. 決定 0015 の表（PE の import 表の 24 DLL と ntdll.dll）にある名前: 仮想ハンドルと参照 +1。
2. 決定 0015 が「ロードされていない」とした 9 DLL（上記の遅延 import だけの DLL）: NULL と ERROR_MOD_NOT_FOUND（126）。ページは失敗時に NULL を返すと言い、コードは名指ししない。126 は System Error Codes ページの値で、「どのエラーが付くか」は決定 0015 の PM 判断と同じ。この名前表は `fle_load.c` の `fle_load_absent[]`（9 行）。**9 行はこの決定の範囲で追加も削除もしない**。
3. それ以外のすべて: `fle_stop`（`fle: LoadLibraryW: module "<名前>" is not a virtual module ...` で abort）。名前付き既定値では完走させない。

### 2. 外部モジュールと、決定が名指ししない Windows DLL は止める

LoadLibrary 系の呼び出し 46 か所（LoadLibraryW 44、LoadLibraryA 1、LoadLibraryExW 1）の第 1 引数を、逆アセンブル（`lift/objdump-text.txt`）と DLL のバイト列から実測した（`lift/out-a6/work/callsites2.py`、結果 `callsites.tsv`。呼び出しの直前 14 命令以内の `lea rcx,[rip+X]` を文字列として読んだ）。結果:

| 第 1 引数 | か所 | 扱い |
|---|---|---|
| `SHFolder.dll`（リテラル） | 21 | 表にある。仮想ハンドル |
| `kernel32.dll` / `KERNEL32.dll` | 2 | 表にある |
| `shell32.dll` 2、`Shell32` 1 | 3 | 表にある |
| `User32.dll`、`wininet.dll`、`advapi32`（拡張子なし） | 各 1 | 表にある |
| `dwmapi`（拡張子なし）、`SHCore.dll` | 各 1 | 遅延 import だけの 9 DLL。NULL + 126 |
| `avrt`、`PowrProf.dll`、`PSAPI.dll`、`RICHED20.DLL`、`URLMON.DLL`、`WebView2Loader.dll` | 各 1 | 表にも 9 DLL にもない。**止める** |
| 直前でリテラルを読み込まない（動的） | 9（LoadLibraryW 7、LoadLibraryA 1、LoadLibraryExW 1） | 実行時の値で決まる。表と 9 DLL にあればその扱い、なければ**止める** |

行の合計は 21 + 2 + 3 + 3 + 2 + 6 + 9 = 46 で、呼び出し 46 か所と一致する。

動的な 9 か所の引数の中身は、この作業では確定していない（直前の `mov rcx,rax` は `f_414850` などの関数の戻り値）。そのうち 3 か所（0xca1008、0xcad9c4、0x11336a4）の近くに `declipper.dll`、`stemextract.dll`、`beat_tracker.dll` の文字列があるが、これらが LoadLibraryW に渡るかは**推測**で、確認していない。依頼文が例に挙げた `dsp_ippv2.dll`（文字列は `.rdata` 0x2566dc にある）、`ILTools_x64.dll`（DLL には `ILTools` と `_x64.dll` が別々の文字列としてあり、`ILTools_x64.dll` という 1 つの文字列は見つからなかった。組み立てる形と**推測**）の呼び出し位置も特定していない。

全文字列の走査（`ext_modules.py`、結果 `ext_runs.tsv`。`.dll` `.drv` `.ocx` で終わる ASCII と UTF-16 の文字列を DLL 全体から 164 行）には、表の 25 名のほかに、外部 DLL の名前として `dsp_ippv2.dll`、`WavpackDLL_x64.dll`、`stemextract.dll`、`declipper.dll`、`beat_tracker.dll`、`ss2wav.dll`、`ds2wav.dll`、`oggio.dll`、`LAMEEnc.dll`、`QuickFontCache(_x64).dll`、`REX Shared Library_x64.dll`、`Speaker_x64.dll`、`ilvideo_x64.dll`、`LicenceEngine.dll`、`CloudMastering.dll`、`AudioRestore.dll`、`Blend2D.dll`、`DelZip64.dll`、`IdnDL.dll`、`ILRemoteServer.dll`、`FL Studio VSTi.dll` などがあり、Windows の DLL として `iphlpapi.dll`、`ws2_32.dll`、`mswsock.dll`、`Fwpuclnt.dll`、`Wship6.dll`、`Msctf.dll`、`Normaliz.dll`、`PSAPI.dll`、`PowrProf.dll` などがある。

最終的な扱い（コード `fle_load.c` と一致する。表は 1 か所で、行の数をテストで固定していない）:

| 名前 | 扱い |
|---|---|
| 決定 0015 の表の 25 名 | 仮想ハンドル、参照 +1 |
| dwmapi、imm32、msimg32、propsys、rpcrt4、shcore、uxtheme、windowscodecs、wtsapi32（決定 0015 が「ロードされていない」とした 9 DLL） | NULL + 126 |

外部 DLL（プラグインと道具）への応答は M2 の判断で、この決定では作らない。`avrt`、`powrprof`、`psapi`、`riched20`、`urlmon` に「存在しない」（126）を返す案は、これらの呼び出しの先へ実行を進められるが、決定 0015 が名指しした 9 DLL の範囲を越え、環境についての主張を新しく作ることになるので採らなかった。足す場合は `fle_load_absent[]` に 1 行ずつ足す（PM の決定が先）。

注記（決定 0088、仮の決定）: このうち `avrt` と `powrprof` は、PM の決定により、`fle_load_absent[]` ではなく仮想モジュール表の末尾（N = 31、32。`LoadLibraryW` は成功し、`GetProcAddress` は NULL と 127）に足された。`avrt`、`powrprof` は `fle_load_absent[]` の 9 名に入っていなかったので、absent の名簿（9 行）は変わらない。`psapi`、`riched20`、`urlmon` は 0088 でも決めていない（名前付き停止のまま）。決定 0015/0029 と 0055 の基準の違いは解消していない（0088 の「範囲外」）。この段落の本文は書き換えていない。

### 3. 参照カウント

ページ（FreeLibrary）: 起動時にロードされたモジュールは参照 1。LoadLibrary が増やし、FreeLibrary が減らす。仮想プロセスは表の 25 名を起動時にロード済みとして参照 1 から始める。FreeLibrary で 0 になる呼び出し（ページは「アンロードする」）は、仮想モジュールのアンロードをモデル化していないので止める。GetModuleHandleW で得たハンドルを渡すと早すぎるアンロードになる、とページが警告する形と同じ。

### 4. FreeLibrary と SetDllDirectoryW の未定義入力は止める

- FreeLibrary: NULL、リフトした DLL 自身（0x400000）、表のハンドルでない値。ページは失敗時に 0 と言うが、どの入力が失敗するか、エラー値は書いていない。
- LoadLibrary: NULL ポインタ、空文字列、パスを含む名前（`\`、`/`、`:`。ページは「完全パスはそのパスだけを探す」と言うが、仮想ファイルシステムに DLL ファイルがないときのエラーは書いていない）、256 文字超の名前、`.dll.dll` のような表にない名前（区分 3 に落ちて止まる）。
- SetDllDirectoryW: 32,767 文字を超えるパスは止める（**仮定**: Unicode 形式のパスの上限。ページに上限はない）。

### 5. ImageNtHeader の NULL 返却は作らない

ページは「失敗時は NULL」と言うが、失敗する入力を挙げない。ランタイムは、読めるイメージと任意のポインタを区別できない（ゲストのメモリはホストのメモリ）。Base が 0x400000 以外のときに NULL を返すと、ランタイムが作った値で実行が進む。ゲストの 2 つの呼び出し（0x63b714、0x63bb02）は、直前の呼び出し 0x423a10 の結果を渡す（0x423a10 は `jmp [0x1971410]` で、`out-imports/imports.txt` の 0x1971410 は kernel32!MapViewOfFile。実測）。ImageNtHeader の結果が NULL なら別の分岐（後始末の呼び出し 0x423cb0 など）へ進む（逆アセンブルを読んだ範囲。分岐の意味は**推測**）。MapViewOfFile は別の担当（A13）が `imports_table.rs` に行を追加している最中で（この決定を書いた時点で作業ツリーに行がある。実装の中身は読んでいない）、MapViewOfFile がどんなアドレスを返し、それが 0x400000 になるかは、この作業では確認していない。0x400000 以外の Base に対して NULL を返す値は、公式ページが定めず、ゲストの分岐を実測で裏付けられないので作らず、止める。MapViewOfFile の結果が渡る経路が実際に動いたとき、この判断を見直す（その時点で止まる Base の値が分かる）。

0x400000 のイメージのヘッダは検査してから返す（MZ、e_lfanew が 0x40 から 0xFFF、`PE\0\0`）。範囲は DOS ヘッダの大きさと、ハーネスがヘッダを最初の 4 KiB に置くことから決めた（決定。PE 仕様の値ではない）。

## ホストを見せない

どの API もホストの DLL を開かず、ホストのファイルシステム、環境、プロセスを読まない。モジュールは名前と固定値で、ハンドルは実メモリの住所ではない（決定 0015 の限界のとおり、ゲストがハンドルからヘッダを読むと SIGSEGV）。

## 限界

- LoadLibrary 系が 0x400000 のハンドルを返す名前はない（GetModuleHandleW(NULL) だけ）。
- 呼び出しの引数の実測は第 1 引数が直前でリテラルとして読み込まれる形だけ（上記の表）。動的な 9 か所の引数の中身と、外部 DLL の名前が LoadLibrary のどの呼び出しに渡るかは、この作業では確定していない。
- 公式ページが定める DllMain の呼び出し、依存 DLL の読み込み、検索順序は仮想モジュールにはない。
- Windows 本体との照合はしていない（ホストは Linux）。
- ホストの `GetLastError` の扱いは決定 0004 のとおり（`fle_set_last_error` の値を `GetLastError` が返す）。
