## 7. E11 の効きの大きさ(訂正つき。PM の依頼『mt3 の見込み CPU −4〜7.5% より大きく効いた理由の仮説』)

- **訂正(14:41 の info の読みの取り下げ)**: 14:41 に『E11 は見込みより大きく効いた(ミキサー −18%、率 +26%)』と書いたが、これは**プロファイル付き run 同士**(E10 は 2 ms のプロファイラ + 開始 load 10.45 で 0.704 に押し下げられていた)の比較に依っていた。**plain の交互 A/B(§6、2 往復)では、CPU / 音声 1 秒は 1.057 → 1.002 s(−5.2%)で mt3 の見込みの内、書き込み率の差は +0.047 ± 0.072 で区別できない**。= **『見込みより大きい』という結論は plain の測定では支持されない**。
- **実測(確かなもの)**: (i) dispatch + 小 adapter の自己時間(プロファイル、同じ道具・同じ窓)は 6.305 → 0.669 ms/ブロック(−89%)で、ミキサーの 1 ブロック(92.88 ms の音声)あたり **−5.6 ms**。(ii) 5.6 ms は plain の A/B の CPU −5.2%(音声 1 秒あたり 約 55 ms = 1 ブロック約 5.1 ms)とほぼ同じ大きさ = **dispatch + 小 adapter の減りが、plain で見える CPU の減りをほぼ説明する**。(iii) 仮想時計の課金は変わらない(node 行 0 行差)ので、効きは実 CPU 側だけ。
- **読み**: E9 以降エンジンが CPU 側(仮想時計が壁の約 0.5〜0.7 倍)にいるため、実 CPU の −5% は仮想時計の速さ(0.60 → 0.65、+8%)に出る方向だが、書き込み率は run 間の揺れ(±0.1)に埋もれる。5 分再生の 0.97 は、静かな窓(開始 load 3.4)の 1 本で、**同じ静かな窓の E10 の 5 分データが無いので、E11 の効きの証拠にしない**(E10 の plain の 60 s は 0.82、E11 の plain の 60 s は 0.80〜0.93)。プロファイル run の `m` −18% は、プロファイル条件の揺れを含む参考値。
