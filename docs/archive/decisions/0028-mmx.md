## 仕様の出典

- Intel SDM（Order Number 325462-093US、結合版の公式 PDF）。取得: `https://cdrdv2.intel.com/v1/dl/getContent/671200` が `https://cdrdv2-public.intel.com/929349/325462-093-sdm-vol-1-2abcd-3abcd-4.pdf` に 301（`curl -L`、26,664,929 バイト）。`pdftotext -layout` で `lift/out-mmx/spec/sdm-full.txt`。Vol. 2 は決定 0023 で取得済みの `lift/out-int2/spec/sdm-vol2.txt`（325383-093US）も読んだ（命令の擬似コードは同じ内容）。
- 各命令の「With 64-bit Operands」の擬似コード（Vol. 2: EMMS、MOVD/MOVQ、PADDW、PSUBSB/PSUBSW、PMULHW、PMULHUW、PACKUSWB、PUNPCKLBW、PSHUFW、PSLLW）。
- x87 との関係: Vol. 1 第 9 章（9.5、9.6.2、9.6.3、9.6.8）、Vol. 3A 第 15 章（15.2 の Figure 15-1、Table 15-2、15.2.1 の Table 15-3）、Vol. 3B 25.25.3（Table 25-7、メモリ参照のある MMX 命令の例外）。

## 判断

1. **レジスタ状態: 独立の `uint64_t MM[8]`**（`ST0-7` とはエイリアスしない）。
   - 理由: x87 の演算命令を lift していないので、`ST` の 80 ビットの内容を持つ表現が runtime に存在しない（`fle_x87` は `cw`、`sw`、`tw` だけ。決定 0019）。MMX の値を 80 ビットの `ST` に載せる先がない。
   - モデル化しないもの: Vol. 3A 15.2 の「MMX レジスタへの書き込みで、対応する浮動小数点レジスタのビット 64-79 が全 1 になる」こと、`ST(i)` との値の共有（x87 演算がないので観測できない）。物理レジスタ番号と TOP のずれ（TOP は MMX 命令ごとに 0 になる。下の 2）。
   - `MM[8]` は `fle_mmx.h` で `__attribute__((weak))` の定義にした。生成 C（`fle_sse.h` を include）にも、`fle_sse.h` を include する runtime の `.c` にも、テストの C にも、個別の定義を足さずに済む（リンクで 1 つに統合される）。`lib.rs` の生成ヘッダ文字列は変えていない。
2. **x87 状態への作用は、`fle_x87`（`fle_x87ctl.h`、決定 0019）の `sw` の TOP と `tw` に限ってモデル化する。**
   - MMX 命令（EMMS 以外、読み出しだけの命令も含む）: `sw` のビット 11-13（TOP）を 0 に、`tw = 0x0000`（全 tag が valid、00B）。根拠: Vol. 1 9.6.2「The TOS value of the x87 FPU status word is set to 0. The entire x87 FPU tag word is set to the valid state」、Vol. 3A Table 15-2（読み出しも書き込みも「All tags set to 00B、000B」）。
   - EMMS: TOP を 0、`tw = 0xFFFF`。擬似コードは `x87FPUTagWord := FFFFH`。TOP を 0 にするのは Vol. 3A Table 15-2（EMMS の行は 000B）で、ホストでも実測した（下）。
   - `sw` のほかのビット（例外フラグ、C0-C3、B）、`cw` は変えない（Vol. 3A 15.2「Execution of MMX instructions does not affect the other bits in the x87 FPU status word … or … control word」）。
   - `tw` の意味: 既存のモデルは「FNINIT で FFFFH」。MMX 命令の後の `0x0000` は SDM の表（Table 15-3）の「All tags are set to 00B (valid)」をそのまま持つ。x87 の FNSTENV が書くタグ語の像は、各レジスタの内容から tag（valid/zero/special）を再計算した値になる（ホストの実測: MMX 命令の後の FNSTENV のタグ語は 0x5555、0x5559、0x5569。`work/probe_x87-out.txt`）。FNSTENV は lift していないので、この差は観測されない。
3. **メモリオペランドは 64 ビット（PUNPCKLBW は 32 ビット）、アラインメント要件なし。** Vol. 3B Table 25-7 は #GP を「非正規アドレス」だけ、#AC を「アラインメントチェックが有効で CPL 3」だけにしている（16 バイト境界の #GP は xmm 形のクラスの規定で、mm 形にはない）。ホストの実測: `movq mm3,[p]`、`paddw mm3,[p]` は p が 8 の倍数でなくても fault しない（`probe_x87-out.txt` のオフセット 1、3、5、7、9）。`fle_ld`/`fle_st`（`memcpy`）を使う。PUNPCKLBW の `mm, mm/m32` は 4 バイトを読んで 0 拡張する（SDM の命令の表。ソースの上位 32 ビットは使わない）。
4. **フラグ**: 変えない（Flags Affected: None）。
5. **SDM の擬似コードにない事項**: #MF（保留中の x87 例外）、CR0.EM/TS の #UD/#NM はモデルを持たない（決定 0019 のモデルに保留例外がない）。
6. **PSLLW のカウント**: mm または m64 のカウントは 64 ビット全体（`COUNT > 15` で結果は 0。上位ビットが立っていても同じ）。imm8 は 8 ビット。
7. 4 バイトの MOVD で GPR に書く場合は 64 ビットに 0 拡張（`R[n] = (uint32_t)MM[s]`）、mm に書く場合は 64 ビットに 0 拡張。GPR が 8/16 ビットの形、AH など上位バイトのレジスタは `Err`（fail-closed）。FS/GS セグメントと 32 ビットアドレスも `Err`（他の SSE モジュールと同じ）。

## x87 演算との混在（静的に確認したこと）

`MM` を ST と別にしているので、MMX の後に x87 演算が MMX の値を読む、あるいは x87 演算の後に MMX が ST の値を使う、という混在があると、このモデルは SDM と食い違う。閉包（896 seed）での確認:

- 生成 C の x87 命令は **制御系の 10 件だけ**（Fldcw 4、Fnclex 2、Fnstcw 2、Fnstsw 1、Fninit 1。`/* VA F... */` のコメントの集計）。x87 の演算（Fld、Fadd、Fmul、Fistp など）、Fnstenv、Fnsave、Fldenv、Frstor、Fxsave、Fxrstor は閉包に **0 件**。
- したがって、この閉包の範囲では「MMX の値を x87 が読む」ことは起きず、モデル化しなくても結果に差が出ない。EMMS は閉包の 3 件とも `ret` の直前（`0x63a668` は `fnclex; fldcw; emms; ret` の関数、`0x660c6e`、`0x6a7a55`）。
- **確認できていないこと（仮定）**: `.text` 全体には x87 演算が多数ある（`objdump-text.txt` の mnemonic 別の件数: fld 887、fadd 804、fmul 767、fistp 608 など、fnstenv 19、fnsave 17、fldenv 24）。閉包の外のコードや、今後 seed を増やして閉包に入るコードが MMX と x87 を混在させるかは、この作業では確認していない。入った場合に x87 演算は `fle_unsupported` で止まる（黙って近似しない）ので、不整合な結果を出すのではなく停止する。MMX 命令を含む 3 関数の呼び出し元が x87 を使うかも調べていない（推測: 小さな補間のルーチンで、呼び出し元の x87 利用は不明）。

## 実装しなかったもの（fail-closed）

- 上記以外の MMX 命令（未対応のまま、`lift_insn` が `Err("mnemonic outside minimal set")`）。
- xmm 形、VEX/EVEX 形（`mmx::lift` は mm レジスタを含まない命令に `None` を返す。EMMS だけが mm オペランドを持たない例外）。
- 確認できず実装しなかった命令: **なし**（実装した 12 mnemonic は SDM の擬似コードを読み、ホスト突合で一致した）。

## テスト（ホスト突合）

`cargo test --offline -p fe-lift --test mmx`: 14 件（突合 12 + ケース集合の範囲確認 1 + 他の MMX 形が未対応のまま 1）すべて通過。ログ `lift/out-mmx/test-mmx-3.txt`、最終は `test-mmx-final.txt`。

方式は `tests/sse_int2.rs` と同じ（ホストは実機械語を mmap して実行、C は `lift_body` の本文を clang -O0 でコンパイル。MMX 命令は intrinsics ではなく命令バイト列を直接エンコード）。`fle_x87ctl.c` を一緒にリンク。比較する状態: mm0-7、rax、rcx、rdx、rbx、rsi、r8、r9、r10、メモリ 64 バイト、**命令の後の x87 ステータスワード（TOP 込み）、命令の後の「空の tag」の集合、続けて EMMS を実行した後のステータスワードと空の tag の集合**。

- ホスト側は、命令の前に FDECSTP を 0〜7 回実行して TOP を動かし、半数のケースでは EMMS で tag を空にしておく。C 側の初期状態は、ホストが命令の直前に報告したステータスワード（FNSTSW）と、同じ tag の状態から始める。
- 比較は「tag が空か」（FNSTENV のタグ語が 11B か）だけにした。valid のときの 00/01/10 の区別（上の判断 2）は FNSTENV の再計算の値で、モデルの `tw` とは別物のため。
- ホストのスタブは必ず最後に EMMS を実行する（ホストの x87 状態を元に戻す）。
- ケース: 二項（PXOR、PADDW、PSUBSW、PMULHW、PMULHUW、PACKUSWB、PUNPCKLBW）はランダム 300 ラウンド × （レジスタ形 + メモリ形、メモリのオフセットは -16〜40 の 10 通りで大半が非整列）+ 辺の値の全組合せ（8 ビット 13² = 169、16 ビット 21² = 441）。ラウンド 7 回に 1 回は `d == s`。PSLLW はカウント 47 通り（0、幅の前後、63/64/65、`0x1_0000_0000`、`u64::MAX`、上位ビットが立つ値、乱数）× 3 回 × （mm カウント、m64 カウント）+ imm8 の 256 通り全部。PSHUFW は imm8 の 256 通り全部 × （レジスタ形、メモリ形）。MOVD、MOVQ は GPR（r8-r10 を含む）、メモリ、mm 間の全形。EMMS は TOP 8 通り × tag 2 通り。
- ケース数: 合計 **10,081**、失敗 0（二項 769〜1,041、PSLLW 538、PSHUFW 512、MOVD 800、MOVQ 1,200、EMMS 16）。ホストが状態を変えたケースは、全命令で 80% 以上（`host_changed_state`。EMMS は 16 件中 15、PXOR は 1,041 件中 1,039、MOVQ は 1,200 件中 1,197、他は全件）。
- 検査の感度の確認（変異）: `fle_mmx_touch` から TOP のリセットを外す（`test-mmx-mutation-top.txt`）と 11 件が失敗、tag のリセットを外す（`test-mmx-mutation-tag.txt`）と 11 件が失敗した（どちらも通常は 14 件通過）。両方とも元に戻して再実行し、14 件通過（`test-mmx-final.txt`）。
- 既存テストの編集: `tests/sse_int2.rs` の `mmx_and_vex_forms_stay_unsupported` は、`psllw mm0, mm1` と `pshufw mm0, mm1, 0x1b` を「未対応のまま」の例にしていた。この 2 命令が今回対応したため、同じ目的の `psrlw mm0, mm1`（`0F D1`）と `psraw mm0, mm1`（`0F E1`）に差し替えた（+2/-2 行）。

## 確認できていないこと

- Intel の CPU での挙動（ホストは AMD Ryzen 9 9950X。SDM の擬似コードと一致したことは確認）。
- 閉包の外での MMX と x87 の混在（上の節）。
- 実行経路で MMX の関数が実際に実行されるか（`docs/investigations/mmx-run.md` §5）。
- Vol. 3A 15.2 の「ビット 64-79 が全 1」の影響（x87 演算が lift されるまで観測できない。そのときは `MM` と `ST` の関係を再設計する必要がある）。
