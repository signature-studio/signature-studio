# pdata 関数 entry 852 件の、データ中の参照

対象: `binaries/win64/FLEngine_x64.dll`（読み取りのみ）。
分析ツール: `lift/out-ref/`（新規。既存の `lift/crates/` を path 依存で読むだけ。既存のコードは変更していない）。
出力: `lift/out-ref/out/ref-852-*.r1`（新規。`create_new` で作成し、上書きはしていない）。

「実測」は分析ツールの出力か、読んだ逆アセンブル・ファイルの内容。「推測」は未検証の解釈。

## 0. 母集団と前提（実測）

- 852 件は `lift/out-seed/out/seeds-pdata-852.txt`（既存）の値をそのまま使った。852 行、重複なし。
- 852 件はすべて `.text` 内、かつ pdata の関数 begin と一致（実測）。
- 852 件はどれも既存閉包（`fe_decode::analyze`、6,969 関数）の関数 entry ではない（実測。`seeds_in_closure 0`）。
- 852 件の選び方は「`.text` 以外の DIR64 再配置の値で `.text` を指し、pdata の begin と一致する」。**このため、852 件は定義上すべて何らかの非 `.text` の 8 バイト値から指されている。** 下記 1 の「参照あり 852」は、この選び方の帰結であり、独立な発見ではない（推測ではなく、母集団の定義からの計算）。

分析ツールは、`.text` の命令のうち、RIP 相対のメモリ参照または即値の絶対アドレスで、表の範囲（run の先頭から長さ分）に当たるものを数えた。

| 項目 | 件数 |
|---|---|

| うち閉包の中（命令が閉包の関数に入っている） | **15** |
| うち閉包の外 | **53** |
| 命令の種類（閉包の中） | `lea` 6、`call [rip]` 8、`mov` 1 |
| 命令の種類（閉包の外） | `lea` 39、`call [rip]` 7、`mov` 7 |

閉包内の読み手（15 件）:
- `0x41d95a` `lea r9,[rip+...]` → `0x13a9410`（0x41d050 の表）。関数 `0x41d8f0`（閉包内）。
- `0x4093ca`、`0x40941e`、`0x40944e`、`0x409487`、`0x4094a1`、`0x4094c5`: `call [rip+...]`（閉包内の関数 `0x4093c0`、`0x409410`、`0x409440`、`0x409470`）。読まれる値は `0x4083b0`、`0x407a50`、`0x407e20`、`0x408040`（いずれも seed の 852 件に無い、閉包内の関数）。

- `0x478aed`、`0x478b6d`、`0x67d4ad`、`0x86b9fe`、`0xa99d2d`: `lea` 等（閉包内）。

閉包の外の読み手（53 件）は、すべて閉包の外の pdata 関数の中にある（実測。`fn_in_closure 0`）。

**限界（実測。重要）:**
- 間接参照で表の要素を読む命令（例: `0x41223e` の `call [rbx+rsi*8]`）は、RIP 相対ではないため **上の集計には入っていない**。0x41d050 の値は、この間接参照で読まれる（`docs/investigations/dispatch-miss-0x41d050.md` による）。
- 表の基底を、別の命令（`mov reg,[rip+X]` で `.data` 内の基底ポインタを読む等）で作る経路も、今の集計には入っていない。
- そのため、(3) の 68 件は「RIP 相対で直接指す読み手」の下限であり、表の全ての読み手の数ではない。

## 4. 参照のない件数

- 852 件のうち、データ中に参照がない: **0 件**（実測。全 852 件に参照がある）。
- 参照がない件数が 0 なのは、母集団の定義からの帰結（§0）。「どこからも指されない関数が 0 件」という意味ではない。

## 5. 結論の分類（(a)(b)(c)）

依頼の (a) (b) (c) を、下記の定義で数えた。

- (a) 表から参照され、かつ表を読む命令が閉包の中にある
- (b) 表から参照されるが、読む命令が閉包の外にある
- (c) どこからも参照されない

| 分類 | 件数 | 区分 |
|---|---|---|
| (a) 閉包内の読み手あり（閉包外の読み手は無い） | **29** | 実測（RIP 相対の読み手のみで判定） |
| (a+b) 閉包内と閉包外の両方の読み手がある | **17** | 実測（同上） |
| (b) 閉包外の読み手のみ | **87** | 実測（同上） |
| (d) データから参照はあるが、RIP 相対の読み手が見つからない | **719** | 実測（分類の名前は (c) ではない） |
| (c) どこからも参照されない | **0** | 実測（データ参照は全件にある） |

- 合計: 29 + 17 + 87 + 719 = 852（実測）。
- **(d) の 719 件は (c) ではない。** データから参照はあるが、RIP 相対の読み手が見つからなかった、という意味。間接参照の読み手（§3 の限界）が見つかれば、(a) か (b) に移る可能性がある（推測）。
- (a)(b) の件数は、RIP 相対の読み手だけで判定した下限。間接参照を加えると、(a) と (b) の件数は増える可能性がある（推測。未計測）。
- 分類 (a) と (b) の数字は「表の読み手の下限」の数字。**これは閉包を広げる根拠の強さの代理にはならない**（推測）。

## 6. 推測（未検証）

- `d` の 719 件は、間接参照（`call/jmp [base+idx*8]`、基底は `.data` から読む等）で読まれる表の要素である可能性が高い（推測）。0x41d050 の表（run 4）と同じ形。
- 閉包を広げても意味がないという予想は、(c) が 0 件のため当てはまらない（推測。`d` の 719 件は依然として読まれうる）。
- 「参照がない件数が閉包の拡大を無意味にする」という根拠は、今回の集計では得られなかった。
