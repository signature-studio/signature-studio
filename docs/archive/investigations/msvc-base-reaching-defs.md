## 2. 到達定義による site ごとの分類

### 2.1 規則の記号（読み。この調査の用語。決定ではない）

「有効」な site（N が導け、表の全エントリが関数内の命令の先頭）43 件（Blend2D 38、dsp_ippv2 5）について、基底レジスタ B の到達定義を、関数（`.pdata` の RUNTIME_FUNCTION＋連鎖の全ピース）の CFG（iced-x86 の線形走査。直接分岐、fall-through、call は fall-through。ret／int3／ud2 は終端）で求めた。定義 = B を書く命令（iced が報告する明示・暗黙の書き込み。`push B` は書き込みでない。`pop B` はこの解析では**定義として数える**（0090 の `prove_base` は `push B` があれば数えない）。関数の入口（呼び元の値）。B が揮発（rax rcx rdx r8〜r11）なら**すべての call**（呼び先が B を書きうる）。「lea のみ」= jmp に届く定義がすべて `lea B,[ImageBase]`。

| 記号 | 規則 | 他の間接 jmp の扱い |
|---|---|---|
| R0 | **現行（決定 0090）**: 書き込みがちょうど 1 回で `lea ImageBase`、揮発 B と関数内 call があれば拒否、`lea` が jmp を支配 | 1 つでもあれば拒否 |
| P1 | 書き込み 1 回の条件だけを「到達定義が lea のみ」に置換（call は経路上の定義。関数全体の call 規則は外す） | 1 つでもあれば拒否（0090 項目 2 のまま） |
| P1c | P1 に、関数全体の「揮発 B と call があれば拒否」を残す | 同上 |
| P3 | P1 と同じ判定。ただし他の間接 jmp は、**それ自身が P3 で証明された switch なら拒否しない**（その表の全移動先を辺にする。不動点。最大不動点） | **未解決の他の間接 jmp があれば拒否（fail-closed）** |
| P4 | P1 と同じ判定。他の間接 jmp のうち証明されないものは、**移動先が不明なので「関数内の任意の命令の先頭に、その jmp の時点のレジスタ状態を持って着地する」と扱う**（ワイルドカードの辺） | 未解決でも拒否しない（ただしワイルドカードで届く定義が lea のみであること） |
| P4c | P4 に、関数全体の call 規則を残す | 同上 |
| PO | P1 と同じ判定。他の間接 jmp のうち証明されないものは**辺なし**（移動先を見ない） | 未解決でも認める。**規則として健全でない**（比較のためだけ） |
| D | 規則ではなく**バイト列の読み**: 他の間接 jmp の表を、解決済みなら実表、N が導けない (c1) は「エントリが関数内の命令の先頭である間の連続」（上限の見積もり）、形違いの `jmp reg` も同じ方法で読む。`jmp [mem]` は移動先不明 | — |

### 2.2 分類の数え上げ（実測。`logs/b2d7.sites.tsv`、`dsp7.sites.tsv`）

| | Blend2D（38） | dsp_ippv2（5） |
|---|---:|---:|

| (i') 同、辺 = 解決済み・読めた他の表を全部足す（D） | 38（定義 1 つ 34、2 つ 2、8 つ 2） | 5 |

| (ii) 定義が 2 つ以上（すべて `lea ImageBase`。(i') の内数） | 4（`0x47639ae`/`0x47802d9` = 2、`0x487d636`/`0x4889443` = 8） | 0 |

読み取り:

- **到達定義の分類で lea 以外が届くものは 0 件**。MSVC の switch が B を `lea B,[ImageBase]` で出し直す形（調査 `blend2d-switch-tables.md` §3.4 の 33 か所の大半）は、書き込みが多いだけで、**jmp に届く定義は `lea` だけ**。
- call をまたぐものも 0 件。現行の「揮発 B と関数内 call があれば拒否」は**関数全体**で見る規則で、この 0 件より厳しい（§3 の P1 と P1c の差）。
- 「ガードを迂回する」1 件は `0x4745efd`: `0x4745e9c: test r8,r8; je 0x4745ef2`（r8 = 0）が、`cmp r8,9; ja` の**後ろ**の `mov eax,[r12+r8*4+…]`（0x4745ef2）へ飛ぶ。これは**基底証明ではなく既存の `landings_in_idioms`／`verify_msvc` が落とす形**（ガードを飛ばす着地）で、規則を緩めても変わらない。
- 他の jmp の表からの到達 12 件のうち、実際に「別の switch の手前に届く」実例: `f_4745bd0`（`0x4745cf4` の表の移動先 `0x4745e86` から `0x4745efd` へ。上の迂回）、`f_48aeed0`（`0x48aef10` と `0x48aefcc` の表から `0x48af10a` へ。ガードの `cmp r9d,0xf; ja` を通る）、dsp の `f_37d9630`（`0x37d9670`、`0x37d972c` から `0x37d986a` へ。同じ形）。
- N が導けない site（Blend2D 42、dsp_ippv2 6）の B の到達定義も、HEAD の線形走査で見ると**ほぼ lea のみ**（Blend2D 39 が lea のみ、3 が入口から届かない。dsp_ippv2 は 6 すべて lea のみ。辺なしの計算。`logs/b2d7.sites.tsv` の `cls_noN` 列）。ただし N が導けないので、基底証明を緩めても解決しない。

## 4. `f_48a2060` と `f_37cc7e0` の詳細

出力: `logs/memcpy-b2d.txt`、`logs/memcpy-dsp.txt`（`analysis/rdef_memcpy.py`）、`logs/probe-48a2060.txt`、`probe-37cc7e0.txt`。2 つの関数は同じコンパイラ出力で、VA が違うだけ（Blend2D `0x48a2060` + `x` ↔ dsp_ippv2 `0x37cc7e0` + `x`、表の RVA が違う）。以下は Blend2D の VA。dsp_ippv2 は末尾に対応を書く。

### 4.1 構造（実測）

- 関数 `[0x48a2060, 0x48a26d5)`、`.pdata` 1 エントリ（連鎖なし）、346 命令、call 0 個。入口に `mov rax,rcx` と `lea r10,[rip-0x1a206a]`（0x48a2063。r10 = 0x4700000 = ImageBase）。

### 4.2 3 つの `jmp r11`（実測）

3 つとも `lea r9,[r8+0x1f]` または `[r8+0xf]` → `and r9,-0x20`（`-0x10`）→ `mov r11,r9` → `shr r11,5`（`4`）→ `mov r11d,[r10+r11*4+T]` → `add r11,r10` → `jmp r11`。(c1) の形（`mov; add; jmp`）で、**`cmp idx,imm; ja` が無い**（添字が `shr` で作られ、直前が `mov`/`and`/`lea`）。HEAD の `recognize_msvc` は `N not derived: no ja before the table idiom`。表は T2 = 0x2fd090、0x2fd0b4、0x2fd0d8（`jmp r9` の表は 0x2fd050）。

|---|---|---|---:|---|---|
| `jmp r9` 0x48a208b | 0x2fd050 | 0x2fd050〜0x2fd090 | **16**（N = 15 と一致） | r8 = 0..15（`cmp r8,0xf; ja`） | **導ける** |
| `jmp r11` 0x48a22d2 | 0x2fd090 | 0x2fd090〜0x2fd0b4 | **9** | `shr (r8+0x1f)&-0x20, 5`。r8 ≤ 0x100 → 0..8 | **導けない**（`cmp; ja` なし） |
| `jmp r11` 0x48a2402 | 0x2fd0b4 | 0x2fd0b4〜0x2fd0d8 | **9** | 同上 | 導けない |
| `jmp r11` 0x48a2576 | 0x2fd0d8 | 0x2fd0d8〜0x2fd0fc | **9**（`_RDATA` の末尾 0xfc まで） | `shr (r8+0xf)&-0x10, 4`。r8 ≤ 0x80 → 0..8 | 導けない |

- 添字の範囲は、`r8` の範囲（`cmp r8,0x100; jbe` または `jae` の先）を総当たり（r8 = 0..0x100、0..0x80）で確かめた（`shr ((r8+0x1f) & ~0x1f), 5` は 0..8、`shr ((r8+0xf) & ~0xf), 4` は 0..8。**読み**。この範囲が実行時に成り立つかは、`cmp r8,0x100; jbe/jae` の読みに依存し、実行していない）。
- 4 つの表が `_RDATA` に連続して並び（0x2fd050、0x2fd090、0x2fd0b4、0x2fd0d8、合計 0xac バイト）、各表の長さは次の表の開始位置までの距離と一致する。4 つの表の全エントリ（16 + 9 + 9 + 9 = 43 件）は、すべて関数内の命令の先頭（`rdef-idump` の iced の掃引）で、重複なし（`jmp r9` の 16 件は 16 個すべて異なる。`logs/memcpy-b2d.txt`）。
- 隣の表の中身まで読み進めた場合（N が導けない表を「エントリが関数内の命令の先頭である間の連続」として読む。上限の見積もり）、`jmp r9` の表は 43 件、`jmp r11` の 1 つ目は 27 件、2 つ目は 18 件、3 つ目は 9 件まで続く（4 つの表の中身がどれも関数内の命令の先頭に見えるため）。**表のエントリ数は、この読みでは決まらない**。上の表の「9」は、次の表の開始位置までの距離（RVA の差 ÷ 4）と、添字の範囲の読み（`shr` 後の 0..8）が一致することから来た値で、規則として導いたものではない。それでも、over-read の 43/27/18/9 件のどれで読んでも、3 つの `jmp r11` の移動先は `jmp r9` の手前（0x48a2060〜0x48a208b）に届かない（4.3）。

### 4.3 `jmp r9` に届く r10 の定義（実測。読みの CFG）

CFG: 直接分岐と fall-through。間接 jmp の辺は、`jmp r9` の表（16 件）と 3 つの `jmp r11` の表（9 件ずつ）を辺にした場合（「正確な表」）、`jmp r11` の表を over-read の最大値（27、18、9）にした場合、他の 3 つの間接 jmp を「関数内の任意の命令の先頭へ着地する」とした場合の 4 通り。

| 辺のモデル | `jmp r9` の r10 の定義 | `jmp r11` ×3 の r10 の定義 |
|---|---|---|
| closure の見方（`jmp r9` 自身の表だけ。他の jmp は辺なし） | `lea r10,[ImageBase]`（0x48a2063）のみ | 同（辺なし） |
| 4 つの表を正確に辺に入れる | 0x48a2063 のみ | 0x48a2063 のみ |
| `jmp r11` の表を over-read の最大値で辺に入れる | 0x48a2063 のみ | 0x48a2063 のみ |
| 他の 3 つの間接 jmp = ワイルドカード（任意の命令の先頭へ着地） | 0x48a2063 のみ | 0x48a2063 のみ |

- `jmp r9`（0x48a208b）への経路: 入口 `0x48a2060` → `0x48a2063`（lea）→ `0x48a206a` → `0x48a206e` → `0x48a2074`（nop）→ `0x48a2080` → `0x48a2088` → `0x48a208b`。**入口から `jmp r9` までに branch で入ってくる点は 1 つもない**（`0x48a2060..0x48a208b` の中へ入る直接分岐・表のエントリは 0 件。`0x48a2074` へ入る `ja` は fall-through の辺）。`jmp r9` に直接辺だけで到達できる命令は、この 8 命令（0x48a2060、0x48a2063、0x48a206a、0x48a206e、0x48a2074、0x48a2080、0x48a2088、0x48a208b）だけ。
- `0x48a209b`（`movzx r10d`）が届く先は 6 命令で、`ret`（0x48a20af）で終わる。`0x48a25f3`（`mov r10,rdx`）が届く先は 58 命令で、`ret`（0x48a26d4）で終わる。**どちらからも、4 つの間接 jmp のどれにも届かない**（`jmp r9` の表の 16 エントリと `jmp r11` の 3 つの表のどのモデルでも）。この 2 つの書き込みは、各々の枝の末尾（ret 直前）で r10 を使い捨てている（`movzx r10d,byte [rdx+0xe]` はコピーの 1 バイトの一時値、`mov r10,rdx` は入口で r10 にコピー元を退避して最後の `movups xmm1,[r10]` で使う）。
- 3 つの `jmp r11` の移動先（正確な表 9 件ずつ、over-read の最大 27/18/9 件）のどれも、`0x48a2060..0x48a208b` の命令に届かない（`logs/memcpy-b2d.txt` の「zone」の節。0 件）。`0x48a2180`（`jmp r9` の `ja` の行き先）は `0x48a206e` と `0x48a217f`（fall-through）からのみ到達し、そこから 3 つの `jmp r11` のブロック（0x48a22b8、0x48a23e8、0x48a255c）へ進む。3 つの `jmp r11` のブロックの入口へ入る分岐は、いずれも関数内の `jbe/jae/jb` と fall-through。
- r10 の書き込み 2 つ（`0x48a209b`、`0x48a25f3`）の前を通って 4 つの `jmp` のどれかに届く経路は**ない**（上の「届かない」）。したがって `jmp r9` の `r10` と、3 つの `jmp r11` の `r10` は、実データでは**すべて ImageBase**（実測の CFG で。実行していない）。

### 4.4 緩めた規則で `jmp r9`（0x48a208b）は証明できるか（実測。解析器）

| 規則 | `jmp r9` 0x48a208b | `jmp r11`（3 つ） | 理由 |
|---|---|---|---|
| R0（現行） | 拒否（`R10 is written 3 times`） | N 不明 | 書き込み 3 回 |
| P1（到達定義が lea のみ。他の間接 jmp があれば拒否） | **拒否** | N 不明 | 他の間接 jmp が 3 つ |
| P3（他の jmp が解決済みの switch なら辺。未解決があれば拒否） | **拒否** | N 不明 | 他の 3 つの `jmp r11` が未解決（N が導けない）。**未解決の間接 jmp の移動先が不明なので、`jmp r9` の B の定義が `lea` だけと証明できない**（規則として） |
| P4（未解決の他の間接 jmp はワイルドカード） | **通る** | N 不明（解決しない） | ワイルドカードで着地しても r10 の定義は `lea` のみ |
| PO（辺なし） | 通る | N 不明 | 同上。ただし規則として健全でない |
| 読み（D）: `jmp r11` の表を実表で辺にする | lea のみ（上の 4.3）。**安全** | — | — |

読み取り:

- **`0x48a208b` は、他の間接 jmp があっても認める規則（P4、PO）でしか証明できない**。P1 と P3 では証明できない。`jmp r11` の 3 つは N が導けない（`shr` で添字が作られ、`cmp; ja` が無い）ので、**未解決のまま残り、移動先が不明**。fail-closed（P3）の下では、`f_48a2060` の `jmp r9` は解決しない。
- 「未解決の間接 jmp があるのに認める」ことの内容は、**移動先がバイト列から読める**ことに頼る: 4 つの表がそれぞれ隣の表の開始位置で終わる配置（上の 4.2）なので、`jmp r11` の表のサイズは**位置から**9 と読めるが、これは規則として導いたものではない（N の導出規則は `cmp; ja`）。実データ（読み）では安全。規則としては、(1) 「未解決の間接 jmp がある関数では、その jmp の移動先が不明なので、B の定義が `lea` だけと証明できない」（P3。`0x48a208b` は通らない）か、(2) 「未解決の間接 jmp はワイルドカード（任意の命令に着地）として扱い、それでも B の定義が `lea` だけなら認める」（P4。**移動先の表を読まなくても**、`lea` から `jmp r9` までの経路が直線で、途中に着地できる命令がない、という形で成り立つ）のどちらかになる。P4 は表を読まないので、`jmp r11` の表の読みの誤りに影響されない。
- P4 が `0x48a208b` を通す理由（読み。解析器 `rdef_lib.py` の計算の説明）: 解析器は、未解決の他の間接 jmp すべてを「関数内のどの命令の先頭へも辺を持つ**1 つの**仮想ノード」に繋ぎ、到達定義を前向きに求める。仮想ノードが運ぶ定義の集合は、**未解決の間接 jmp すべてに届く定義の和集合**で、どの命令に着地してもその集合が流れ込む（`rdef_selftest.py` で、他の jmp に `lea` 以外の定義が届くと、すべての命令でそれが見えることを確かめた）。`jmp r11` の 3 つに届く r10 の定義は `lea`（0x48a2063）だけなので、仮想ノードが運ぶ r10 の定義も `lea` だけで、どこへ着地しても `jmp r9` に届く定義は `lea` だけのまま。つまり「`0x48a209b`／`0x48a25f3` の r10 の値を持ったまま、他の間接 jmp が `0x48a2080` に着地する」ことは、`0x48a209b`／`0x48a25f3` から間接 jmp へ届かないので起こらない（4.3）。**P4 の成立は「r10 の `lea` 以外の定義が、未解決の間接 jmp のどれにも届かない」ことにだけ依存し、`jmp r11` の表の中身（エントリ数、値）には依存しない**。ただしこの成立条件の確認は、`0x48a209b` と `0x48a25f3` から前向きに到達する先が `ret` で終わる直線＋分岐であること（上の 4.3）という、**CFG の読み**に頼る。
  - 規則として P4 が危ういのは、`lea` 以外の定義が間接 jmp に届く場合で、そのとき仮想ノードが「`lea` 以外の定義」を任意の命令に運ぶので、届く先の B はすべて「lea のみ」でなくなり拒否される。実データではこれが 7 件（§2.2 の (iii')。`0x4745cf4` ほか）で、`f_48a2060` と `f_37cc7e0` は含まれない。
- 他の `.pdata` 関数から `f_48a2060` の中への直接の transfer は、Blend2D 全体で **`call 0x48a2060` が 194 件で、すべて関数の入口**。入口以外へ飛び込む直接 jmp／jcc／call は 0 件（`rdef-idump --xrefs`、`logs/xrefs-b2d.txt` を `[0x48a2060, 0x48a26d5)` で絞った。実測）。`foreign_entries` に引っかからない。dsp_ippv2 の `f_37cc7e0` は `call` 14 件、すべて入口。

### 4.5 dsp_ippv2 `f_37cc7e0`（実測。`logs/memcpy-dsp.txt`）

同じ形（`0x48a2060` ↔ `0x37cc7e0`、`0x48a208b` ↔ `0x37cc80b`、r10 の `lea` ↔ `0x37cc7e3`、`movzx r10d` ↔ `0x37cc81b`、`mov r10,rdx` ↔ `0x37ccd73`）。`jmp r9` の表 0x2615000（16 エントリ、N = 15）、`jmp r11` 3 つ（0x37cca52、0x37ccb82、0x37cccf6。表 0x2615040、0x2615064、0x2615088。N 不明）。r10 への書き込み 3 回、他の間接 jmp 3 つ、call 0 個。r10 の到達定義は **`lea r10,[ImageBase]`（0x37cc7e3）のみ**（4 つの辺のモデルすべて）。`0x37cc81b` と `0x37ccd73` から 4 つの間接 jmp のどれにも届かない。規則の結果も Blend2D と同じ（R0、P1、P3 は拒否。P4、PO は通る）。`jmp r9` の idiom に着地する分岐もない。`.pdata` の関数内。dsp_ippv2 の 14 か所の call（`rdef-idump --xrefs`）はすべて関数の入口。

### 4.6 `jmp r9` を解決した場合の移動先と生成 C（読み。未実施）

- 16 エントリ（`0x48a208e`…`0x48a2090`）のブロックは、`jmp r9` の表の `r8 = 3` で `0x48a20ff`（`movzx ecx,word [rdx]; movzx r8d,byte [rdx+2]; mov [rax],cx; mov [rax+2],r8b; ret`）に届く。3 モジュールの a4 の現在の停止は `fle: indirect call to 0x48a20ff is not a known function entry`（`blend2d-srw.md` §6）で、解決すれば `0x48a20ff` が closure の中のラベルになるので、この停止は解決する（読み。**未実施**。停止の先は未確認）。
- 生成 C の switch は `fe-lift/src/jumptab.rs` の `Select::Target` と同じ形（case = 移動先の VA、default = `fle_jumptab_miss`）。選択子は jmp レジスタの実際の値で、case の VA は fe-lift が読んだ PE の ImageBase + RVA。したがって実行時の r10（`lea r10,[rip+d]` が計算する値）が fe-lift が読んだ ImageBase と一致しなければ、`fle_jumptab_miss` で止まる（0089 以来の 4 か所と同じ性質。読み。実行していない）。基底 0x4700000 は測定用の値（決定 0080 は 0x2000000 を「衝突しない範囲の選択」と書き、実機の ImageBase 0x180000000 と違うことを明記している）。

### 5.3 N が導けない `jmp r11` 3 つについて（事実）

(C) の形で `0x48a208b` を解決するには、`jmp r11` を**表として解決する**か、「未解決で、移動先を辺にできない」ままにするか。前者は N の導出を広げる必要がある（`shr` で作られる添字。`cmp; ja` が無い。0089 1(b) の範囲外。**N は表の位置（次の表の開始位置まで）から読める、または `lea r9,[r8+0x1f]; and r9,-0x20; shr r11,5` の値域から読める**が、どちらも 0089 が書いた規則ではない）。この調査は N の規則を変えていない。

## 7. 限界

- **静的な見積もりだけ**。規則を実装した fe-lift を作っていない。数（net、新規の site）は、解析器（Python。iced-x86 の線形走査を使う）の結果で、実装の結果と一致するのは R0（現行規則）で確認した（Blend2D 3、dsp_ippv2 1、`msvc_rejected` の書き込み回数と N の判定が全件一致。§0.3、§3.1）。P1〜P4 の数は実装との突き合わせを**していない**。
- 解析器の CFG は、直接分岐と fall-through、`ret` などの終端だけ。SEH のハンドラ・フィルタ・`longjmp`・例外による遷移は見ていない（0090 の限界と同じ）。関数の外の直接分岐は辺を持たない。`.pdata` の連鎖したピースは全部見る。
- 「他の間接 jmp の表を読む」ヒューリスティック（D、`rdef_survey2.py`）は、直前 8 命令の中の `mov r32,[X+Y*4+disp]` の disp から、エントリが関数内の命令の先頭である間の連続を読む。表の本当のサイズを導いたものではなく、**読みの上限**。D の「安全」16 件のうち 10 件はこの読みに頼る。
