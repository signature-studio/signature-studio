# 0x412104 の添字（表の index）の由来と、表の中身（計測）

対象: f_4120c0 の 0x412104（`[rbp+0x38] = [[0x15eac90]+8 + 添字×16]`）と、0x412126 の `call [rbp+0x38]`。
計測用の複製は `lift/out-idx/` の中のみ。本番の `out-final/`、`out-seed-final/`、既定の生成 C と seed は変えていない。

## 1. 0x412104 の添字の由来（objdump の根拠）

f_4120c0 の 0x4120c0〜0x41214b を `objdump -d -M intel` で読んだ結果（実測）。

```
4120cc  mov   rax,[0x15eac90]        ; 表の構造体へのポインタ
4120d6  je    0x412146               ; 0 なら終了
4120d8  mov   ecx,[rax]              ; 件数 = 構造体+0（4 バイト）
4120da  mov   [rbp+0x4c],ecx         ; 上限
4120dd  mov   DWORD [rbp+0x48],0x0   ; 添字 = 0（ループの初期化）
4120e4  mov   rax,[rax+0x8]          ; 表の先頭 = 構造体+8
4120e8  mov   [rbp+0x40],rax
4120ed  mov   eax,[rbp+0x48]         ; 添字（ループ変数）
4120f0  cmp   eax,[rbp+0x4c]
4120f3  jge   0x412131               ; 添字 >= 件数なら終了
4120f5  mov   rax,[rbp+0x40]
4120f9  movsxd rcx,[rbp+0x48]        ; 添字
4120fd  add   rcx,rcx                ; 添字 × 2
412100  mov   rax,[rax+rcx*8]        ; 要素 = [表先頭 + 添字×16]
412104  mov   [rbp+0x38],rax         ; 0x412126 の宛先
412108  add   DWORD [rbp+0x48],1     ; 添字 += 1
41210f  mov   [0x15eac98],eax        ; 添字（次回の再開用の大域）
412115  cmp   QWORD [rbp+0x38],0
41211a  je    0x412129
41211c  mov   rax,[rbp+0x38]
412120  cmp   QWORD [rax],0          ; 宛先の先頭 8 バイトが 0 なら飛ばす
412124  je    0x412129
412126  call  [rbp+0x38]
412129  mov   eax,[rbp+0x48]
41212c  cmp   eax,[rbp+0x4c]
41212f  jl    0x4120f5               ; ループ
```

- 添字は引数ではない。f_4120c0 の内部のループ変数 `[rbp+0x48]`（0 から件数まで）。
- 上限は表の件数（`[構造体+0]`、4 バイト）。
- 0x412104 は、ループの各回で 1 回ずつ通る。
- 0x41202c（f_41202c）でも `[0x15eac90]` を読み、`[0x15eac98]`（添字の大域）を読む。これは別経路の再開用。

## 2. 呼び出し元からの添字と表の渡し方（objdump の根拠）

- 呼び出し元は 0x412295（f_412160 の中）の 1 箇所。`call 0x4120c0` は `cmp dword [rbp+0x170],1` の後にだけ通る（実測）。
- 添字そのものは f_412160 から渡されない。f_4120c0 は引数を取らない（`void f_4120c0(void)`）。
- 表の構造体へのポインタは、f_412160 の rdx を保存した値。
  - `0x412176: lea r13,[0x15eac80]`。`0x41217d: cmp dword [rbp+0x170],2`、`0x412184: jb 0x41218d` で、`[rbp+0x170] >= 2` のときだけ `0x412186: lea r13,[0x15eada8]` に変わる（実測）。
  - `0x4121bb: mov [r13+0x10], rdx`。`r13 = 0x15eac80` のとき、このストアは `0x15eac90` に rdx を書く（実測）。`[0x15eac90]` の書き込みは、この経路が唯一（生成 C の `fle_st(0x15eac90...)` は 0 件。実測）。
  - 0x412295 の呼び出し（f_4120c0）は `[rbp+0x170] == 1` のときだけ（0x412293）。その時は `r13 = 0x15eac80`（0x412186 の分岐は通らない）。
  - 注意: `[rbp+0x170]` の値の由来（呼び出し元の引数）は、本計測では追っていない（未確認）。
  - f_412160 が rdx を受け取るのは、呼び出し元 f_41d8f0（0x41d984 の `call 0x412160`）が `rsi = rdx` を保ち、`lea rdx,[rip+...]` を渡すため。
- f_41d8f0 の rdx（= rsi）は、f_1376820（entry）が `lea rdx,[rip+0x51]`（0x13768b0）として渡す（0x137685f。実測）。
- 添字は 0x412295 の時点では関与しない（添字は f_4120c0 の中で 0 から数える）。

## 3. 実行での到達回数と添字の値（実測）

### 3.1 probe のみ（out-idx: `after-idx.c`、ビルド `build.sh`、ログ `run-idx.txt`）

- 0x412104 の到達: 1 回（`IDX hit=1 index=0 count=942 elem=0x41e7e0`）。
- 添字 0 の値は 0x41e7e0。以降、0x412126 の call で停止（`fle: indirect call to 0x41e7e0 is not a known function entry`）。
- 表の全要素（942 件）を初回に dump（`TBL k value`）。ログ `run-idx.txt`、一覧 `table-elements.txt`。
- 停止は、既存の本番（`out-seed-final/run-after-seed41d050.txt`）と同じ 0x41e7e0。

### 3.2 walk 版（out-idx: `walk-idx.c`、ビルド `build-walk.sh`、ログ `run-walk.txt`）

0x412126 の call で「宛先が生成 dispatch 表（6971 件）に無ければ記録して call せず先へ進む」計測専用版。

- 0x412104 の到達: 942 回。添字 0〜941 が各 1 回（`walk-index-hits.txt`）。
- 添字と表の要素の値は、表の dump と一致（942 件すべて、不一致 0）。
- 0x412126 で dispatch 表に無かった（= skip した）回数: 895 回（`walk-skipped.txt`）。skip した 895 件の宛先は、表の text 値（pdata の関数先頭）と一致する。
- 注: `WALK skip index=N` の N は、表の添字 + 1 で出ている（ループ変数が 0x412108 で既に +1 されているため）。895 件すべてで「N − 1 の表の値 = skip した宛先」を確認（実測）。
- 残り 47 件（data 宛 46 件、0 の 1 件）は skip されなかったが、walk 版のログには 0x412126 の call として現れていない（`WALK` も `fle_dispatch` のログも無い）。この 47 件で 0x412126 がどう振る舞うかは未確認。walk 版は添字 941 の後、0x4126f0 の `fle: unsupported instruction` で停止した（0x4126f0 は f_4120c0（0x4120c0〜0x41214b）の外。どの呼び出しから来たかは未調査）。
- 本計測で確かめられたのは、「添字 0〜941 の全てで 0x412104 に到達し、値が表の要素と一致した」「text 宛の 895 件は閉包外の候補として skip 対象になった」まで。

注: walk 版の「dispatch 表に無い」判定は、生成 C の `fle_dispatch_table`（6971 件）を基準にしている。これは閉包の定義そのものではない（閉包の一覧ファイルは `closure-run5-dataflow.txt` で、件数の要約しか含まない）。

## 4. 表の要素の一覧（件数と分類）

表（`[0x15eac90]` が指す構造体）:

- 構造体 0x13768b0（DLL の .text 内、静的に存在）。`+0` = 件数 942、`+8` = 表の先頭 0x13768e0。
- 表本体 0x13768e0、要素 942 件（各 16 バイト。`+0` が値、`+8` は未使用）。
- 静的（DLL のバイト列）から読んだ表と、実行時の dump は一致（942 件、不一致 0）。
- 表は .bss ではなく、DLL の .text に静的に入っている。`[0x15eac90]` 自体（ポインタ）は .bss。

分類（`table-classify.txt`。各行: 添字、値、領域、生成 dispatch 表にあるか、pdata の関数先頭か）:

| 分類 | 件数 | 備考 |
|---|---|---|
| text 内、生成 dispatch 表に無い（閉包の外と見なす） | 895 | 全件が pdata の関数先頭 |
| text 内、生成 dispatch 表にある（閉包内と見なす） | 0 | |
| data（0x13a5000〜0x15e5008）内の値 | 46 | 全件 0x13a9390（データ領域。関数ではない） |
| 0 | 1 | 添字 941（終端の 0） |
| 合計 | 942 | |

- 添字 0: 0x41e7e0（閉包外、pdata の関数先頭）。
- 添字 1: 0x41ce10（閉包外、pdata の関数先頭）。
- 添字 2: 0x420d80（閉包外、pdata の関数先頭）。
- 0x41d050 は、この表には無い（0 件）。依頼文の「表 0x13a9410 の [1]」は、この表（0x13768e0）とは別の表。0x13a9410 の表は静的に確認した（[0]=0x41d0e0、[1]=0x41d050、[2]=0x41d000、[3]=0x41d090。ファイルの .data の生バイト。実測）。この表は 0x412104 の表ではなく、0x412126 とは経路が別（未確認）。
- 表の値の種類: 異なる値 897 種（942 件のうち、重複を除く）。

閉包内外の判定の基準: 生成 C の `fle_dispatch_table`（6971 件、`after-seed41d050.c` 6982 行付近）。この表に無い関数先頭は、閉包の外（生成 C に変換されていない）と見なす。pdata の関数先頭は `.pdata` の BeginAddress から取った（57,816 件、重複なし）。

## 5. 結論（実測の範囲で）

- 0x412104 の添字は、f_4120c0 の内部ループ変数（0 から件数 942 まで）。引数から来ない（objdump と実行で一致）。
- 表は、DLL の .text に静的に入った 942 件の配列（構造体 0x13768b0 経由）。f_1376820 が渡す。
- 表の要素の大半（895 件）は、生成 dispatch 表に無い text の関数先頭（すべて pdata の関数先頭）。閉包の外と見なせる。
- 表は「閉包の外の関数を選ぶ仕組み」を含む。閉包内の関数だけを選ぶ仕組みではない（dispatch 表にある要素は 0 件）。
- 閉包の外の関数を一括で扱うのに必要な情報:
  - 表の全要素（942 件、`table-elements.txt`）。
  - 添字の範囲（0〜941）と、件数（942）。
  - 閉包の外の要素の件数（895）。
  - 閉包内と見なせる要素は 0 件（生成 dispatch 表に入る値は無い）。
  - 残りの 47 件は data 宛 46 件（値 0x13a9390。データ領域のアドレス）と 0 が 1 件。walk 版では 0x412126 の call に入っていない（ログに無い）。
- 注意（未検証）: 0x412126 で data 宛や 0 を call したときの挙動、表の要素が呼ばれる順序（walk 版は呼ばずに skip した）、各関数の実行結果は未確認。0x41d050 は、この表の外（0x13a9410 の表）で見つかっている。
