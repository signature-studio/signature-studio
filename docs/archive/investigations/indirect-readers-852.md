# 852 件の関数先頭を読む間接参照（閉包内と閉包外）

対象: `binaries/win64/FLEngine_x64.dll`（読み取りのみ）。
分析: `lift/out-indir/`（新規。`indir_scan.py`、`indir_scan2.py`、`indir_scan3.py`）。既存のコードと生成物は変更していない。

「実測」は、逆アセンブルとスクリプトの出力による結果。「推測」は、未検証の解釈。

## 0. 前提（実測）

- ImageBase は 0x400000。`.text` の VA は 0x401000 から、`.data` は 0x13a5000 から（objdump と一致）。
- 852 件の母集団は `lift/out-seed/out/seeds-pdata-852.txt`（既存）。
- 閉包は `lift/out-seed/out/base-functions.tsv`（既存、6,969 関数）。
- 間接 call の既知件数は、閉包内 6,490 件（一致）。

## 1. 間接 call/jmp の件数（実測）

閉包内は、閉包の各関数の entry から到達可能な命令を辿って数えた（`indir_scan2.py`）。閉包の 6,969 関数のうち、pdata に無い 423 件も含む。

閉包外は、pdata の関数範囲を線形に逆アセンブルして数えた（51,270 関数）。

| 区分 | call | jmp | 合計 |
|---|---:|---:|---:|
| 閉包内 | 6,490 | 425 | **6,915** |
| 閉包外 | 36,068 | 3 | **36,071** |

オペランド形式別:

| 形式 | 閉包内 call | 閉包内 jmp | 閉包外 call | 閉包外 jmp |
|---|---:|---:|---:|---:|
| `[rip+X]` | 171 | 423 | 321 | 0 |
| `[base]` | 6,223 | 1 | 35,129 | 0 |
| `[base+idx*8]` | 4 | 1 | 9 | 0 |
| `reg` | 92 | 0 | 609 | 3 |

注意（推測）: 閉包外の数は線形走査のため、関数範囲にデータや埋め込みが含まれる可能性がある。閉包外の数字は上限寄り。

## 2. 基底レジスタの由来の分類（実測）

同じ基本ブロック内を、直前の命令から逆にたどった（`indir_scan2.py`）。

| 由来 | 閉包内 | 閉包外 |
|---|---:|---:|
| `rip_direct`（オペランド自体が RIP 相対） | 594 | 321 |
| 同一ブロック内に定義なし（`cross_block`）・その他 | 6,321 | 35,750 |
| 同一ブロック内で、`lea`（RIP 相対）・`mov reg,[rip+X]` が由来（集計の出力に該当の区分なし） | 0 | 0 |

補助（`indir_scan3.py`、推測）: 同じ関数内の RIP 相対の `lea/mov` を基底レジスタの定義として集めた。基本ブロックの支配関係は見ていない。`cross_block` 39,561 件のうち、定義が見つかったものは 9,735 件。この集計は、表の範囲（0x13a9410 の run）とは照合できていない。表の範囲に当たったものは 0 件（閉包内 0、閉包外 0。`indir3b-summary.txt`）。

## 3. 852 件の表（0x13a9410 を含む run）を読む読み手（実測と推測）

- 自動（同一ブロック内、または `rip_direct`）で、基底が 0x13a9410 の run に当たるもの: **閉包内 0、閉包外 0**。
- 補助（関数内の RIP 相対の定義）で、0x13a9410 の run に当たるもの: 0。
- **手動（関数をまたぐ逆追跡）で見つかったもの: 1（閉包内）**。

手動で追跡した経路（実測。逆アセンブルで確認）:

1. `0x41d95a`: `lea r9,[rip+0xf8baaf]` → `r9 = 0x13a9410`（852 件の表の基底）。
2. `0x41d984`: `call 0x412160`（`r9` を引数として渡す。この関数内に、他の直接の呼び出し元は無い）。
3. `0x412173`: `mov rbx,r9` → `rbx = 0x13a9410`。
4. `0x41221f`: `mov rax,[rbx]`。
5. `0x41223e`: `call [rbx+rsi*8]`（閉包内の関数 `0x412160`）。

注意: 2 は、直接の `E8/E9` の rel32 で `0x412160` を呼ぶ箇所を `.text` 全体で探したもの。間接的な呼び出し（関数ポインタ経由）は探していない（推測の余地）。

## 4. 呼ばれる値と 852 件の関数先頭（実測）

`0x41223e` の呼び出しの条件（逆アセンブル）:

- `[rbp+0x170]` が 1 のとき `je 0x412238` で呼ぶ。
- `[rbp+0x170]` が 2 のとき、`jne 0x412241` を通らず 0x412238 に入って呼ぶ。
- それ以外は呼ばない。

したがって、呼ばれうる表の要素は `rsi = 1` と `rsi = 2` の 2 つ。

| rsi | 表の値（ファイル上） | 852 件の先頭か | 閉包内か |
|---|---|---|---|
| 0 | 0x41d0e0 | 852 件（呼ばれない） | 閉包外 |
| 1 | **0x41d050** | **852 件（呼ばれうる）** | 閉包外 |
| 2 | 0x41d000 | 852 件でない | 閉包内 |
| 3 | 0x41d090 | 852 件（呼ばれない） | 閉包外 |

- 呼ばれうる値 2 件のうち、852 件の先頭に当たるのは 1 件（0x41d050）。
- 表の値はファイル上の値（優先 ImageBase 0x400000 での VA と仮定）。実行時のロード先での補正は未検証（推測）。
- `[rbp+0x170]` の実行時の値は未検証。このため、0x41d050 を実際に呼ぶかは推測。

## 5. 結論

### 5.1 読み手（間接参照の箇所）の件数

- **(a) 852 件を読む間接参照で、閉包内の関数にあるもの: 1 箇所**（`0x41223e`）。手動の追跡による（実測の経路、推測を含む）。
- **(b) 852 件を読む間接参照で、閉包外の関数にあるもの: 6 箇所**（自動。`call [rip+X]` で、slot の値が 852 件の先頭）。
  - 関数 `0x426570`（読む値 0x426570、2 箇所: `0x4265a4`、`0x426604`）
  - 関数 `0x4093f0`（読む値 0x408870）
  - 関数 `0x525b10`（読む値 0x525b10、2 箇所: `0x525b5e`、`0x525bb4`）
  - 関数 `0x5dea70`（読む値 0x5dea70）
  - 注意: `0x426570`（2 箇所）、`0x525b10`（2 箇所）、`0x5dea70`（1 箇所）は、読む値が自分の関数の先頭（自己参照。計 5 箇所）。`0x4093f0`（1 箇所）だけは、読む値が別の関数（0x408870）。
  - 注意: 上の 6 箇所は、スロットの値が seed と一致したものを数えた。(b) の「852 件を読む」は、値が seed と一致することで判定した（スロットの位置の一致ではない）。
- **(c) 由来が特定できなかった間接参照: 閉包内 6,321 箇所、閉包外 35,750 箇所（計 42,071 箇所）**。
  - この中に 852 件を読むものがあるかは、判定できていない（推測の余地が大きい）。

### 5.2 852 件の先頭（seed）の件数

- 閉包内の読み手が読む（実測の範囲）: **1 件**（0x41d050。`0x41223e` による）。
- 閉包外の読み手だけが読む（自動）: **4 件**（0x426570、0x408870、0x525b10、0x5dea70）。
- 読み手が特定できない（(c)）: **847 件**。

## 6. 失敗と拒否（実測）

- 権限拒否、削除、既存ファイルの上書き、git 操作、`/tmp` の利用、sleep/timeout の利用: **なし**。
- 途中で誤った出力を作った。次の 3 つのファイルは誤りのため、**結論に使わないこと**（削除できないため、残置）:
  - `lift/out-indir/indir-*`（v1）: 閉包内に pdata の無い 423 関数を、次の関数の範囲で数えた。閉包内の数字が誤り（`jmp [rip]` 6 万件超）。
  - `lift/out-indir/indir2-*`（v2 の 1 回目）: 子プロセスの起動方式（forkserver）のため、表の情報が空。
  - `lift/out-indir/indir3-*`（v3 の 1 回目）: 同じ理由で誤り。
- 有効な出力: `indir2b-*`（v2 の fork 版）と `indir3b-*`（v3 の fork 版）。
- 生成された `lift/out-indir/__pycache__/` は、分析スクリプトの import によるもの。

## 7. 推測（未検証）

- `0x41223e` は、呼ばれる実行の経路で 0x41d050 を実際に読む可能性が高い（推測）。`[rbp+0x170]` の値の分布は未確認。

- 閉包内の 6,321 箇所も同様（推測）。
