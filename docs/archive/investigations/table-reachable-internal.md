# 閉包外の pdata 関数のうち、データ表から指されるものの件数（M1 作業者）

対象: `binaries/win64/FLEngine_x64.dll`（読み取りのみ）。
分析: `lift/out-table/table_reach.py`（新規。出力は `lift/out-table/out/`、新規作成のみ）。
既存のコード、生成物、閉包は変更していない。`rm` と上書きは使っていない。

「実測」は計算と逆アセンブルの結果。「推測」は未検証の解釈。

## 0. 結論（件数）

| 項目 | 件数 | 区分 |
|---|---:|---|
| X: 閉包外の pdata 関数先頭（`.text` 内、閉包の 6,969 関数に無いもの） | **51,270** | 実測 |
| Y: X のうち、`.text` 以外の DIR64 再配置の値になっているもの | **852**（すべて `.data`） | 実測 |
| Z_ref: Y のうち、閉包内のコードが表の範囲を RIP 相対または即値で指すもの（自動、片側） | **46** | 実測（方法の限界あり、§3） |
| Z_ind: Z_ref のうち、参照元の関数に非 IAT の間接 call もあるもの（自動、片側） | **5** | 実測（方法の限界あり、§3） |
| 判定できない件数（Y − Z_ref） | **806** | 実測（自動判定の残り。「閉包外」とは判定していない） |

**依頼の Z（閉包内の表経由の間接 call の基底の由来から読まれうるもの）は、自動では数えていません。** 上の Z_ref と Z_ind は、依頼の Z の代理です。依頼の定義（間接 call の基底の由来を逆追跡する）による件数は、未計測です（§5）。

## 1. 方法

1. pdata（`IMAGE_DIRECTORY_ENTRY_EXCEPTION`）の begin のうち、`.text` 内のもの（57,816 件）を集める。
2. 閉包の関数集合（`lift/out-seed/out/base-functions.tsv`、6,969 件）に無いものを X とする。
3. `IMAGE_REL_BASED_DIR64` の再配置の位置のうち、`.text` 以外のものの 8 バイト値を読む。値が X にあるものを Y とする。
4. 表の範囲は、同じセクション内で `.text` を指す連続する DIR64 の位置（run）とした。
5. 閉包の各関数（pdata の範囲を Capstone で逆アセンブル）から、RIP 相対のメモリ参照と即値を集める。run の各スロットの番地に当たる参照を Z_ref とした。
6. Z_ind は、その参照元の関数に、非 IAT の間接 call（`call reg` と `call [mem]`。IAT の `call [rip]` は除く）があるものとした。

## 2. 検証（実測）

- X = 51,270 は、既存の `indir2-summary.txt`（`stat.outside_functions 51270`）と一致。
- Y = 852 は、既存の `seeds-pdata-852.txt`（852 件、`ref-852-function-pointers.md`）と一致。
- Y の 852 件は、すべて `.data` の位置を持つ（`table-reach-y.tsv` の `section` 列）。
- 0x41d050 の経路は、逆アセンブルで手動で確認（既存の `indirect-readers-852.md` §3 と一致）:
  - `0x41d95a` `lea r9,[rip+0xf8baaf]` → `0x13a9410`（表の基底）。
  - `0x41d984` `call 0x412160`（`r9` を渡す）。
  - `0x412173` `mov rbx,r9`。
  - `0x41221f` `mov rax,[rbx]`。
  - `0x41223e` `call [rbx+rsi*8]`（閉包内の関数 `0x412160` の中。`base-functions.tsv` に `0x412160` あり、`0x41d8f0` もあり）。

## 3. 方法の限界（実測と推測）

- **Z_ref は、表の基底を RIP 相対の `lea` で作る経路だけを見ている。** 表の基底を `mov reg,[mem]` や引数（`rcx/rdx/r8/r9`）で渡す経路は、見ていない。このため、Z_ref は下限（推測を含む）。
- **Z_ind の条件は弱い。** 0x41d050 の参照元 `0x41d8f0` には非 IAT の間接 call が無い（間接 call は `0x412160` にある）。このため、Z_ind の 5 件は、正しい Z の上限でも下限でもない。
- **閉包内の間接 call の総数は、既存の値と一致しない。** スクリプトは pdata の範囲を線形に逆アセンブルし、到達しないバイトも数えた。このため `7,054`（スクリプト）と、既存の閉包の `6,490`（到達解析）は別の数字。Z の判定には、到達解析の結果を使うべき（推測）。
- 上の Z_ref と判定できない件数（806）は、「閉包外に読み手がある」という意味ではない。読み手が見つからなかった、という意味。

## 4. 3 件の停止点（0x41d050、0x41e7e0、0x41ce10）

| 番地 | X | Y（DIR64 の表） | Z_ref（自動） | 根拠 |
|---|---|---|---|---|
| 0x41d050 | ✓ | ✓（`.data` 0x13a9418、表 0x13a9410 の [1]） | **✓** | 上の §2 の経路で、閉包内の `call [rbx+rsi*8]`（0x41223e）が読む。実測（逆アセンブル）。ただし、`[rbp+0x170]` が 1 のとき実際に呼ばれるかは未検証（`indirect-readers-852.md` §4） |
| 0x41e7e0 | ✓ | ✗ | ✗ | 再配置の値として `.data` や `.rdata` に無い（`pe_probe.py find`、`reloc_covers` とも該当なし）。`.text` 内の 0x13768e0 に同じ 8 バイトのパターンがあるが（実測。`raw occurrences`）、これが表かどうかは未検証（推測: コード内の定数）。呼び出し元の `0x412126 call [rbp+0x38]` は、`rbp+0x38` のスロットが実行時に書かれる可能性がある。その場合は再配置にも `.data` にも現れない。推測 |
| 0x41ce10 | ✓ | ✗ | ✗ | 上と同じ。再配置と `.data` に無い。`.text` の 0x13768f0 にバイト列が一致する（実測）。表かどうかは未検証（推測）。0x412126 の経路で呼ばれるかは未確認（推測） |

**判定:**
- 0x41d050 は **Z に入る**（実測の経路、Z_ref では検出済み）。ただし、依頼の Z の定義（基底の由来が表）に沿った確認は、手動の 1 件だけ。
- 0x41e7e0 と 0x41ce10 は、**Y に入らないため、この定義の Z には入らない**（実測）。実行時に書かれたスロットから呼ばれている可能性があり、その場合は Y の定義の外（推測）。

## 5. 残りの作業量（推測を含む）

- 0x412126 の `[rbp+0x38]` のスロットの由来（実行時の値）、および 0x41ce10 の呼び出し元の確認: 未実施。
