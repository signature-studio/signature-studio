# pdata の関数 entry 852 件を seed に加えた場合の影響

対象: `binaries/win64/FLEngine_x64.dll`（読み取りのみ）。
計測は `lift/out-seed/`（新規）の計測用コピーで行った。本番の閉包（`lift/crates/fe-decode` の seed 既定値）と生成器は変えていない。

「実測」は計測ツールの出力、「推測」は未検証の解釈。

## 0. 計測の方法

- 852 件の定義: `lift/out-diag/pointer_census.py` と同じ。`.text` 以外のページにある DIR64 再配置の値のうち、`.text` を指し、`lift/out-imp/after.c` の表に無く、pdata の関数 begin と一致するもの。
  - 再現した母集団: 6,974 distinct（表内 12）。852 件は `lift/out-seed/out/seeds-pdata-852.txt`（`make_seed_list.py`、新規）。
- 計測用コピー: `lift/out-seed/crates/{fe-pe,fe-decode,fe-lift}`（`lift/crates` の複製）に、外部から seed を渡す関数を追加:
  - `fe_decode::analyze_with_seeds(pe, extra)`: entry と export に加えて `extra` を seed にする。
  - `fe_decode::analyze_isolated(pe, extra)`: entry と export を含めず、`extra` だけから辿る。
  - `fe_lift::generate_with_seeds(data, extra, w)`。
  - 計測用の集計（decode 失敗を関数ごとに数える、関数ごとの未対応件数）。
- 計測ツール: `lift/out-seed/tool/seed-measure`（新規）。
- 基準の確認（実測）: seed 追加なしの計測は、既存の数字と一致した（関数 6,969、ブロック 67,399、命令 460,479、未対応 1,576、表 6,969 行）。計測系は既存と同じ定義で動いている。

既存のコード（`lift/crates/`）は変えていない。`lift/crates` の更新時刻が `lift/out-seed/Cargo.toml` より新しいファイルは 0 件（実測）。

注: 既存の `fe-decode` の `analyze` 等の本番経路は、計測の数字に一切使っていない（基準は `analyze_with_seeds(pe, [])`＝本番と同じ seed）。

## 1. 852 件のうち、有効に decode できる件数（実測）

判定の定義（この文書の定義。推測ではない）:
- 「先頭が有効」: seed の VA が `.text` 内にあり、先頭の 1 命令が decode できる。
- 「再帰降下が成立」: その seed だけから辿った再帰降下（`analyze_isolated`）で、decode 失敗が 0 件。

| 項目 | 件数 |
|---|---|
| 852 件 | 852 |
| 先頭の命令が有効 | **852** |
| 先頭の命令が無効 | 0 |
| 単独の再帰降下で decode 失敗 0 件 | **852** |
| 単独の再帰降下で関数が 0 個 | 0 |
| 単独の再帰降下で関数が 2 個以上（seed 以外の直接 call 先を含む） | 673 |

- 単独の再帰降下の合計（重複を含む）: 関数 503,927、命令 29,172,593。seed 1 件あたり平均 34,240 命令（実測。重複を含むので閉包の大きさではない）。
- ここでいう「有効」は、先頭 decode 可能かつ辿った範囲で decode 失敗 0 件、という意味。ret や分岐で正しく閉じたかは見ていない（推測: 多くは閉じると思われるが未検証）。

## 2. 852 件を seed に加えた閉包の増分（実測）

| 項目 | 基準（現状） | 852 件を追加 | 増分 |
|---|---|---|---|
| 関数 | 6,969 | 8,623 | **+1,654** |
| 基本ブロック | 67,399 | 80,779 | **+13,380** |
| 命令（一意 VA） | 460,479 | 558,743 | **+98,264** |
| decode 失敗 | 0 | 0 | 0 |
| 間接 call（IAT 以外。解決前の件数の合計） | 6,490 | 7,847 | +1,357 |
| 間接 jmp（IAT 以外。解決前の件数の合計） | 16 | 26 | +10 |

注: 上の 2 行は解決の前の件数で、未解決の件数ではない。未解決の内訳は項目 3 の `fle_dispatch` の件数を参照。

- 関数 8,623 は、基準 6,969 の全件を含む（包含。実測）。増分の 1,654 関数は基準に無い。
- 命令数の増分（+98,264）は、関数数の増分（+1,654）に比べて大きい。1 関数あたり平均 約 59 命令（推測を含まない計算: 98,264 / 1,654）。

## 4. 既存の閉包との重なり（実測）

| 項目 | 件数 |
|---|---|
| 852 件のうち、既存閉包の関数 entry | **0** |
| 852 件のうち、既存閉包の命令（関数内部）として既に含まれる | **0** |
| 852 件のうち、既存閉包の外 | **852** |
| 増分の 1,654 関数のうち、既存閉包に既にある関数 | 0（定義上。増分 = 追加後 − 基準） |

- 852 件はどれも、基準の閉包の中には無い（実測）。
- 「増分の関数が既存と重なる」件数は、差分の定義により 0。重なりは「seed 自身が既存閉包にあるか」の方で見るのが正しく、答えは 0 件。
- 注: 増分の中で、seed 以外の関数（直接 call で辿った先）が既存の閉包と重なるかは、基準の閉包に含まれる関数の VA を、追加後の閉包が含む、という包含関係で既に確認済み（基準 6,969 件すべてが 8,623 件に含まれる）。

## 7. 注意と制約

- 閉包は下界（既存文書 `closure-count.md` と同じ）。852 件を足しても、間接 call の未解決（6,478）は解決していない。
- 「有効に decode できる」は、先頭の decode 可能性と、単独の再帰降下の decode 失敗 0 件、で定義した。関数の正しさ（終端の閉じ方、ret の位置）は未検証。
- 計測は計測用コピーで行った。本番の seed 既定値を変えた場合の数字は、その変更の後に再計測する必要がある（実測の前提が変わるため）。
- 本番の `fe-lift` の生成 C（`lift/out-string/after.c` 等）は変えていない。増分の生成 C は作っていない（ディスク容量ではなく、作業範囲の制約による）。
