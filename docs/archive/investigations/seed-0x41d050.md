# 0x41d050 を seed に加えた場合の閉包・生成 C・実行の結果

対象: `binaries/win64/FLEngine_x64.dll`（読み取りのみ）。
計測は `lift/out-seed41d/`（新規）で行った。本番の seed 既定値（entry と export）と既存の生成物は変えていない。

「実測」は計測ツールと実行ログの出力。「推測」は未検証の解釈。

## 0. 方法

- 計測用ツール `lift/out-seed41d/tool/gen41d`（新規）。`lift/out-seed/crates` の複製を `lift/out-seed41d/crates` に置き、`fe_lift::generate_with_seeds(data, extra, w)` を、extra = `[0x41d050]` で呼ぶ。
- 基準（extra なし）の確認（実測）: 関数 6,969、命令 460,479、未対応 1,576、C のバイト数 39,175,730。既存の `lift/out-string/after.c` と一致。
- 生成 C: `lift/out-seed41d/out/plus41d.c`（新規）。
- ビルド: `lift/out-seed41d/build.sh`（新規）。`lift/out-imp/build.sh` と同じ GetCurrentThreadId の 1 行書き換えを行い、それ以外は同じ。
- 実行: `./flengine_seed41d ../../binaries/win64/FLEngine_x64.dll`（DLL のパスを引数で渡す。引数なしだと `image: open failed`）。出力は `lift/out-seed41d/run1.txt`。

## 1. 閉包と生成 C（実測）

| 項目 | 基準（extra なし） | 0x41d050 を追加 | 差 |
|---|---|---|---|
| 関数 | 6,969 | 6,971 | +2 |
| 命令（一意 VA） | 460,479 | 460,492 | +13 |
| 基本ブロック等 | 未計測（この計測では出していない） | — | — |
| 未対応（`unsupported_total`） | 1,576 | 1,577 | +1 |
| C のバイト数 | 39,175,730 | 39,176,976 | +1,246 |
| 表の行 | 6,969 | 6,971 | +2 |

- 増えた関数は 2 件（実測）。内訳は推測: 0x41d050 本体と、0x41cf40（IAT への jmp thunk）。内訳の確認は未実施。
- 未対応の +1 は、`Jmp: indirect through IAT slot (not lifted)` の 409 → 410（実測）。
- 0x41d050 は表の行 `{ UINT64_C(0x41d050), f_41d050 }` に入った（生成 C で確認。実測）。

## 2. ビルドとリンク（実測）

- `sh lift/out-seed41d/build.sh` は成功（`built .../flengine_seed41d`）。
- 生成 C は `L_406f90` を含む（既存と同じ形）。書き換えの確認は `grep -c fle_imp_GetCurrentThreadId` の 1 件で成功。
- 表の行数は 6,969 → 6,971（生成器の `dispatch_rows` と一致。実測）。

## 4. 0x41d050 の dispatch miss が消えたか（実測）

- 消えた。0x41d050 は関数本体に入った（entry log の 7 番目 `callee=0x41d050 f_41d050`）。前回の `fle_dispatch_miss`（dispatch target 0x41d050）は出ていない。
- 0x41d050 の本体から、0x41cf40 への呼び出し（entry 8）が行われた。

## 5. 新しい停止点の命令と未対応の種類（実測）

objdump（`binaries/win64/FLEngine_x64.dll`）:

```
41cf40:  jmp  QWORD PTR [rip+0x1554372]   # 0x19712b8
```

- 種類: IAT 経由の間接 jmp（thunk）。生成 C の行は `L_41cf40: { fle_unsupported(0x41cf40); }`。
- IAT スロット 0x19712b8 は `lift/out-imports/imports.txt` の行 284 によれば `kernel32.dll!TlsAlloc`（実測）。
- 未対応の分類は既存の `Jmp: indirect through IAT slot (not lifted)`（409 件、基準）に属する。今回の追加分と同じ分類（実測）。
- 0x406f90（GetCurrentThreadId）は、既存と同じ書き換えで stub 化したため、今回の計測では停止点になっていない（実測）。

## 6. 推測（未検証）

- 0x41cf40 が TlsAlloc の thunk であることは import 表から読んだ。TlsAlloc の戻り値が 0x41d050 以降の処理に必要かどうかは未検証。
- 0x41cf40 は `out-imp/build.sh` の書き換え対象（GetCurrentThreadId）ではない。同じ方法で stub 化するには、TlsAlloc の実装（戻り値の扱い）を決める必要がある。その判断は作業者（PM）の判断事項。
