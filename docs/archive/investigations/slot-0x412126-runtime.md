# 0x412126 `call [rbp+0x38]` の実行時の値（計測）

対象: f_4120c0 の間接 call（0x412126）の宛先が、実行時に何だったか。
計測用の複製は `lift/out-slot/` に作った。本番の `out-final/`、`out-seed-final/` と既定の生成 C・seed は変えていない。

## 1. 0x412126 の直前の命令と、`[rbp+0x38]` の書き込み元（実測。objdump）

f_4120c0（0x4120c0〜0x41214b）の関連部分:

```
4120cc  mov   rax,[0x15eac90]        ; テーブル構造体へのポインタ
4120d3  test  rax,rax
4120d6  je    0x412146
4120da  mov   [rbp+0x4c],ecx         ; 件数 = [構造体+0]
4120e4  mov   rax,[rax+0x8]
4120e8  mov   [rbp+0x40],rax         ; テーブル先頭 = [構造体+8]
4120ed  mov   eax,[rbp+0x48]         ; 添字
4120f0  cmp   eax,[rbp+0x4c]
4120f3  jge   0x412131
4120f5  mov   rax,[rbp+0x40]
4120f9  movsxd rcx,[rbp+0x48]
4120fd  add   rcx,rcx                ; 添字 × 2（stride 16 バイト）
412100  mov   rax,[rax+rcx*8]        ; テーブルの要素（+0 が 8 バイト）
412104  mov   [rbp+0x38],rax         ; ← [rbp+0x38] の書き込み
412108  add   [rbp+0x48],1
41210f  mov   [0x15eac98],eax
412115  cmp   [rbp+0x38],0
41211a  je    0x412129
41211c  mov   rax,[rbp+0x38]
412120  cmp   qword [rax],0
412124  je    0x412129
412126  call  [rbp+0x38]             ; 対象の call
```

- 0x412126 の直前の命令は 0x412124 の `je 0x412129`（`[rax]` が 0 なら飛ばす）。
- `[rbp+0x38]` の書き込み元:
  - f_4120c0 の範囲内で書き込むのは 0x412104 の 1 箇所だけ（実測）。その元は、テーブル要素 `[[0x15eac90]+8 + 添字×16]`。
  - f_4120c0 の範囲内に `[rbp+0x38]` のアドレスを取る `lea` は無い（実測）。
  - f_4120c0 の外からの `[rbp+0x38]` への書き込み（別の関数が同じスタック位置を書く経路）は、網羅していない（未検証）。ただし、0x412126 の直前の値は 0x412104 の書き込みで決まる、という読みは、f_4120c0 の 0x4120c0〜0x41214b の逆アセンブル（実測）に基づく。
  - 呼び出し元は 0x412295 の 1 箇所（f_412160 の中）。f_4120c0 が呼ばれるのは `[rbp+0x170] == 1` のとき（実測。`indirect-readers-852.md` の既存の記録と一致）。
- 呼び出し元の 0x412160 から見ると、`[rbp+0x38]` は 0x412104 の書き込みで毎回作られる。値の由来は次の節。

## 2. 実行時の到達回数と値（実測）

複製: `lift/out-slot/out/after-slot.c`（`out-seed-final/out/after-seed41d050.c` のコピー。0x412126 の直前に probe を 1 つ入れた。元の 0x412126 の文は `L_412126_call` という名前で残した）。

probe の内容: `static` カウンタを増やし、`[rbp+0x38]` の値と `rsp`（rbp と同じ値）を stderr に出す。

ビルド: `lift/out-slot/build.sh`（`out-seed-final/build.sh` と同じ手順。出力は `out-slot/` の中のみ）。
実行: `lift/out-slot/flengine-after-slot`、入力は `binaries/win64/FLEngine_x64.dll`、harness の既定（entry 0x1376820、rdx=1）。
ログ: `lift/out-slot/run1.txt`。

| 項目 | 結果 |
|---|---|
| 0x412126 の到達回数 | 1 回（`SLOT 0x412126 hit=1`） |
| `[rbp+0x38]` の値 | 0x41e7e0 |
| rsp（= rbp、f_4120c0 の内側） | 0x76239ebffc20（ASLR の影響を受ける実行時の値） |
| 停止 | `fle_dispatch_miss`、dispatch target 0x41e7e0（前回の本番の停止と同じ） |
| 呼び出し深さ（停止時） | 4（#0 f_4120c0、#1 f_412160、#2 f_41d8f0、#3 f_1376820） |
| 関数の入口（呼び出し回数） | 17（前回の本番と同じ） |
| 0x412126 の call の戻り先 | 0x412129（f_4120c0 自身の戻り先は 0x41229a。別の値） |

probe の文を入れても、停止の位置・関数の数・深さは本番（`run-after-seed41d050.txt`）と同じ。probe が挙動を変えていない、という意味の実測。

## 3. 値の正体（実測）

- 値 0x41e7e0 は、閉包の外の関数（内部、IAT ではない）の先頭（`sub DWORD PTR [rip+0x11cdae1],1` で始まる。`seed-0x41e7e0.md` と同じ）。
- 閉包内の関数、IAT、データのいずれでもない。
- したがって、f_4120c0 の 0x412126 が実行時に 0x41e7e0 を呼ぶ、という推測は、この 1 回の実行で確かめられた（実測）。

## 4. 結論: 0x41e7e0 を seed に加える根拠は、実行で確かめられたか

**yes（この 1 回の実行の範囲で）。**

根拠:
- 0x412126 の `[rbp+0x38]` の実行時の値は 0x41e7e0 だった（1 回の到達。実測）。
- その呼び出しは、0x41e7e0 への dispatch miss として止まった（実測）。

ただし、次は確かめていない（未検証）:
- 入力を変えた実行（harness の rdx 以外の入力、他の entry）での値。1 回の実行でしか見ていない。
- テーブル要素 `[[0x15eac90]+8]` の 0 番目が、どの書き込みで 0x41e7e0 になったか。書き込みは追跡していない。静的には `[0x15eac90]` を書く命令は見つからなかった（`0x15eac90` の出現は読み出しのみ。grep の結果。ただし間接の書き込みは網羅していない）。
- 0x41e7e0 を seed に加えた後の挙動（その先で別の dispatch miss が出るか）。`extra-seed-run.md` の記録と同様に、加えて実行するまでは分からない。
- seed に加えるかの判断は PM が決める。本記録は既定の生成 C と seed を変えていない。

## 5. 残りの作業量（見積もり）

- 本番の既定値は変えていないので、seed 追加の実施（生成 C の再生成、ビルド、実行）は、PM の決定の後（未決）。
- 追加で確かめるなら: (a) テーブル要素の書き込み元の追跡（`[0x15eac90]` の値の由来）、(b) 別の入力での 0x412126 の値の確認。どちらも今回は未実施。
