## 先頭の事実（実エンジン・実ブラウザ。代役・再生・推測の成果物なし）
1. **原因の層を特定した**。取りこぼし 19 件（観測した移動に触れない版 A+B+C の 2,760 周期 = 0.69%）の**全件**で、直前の周期の Escape が `fle_input_host_key` に届いていない（エンジン内の `REC injk` が無い）。ページ側の記録を付けた 16 件では、Escape を送った時点の `document.activeElement` が **`#desktop` ではなく `panel-toggle`（ページの "Monitor" ボタン）**で、ページの入力カウンタ（`inputEvents`）は Escape の前後で増えていない。→ ポップアップが開いたまま → 次の周期の File クリックはポップアップを閉じる操作になり、ドライバが「6 s 以内に見えない」と数える。**ランタイム（lift したコード）の入力順序・時刻の問題ではなく、ページのキー入力の経路（`app/src/input/pointer.ts`: キーのリスナーは `#desktop` にだけ付く）**。
2. フォーカスは**ブラウザが勝手に移す**: ページ側の記録（`focusin`/`focusout`、`HTMLElement.focus` の呼び出し）では、`focus()` の呼び出しは `#desktop` への物（ポインタ押下）だけで、`panel-toggle` への移動は**スクリプトの呼び出しもポインタ押下も Tab も無い**（`focusout desktop → rel=panel-toggle`、`focusin panel-toggle`）。`document.hasFocus()` は真のまま。頻度はページ側の記録を付けた 540 周期で 12 回（約 1/45 周期）、取りこぼしはその移動がクリックと Escape の間（周期の約 1/3）に起きたときに出る（0.7% と整合）。**ブラウザが移す引き金は未特定**（`Page.bringToFront`・`Emulation.setFocusEmulationEnabled` では再現せず）。依頼者の機械で起きるかは**未確認**（本番ページの欠陥としての露出はある: 起きればキーは次のクリックまで全部落ちる）。
3. **ツール側ではない**: CDP の `Input.dispatchKeyEvent` は全回成功（エラー 0）、ドライバの `dropped` は 0、`injected` は `inputEvents` と一致。ツール側の欠陥は別に 1 つ（Escape が効かなくても次の周期へ進む `waitWindow` の戻り値の無視 — 取りこぼしの見え方を作っていた。次版で直す）。
4. ランタイムの再入（ci1-input）は本件の原因ではない（報告2のとおり。`NESTED-synth` 0 件、キューに溜まった状態での注入 0 件）。

## ページ側の修正 `ci1-page-focus.diff`（app/src/input/pointer.ts + 単体テスト。旗なし）
- 内容: `#desktop` の `focusout` で `relatedTarget`（行き先）が別のコントロールのとき、**ユーザーの操作（直近 1 s のポインタ押下か Tab）が無く、行き先がテキスト入力でなければ**、次のタスクで `#desktop` にフォーカスを戻す。ユーザーがボタンを押した／Tab で移した場合、ファイル窓の入力欄、行き先なし（body へ）は触らない。`-` 行は 1 行（先頭コメントの句点を続きに変えるだけ）。免責は『行き先のコントロール自身（またはその内側）へのポインタ押下』か Tab のみ、1 s 以内。
- 先の 3 案は**効かなかった**: 案1・2（ウィンドウの blur/focus を鍵にした）は、私の `window` キャプチャ付き `blur`/`focus` の記録が要素の blur/focus も拾っていて、ウィンドウの blur/focus を鍵にしたこと自体が誤読（ウィンドウ単位の blur/focus が起きたかは記録から確認できない）。案3（要素の focusout を鍵にした）は、『直近 1 s のポインタ押下』を**どの要素への押下でも**免責にしていたため、メニューを開いた #desktop 自身へのクリックで免責され、効かなかった（表の D）。案4 は免責を『その行き先への押下か Tab』に限った。
- 決定的な確認（実ブラウザ）: 最後の #desktop へのクリックから 0.4 s 後にスクリプトで `panel-toggle.focus()` → 300 ms 後の `activeElement` は、案4 のページで **desktop**、案3 のページと無修正のページでは **panel-toggle のまま**（観測された失敗の形そのもの）。
