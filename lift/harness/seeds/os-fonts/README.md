# Substitutes for the operating-system fonts the engine asks for (decision 0236, provisional; msgothic.ttc added for O16)

The engine asks the file system for `C:\Windows\Fonts\arial.ttf`, `tahoma.ttf` and `lucon.ttf` (decision 0148: `FontCache_AcquireFont`, 84, 26 and 7 requests while the reference project is opened).
The virtual volume had none of them, so the text of some controls was not drawn (for example the list of "Problems loading the project", whose font is Lucida Console).
The four rows at the end of `../vfs-seed-idle1.tsv` put these files on the volume. They are **substitutes**, not the Microsoft fonts (which cannot be distributed):

| guest path (`C:\Windows\Fonts\`) | file here | font | SHA-256 | choice |
|---|---|---|---|---|
| `arial.ttf` | `LiberationSans-Regular.ttf` | Liberation Sans Regular 2.1.5 | `075e71be4c58beda172ecb574a799308f04c3d054c6a5b7434954d3b0f1b28d8` | S-font-arial (decision 0148): a face designed to be metric-compatible with Arial |
| `tahoma.ttf` | `DejaVuSans.ttf` | DejaVu Sans 2.37 | `b4c632e3cdf9acc7f28758fb5a323c8524d7fc6660d46904d9b6cbe2809c419c` | S-font-tahoma (decision 0148): wider than Tahoma (measured in 0148 §3.9: the pixels of the button strip do not change with another face) |
| `lucon.ttf` | `DejaVuSansMono.ttf` | DejaVu Sans Mono 2.37 | `a54dca07c76d6289e717e75e0a58c0128f6d7269ef3faf76417c9d7d3bba37ab` | S-font-lucon (decision 0148): a monospaced face for Lucida Console |
| `msgothic.ttc` | `NotoSansCJKjp-subset-msgothic.ttc` | Noto Sans CJK JP Regular 2.004, a subset (7,171 glyphs), TrueType outlines, a TTC of one face | `1ab00fd8ffe15553c16ef441b6a63e539159d560491c70fbc598d26f470eea69` | S-font-msgothic (O16, 11-07): the engine's text drawing (QuickFontCache) lists the fonts it can fall back to by probing fixed file names under `C:\Windows\Fonts` (`msyh.ttc`, `malgun.ttf`, `batang.ttc`, `msgothic.ttc`, `arial.ttf`, `tahoma.ttf`, `seguiemj.ttf`, `segoeui.ttf` in the Wine run; two more names, `msjh.ttf` and `msjh.ttc`, are in the binary); a character that the font asked for does not have is looked up in that list. Without a face that has Japanese the text of the project (channel, clip and file names) is drawn as boxes. |

`segoeui.ttf`, `MS Sans Serif.ttf` and `Fruity microfont.ttf` are deliberately not substituted (decision 0148 D2; with a Segoe UI substitute the hint bar wraps: PM, decision 0236).

**`msgothic.ttc` is different from the three rows above in four ways.**
1. It is a **modified** file, not a byte-identical copy: a subset of the `Noto Sans CJK JP` face (`fonts-noto-cjk 1:20240730+repack1-1build1`, `/usr/share/fonts/opentype/noto/NotoSansCJK-Regular.ttc`, face 0) with **ASCII, NBSP, general punctuation and arrows (U+2010-2027, U+2190-219F), CJK symbols, hiragana, katakana (U+3000-30FF), full-width forms (U+FF01-FFEE) and all of JIS X 0208 (6,879 code points: symbols, level 1 and level 2 kanji; the source lacks U+2252)**, converted to TrueType outlines, hinting and layout tables removed, wrapped in a collection of one face. Its glyphs are those of Noto Sans CJK JP, **not** those of MS Gothic. It is licensed under the SIL Open Font License 1.1 (`COPYRIGHT-fonts-noto-cjk-jp.txt`; copyright 2014-2021 Adobe; no Reserved Font Name is declared, so the family name is unchanged).
2. **The engine reads the whole file at start-up**: in the Wine reference run (measured 11-07, `WINEDEBUG=+file`, `tools/ja-run.sh p0-font`) the main thread probes the names above about 0.9 s after FL64.exe starts, and, when `msgothic.ttc` exists, opens it and reads all 2,123,288 bytes in one `ReadFile` about 1.1 s after the start, before the first window is drawn. That is why the row is an **eager seed** (a lazily fetched file would make the start-up wait for the fetch). The seed grows by 2,123,288 bytes (about 1.14 MB brotli-compressed).
3. With the file present the Wine reference draws Japanese channel names (`サンプラー`, `ぷにぷに電機　日本語ボリューム`); without it the same project shows boxes (measured, `j4-none` / `j4-font`, 11-07). Latin text is not affected as long as the font the engine asked for has the characters.
4. The file is made by `tools/make-msgothic.py` (in the measurement directory of opt1; a copy is in `lift/out-git/opt2-results/0320/font-seed/tools/`): `PYTHONPATH=<venv with fonttools 4.68.0, brotli 1.2.1> python3 make-msgothic.py OUTDIR` writes `OUTDIR/msgothic.ttc` (the one-face collection) and `msgothic.ttf` (the same face as a plain TrueType); `MSGOTHIC_TIER=S1|S2|S3` chooses the character set (the committed file is S3). The build is **reproducible** (`head.modified` is kept from the source; two builds give the same SHA-256).

Origin of the first three: the files are byte-identical to those of the Debian/Ubuntu packages `fonts-dejavu-core 2.37-8build1` (`/usr/share/fonts/truetype/dejavu/`) and `fonts-liberation 1:2.1.5-3build1` (`/usr/share/fonts/truetype/liberation/`).
The licence texts of the two packages are next to them (`COPYRIGHT-fonts-dejavu-core.txt`: Bitstream Vera / Arev / public-domain additions, free to redistribute; `COPYRIGHT-fonts-liberation.txt`: SIL Open Font License 1.1).
The first three files are not modified (the OFL's reserved font name concerns modified versions; the guest file name `arial.ttf` is only the name on the virtual volume, the name table of the font is unchanged).

`ci/lib/extract_fl.py` copies the rows whose host path is under `lift/harness/seeds/os-fonts/` from the checkout to HOST_ROOT and checks their SHA-256; `ci/plan.sh` already hashes the whole `lift/harness/seeds` directory into the seed key.
