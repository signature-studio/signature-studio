## 2. 読み(手順 2)

- (a) `pvReserved` の位置: `lift/runtime/fle_ole.h` の 3 行目「arguments in R[1] (rcx), R[2] (rdx) …」。よって `CoInitialize` の `pvReserved`(第 1 引数)は `R[1]`。`fle_ole.c` の `com_init` が `R[1]` を見るのは正しい(誤りの可能性は無い)。
- (b) `CoInitializeEx` の引数: 第 1 引数(`pvReserved`)は `R[1]`、第 2 引数(`dwCoInit`)は `R[2]`。`fle_imp_CoInitializeEx` は `(uint32_t)R[2]` を読む。
- (c) 位置の影響: `lift/crates/fe-lift/src/imports_table.rs` の `resp_va(k)` は `RESP_VA_BASE + RESP_VA_STEP * (k + 1)`(`k` は `TABLE` 内の位置)。末尾に足せば既存の行の VA は動かない。ただし `tests/deferred.rs`・`tests/wall_fr*.rs` は「末尾から数える」形で行の位置を固定している。下の 4 で扱う。
- Learn の `CoInitializeEx`(取得済み): `pvReserved` は NULL。`dwCoInit` は COINIT の組み合わせで、APARTMENTTHREADED と MULTITHREADED の同時指定だけ不可。既定値は MULTITHREADED(0)。
- Learn の `COINIT`(取得済み): APARTMENTTHREADED = 0x2、MULTITHREADED = 0x0、DISABLE_OLE1DDE = 0x4、SPEED_OVER_MEMORY = 0x8。

### 3.1 行を末尾に置いた理由(計画からの逸脱)
