## 2. 再計算(16 本)

ずれ: 依頼の「14 本」は、R4-4d の 8 本と R4-3 の 6 本の数。`tools/verify-kit/out/` には `-reference-swapin` の 2 本(`p3-chrome-3-reference-swapin`、`p3-mixmove-chrome-2-reference-swapin`)もあり、合計 16 本。ここでは 16 本すべてを出す(2 本は群を「対象外」と書いた)。

スクリプトは `TMPDIR` の `r44h-mixer.py` に置いた。リポジトリには commit しない(読み取りだけ)。`pulses[].mixer` と `pulses[].epoch` だけを使う(`evidence/R4-4g.md` §3・`tools/verify-kit/tools/r44e-threads.py` の `pulses` の読み方と同じ)。

実行コマンド: `source scripts/env.sh && python3 -B "$TMPDIR/r44h-mixer.py" /home/ubuntu/work/signature-studio/tools/verify-kit/out`

スクリプトの全文:

```python
#!/usr/bin/env python3
# r44h-mixer.py (TMPDIR only, not committed): reads pulses[].mixer of every out/*/audio-p3.json.
# Prints per run: group, pulse count, the mixer of the last pulse, the set of mixer values,
# ms from the first pulse to the first pulse with mixer == 18 (or None), and the count of
# pulses where mixer changes away from 18 after it first became 18. Standard library only; reads only.
import glob
import json
import os
import sys

OUT = sys.argv[1]
R44D = {'r44d-mix0-1', 'r44d-mix0-2', 'r44d-mix5-1', 'r44d-mix5-2', 'r44d-mix10-1', 'r44d-mix10-2', 'r44d-mix20-1', 'r44d-mix20-2'}
R43 = {'p3-chrome-1', 'p3-chrome-2', 'p3-chrome-3', 'p3-mixmove-chrome-1', 'p3-mixmove-chrome-2', 'p3-mixmove-chrome-3'}

files = sorted(glob.glob(os.path.join(OUT, '*', 'audio-p3.json')))
print(f'files {len(files)}')
print('| 群 | run | pulse 数 | 最後の mixer | mixer の値の集合 | 最初の 18 まで(ms, 最初の pulse から) | 18 から外れた pulse 数 |')
print('|---|---|---|---|---|---|---|')
for f in files:
    name = os.path.basename(os.path.dirname(f))
    if name in R44D:
        grp = 'R4-4d'
    elif name in R43:
        grp = 'R4-3'
    else:
        grp = '対象外(reference-swapin)'
    a = json.load(open(f))
    P = sorted(a['pulses'], key=lambda p: p['epoch'])
    e0 = P[0]['epoch']
    mx = [p.get('mixer') for p in P]
    vals = sorted(set(m for m in mx if m is not None))
    idx18 = next((i for i, m in enumerate(mx) if m == 18), None)
    t18 = None if idx18 is None else round(P[idx18]['epoch'] - e0, 1)
    away = 0
    if idx18 is not None:
        away = sum(1 for m in mx[idx18:] if m != 18)
    print(f'| {grp} | {name} | {len(P)} | {mx[-1]} | {vals} | {t18} | {away} |')
```

## 3. 結論(根拠 3 点)

1. **番号は `T[]` の添字**。`fle_thread_current` は `nthr ? cur : 0` を返し(`fle_thread.c:163`)、`switch_to` の `cur` も添字(`:477-481`)。guest に見える ID は `FLE_EMULATED_TID + 添字`(`fle_imports.c:21`、`fle_imports.h:12`)。
2. **18 は、直近の DirectSound Unlock を呼んだスレッドとして記録されている**。`fle_dsound.c:1138-1144` → `fle_audio_transport.c:163` → `:156`。値は「直近の Unlock の呼び出し元」で、全部の呼び出し元ではない。コードの変数名 `mixer_thr` は名前であり、FL Studio の処理の役割の根拠ではない。
3. **開始アドレスは `t->start`(`fle_thread.c:1022`)に保存されるが、`pulses[].threads` には出ない**。出るのは停止時の `fle_thread_report`(`fruity.c:750-753`、`report_threads` の `:585-586`)だけ。`pulses[].threads` は `[a, b, c]` のみ(`fle_audio_transport.c:102`)。名前・作成時刻は `thr` 構造体に無い(`:118-147`)。

0 は `T[0]`(`fle_thread.c:292-302` の `ensure_init` が作る最初のスレッド)。CreateThread で作られたスレッドかは未確認。役割は未確認(UI スレッドかどうかも未確認)。

**既存の保存値だけでは、スレッド 0・18 が FL Studio のどの処理かは絞れない。**

## 4. 次の調べ方
