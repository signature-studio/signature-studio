## 3 1 回目(164c8ed4): 実行で止まる(push 済み)

- bundle の作り方: deploy.yml の step 8・9a・9b・9c・10(R6-31 の手順)。step 9c の hybrid は通った(`hybrid: 178730055 bytes, 8 direct modules`)。
- 実測: Problems の読み込みの途中で、`fle: indirect call to 0x8806f80 is not a known function entry [guest return 0x881101d]` で停止。3 回とも同じ(`r56c/measure`、c6new1〜3)。対照の 3 回は止まらない。
- 原因(確かめた事実): 0x8806f80 は Soundgoodizer の RVA 0x6f80。`jmp qword [IAT]` の thunk で、IAT 先は kernel32!RaiseException(thunk の並び 0x6f80・0x6f90・0x6fa0 は RaiseException・RtlUnwind・RtlUnwindEx)。pdata に無く、直接の call の先でもない。生成 C の `L_88113bd: R[0] = UINT64_C(0x8806f80);` が、その thunk のアドレスを作る(`lea rax,[rip-…]`)。その値を間接 call したため、lift の既知の入口(pdata・直接 call・seed)に無い関数として止まった。
- データ部から thunk を指すポインタは 1 件(RVA 0x22c80)。lift 済みの C で、thunk のアドレスを作る lea の定数は 18 種類(決定 0409 の 10)。
- 分類: (b)(lift の既知の入口の契約。`--seeds` の既存の仕組み)。対応: 18 件を seed に足す(soundgoodizer-8800000-seeds.txt(e27ad00f で追加。revert 済み))。
- 注: 1 回目の bundle は main のワークツリーで commit された(164c8ed4)後、他の worker の push で origin に入り、deploy の run 43961833150(headSha fa751e1a。in_progress)が、その engine を fl-Oz に載せた。main に報告済み(main の判断: 止めない。`docs/failures/0023` の追記)。

## 4 2 回目(e27ad00f): 止まる(exit 134)
