## 7 訂正と原因の確定(2026-11-17。§2・§3・§6 の番地と判定を置き換える)

### 7.1 番地の訂正

- 呼び先のスロットは RVA 0x3503A0 である(0x3500A0 は誤り)。`mov rax,[rip+0x13ad9a]` は 0x215606 の直前にあり、0x215606 + 0x13AD9A = 0x3503A0 で誤りは手計算の 1 桁。
- 出典: 生成 C `work-r56e/gen2/src/m11-02.c:110847`(`L_92155ff: R[0] = fle_ld(UINT64_C(0x93503a0), 8)`)。`grep -rn 93503a0 work-r56e/gen2/src` の結果は 1 件(読み取りだけ。書き込みは 0 件)。
- PE の確認(`fruity_parametric_eq2_x64.dll`、読み取り。`evidence/R5-6f/pe-slot.mjs`、出力は `evidence/R5-6f/pe-slot.txt`):
  ```

  slot RVA 0x3503a0 section .data file offset 0x34efa0
  raw 8 bytes 20f2750000000000
  ```

  RVA 0x3503A0 は .data に入る。reloc 表に DIR64 の項目がある。0x9000000 基準では 0x935F220。

### 7.2 呼び先の表(ILVideo の関数表)

- 0x935F220 は ILVideo の関数表(0x935F188〜0x935F230、8 バイトごと)の 1 件。出典: `m11-02.c:54278`(`L_91d9624: R[2] = UINT64_C(0x935f220)`)。
- 表を埋める工程: 0x91D9390(`m11-02.c:54106`)は、LoadLibrary の結果を 0x935F240 に書く(54119)。その値が 0 なら、GetProcAddress の工程(54121 の後)を通らずに戻る(54121・54130〜54165 の分岐)。0 でなければ、0x91D9340(`m11-02.c:54079`)が GetProcAddress の結果を [R3] に書く(54091)。
- 表は、ILVideo の LoadLibrary が成功したときだけ埋まる。

### 7.3 原因の連鎖

1. 0x2155B0 が ILVideo の読み込み 0x91D9390 を呼ぶ。戻り値は見ない(`m11-02.c:110837`)。
2. 0x91D9390 が LoadLibraryW("ffmpeg\x64\ilvideo_x64.dll") を呼ぶ(0x91A4040 の経路)。計測 1 の実測: 結果 0(§1)。
3. ハンドルが 0 なので、表は埋まらない。0x935F220 は 0 のまま。
4. 0x2155B0 は 0x93503A0 → 0x935F220 の値を call する(`m11-02.c:110847`〜`110848`)。0 なので停止する(`indirect call to 0`)。
5. Windows では ILVideo が読めて表が埋まり、この呼び出しは通る(読み。Windows での計測は 0 件。未確認)。

停止の時点の値: 0 である(実測)。計測 3 の raw: `trc3-tail.txt` の 2295 行(呼び先の値 0 で停止)と 2301 行(rax = 0x935F220)。§6b。0 の原因は、上の 3 の工程(ハンドルが 0 で表が空)と読む。r56e の計測版で表の中身を直接読む計測は、この計測の範囲では行っていない。
