## 1. P3 の定義(出典)

- `docs/core/performance.md` §1: P3 は「枯渇カウンタ、書き込み率(Unlock したフレーム ÷ 実時間のフレーム。目標 0.95)、underrun の quanta」。この 0.95 は参照値で、この表は判定しない。
- `tools/verify-kit/tools/p3-win.py`(10 秒窓): 書き込み率 = Unlock フレーム ÷ (10 × 44100)。消費率 = worklet が読んだフレーム。underrun quanta・episodes・engine gap frames は窓の両端の差分(2 s ごとの snapshot を線形補間)。
- `tools/verify-kit/tools/s3a-summary.py`: 0.95 未満の窓数・最長の連続(longestRunQuanta × 128 / 44100 s)。§6 の不具合を参照。

## 6. 既知の欠け・誤り(報告)

1. 書き込み記録の上限: `app/src/audio/page-audio.ts:51` の `KEEP_UNLOCKS = 2400`(`keepLast` は :52、:137)。ページは最後の 2400 件の Unlock だけを残すため、今回の 6 run すべてで最初の約 73〜90 s の書き込み記録が無い。書き込み率はその窓を `-` とし、0 とはしていない。`s3a-summary.py` は記録の無い窓を 0 と数えるため、その出力の「書き込み率の平均・最小・0.95 未満の窓数」と「条件 1 の 0.742」は誤り(この表では使っていない)。app/ は変更していない。
2. `s3a-summary.py` の「音楽 / 実時間」の列は、窓を 300 s に切る一方で音楽は最後の pulse まで数えるため、条件 2 が 1.073 と出る(実際は 321.5 / 321.7 ≈ 1.0)。この表では実時間の窓で再計算した値を使った。
3. `s3a-summary.py` の条件ごとの表は、フォルダ名を `s3a-r…` の形で割るため、今回の名前(`p3-chrome-N`)で IndexError になる(表の前半は出る)。
4. `p3-win.py` は `<prefix>-<browser>-(prev|new)-N` の名前だけを読むため、今回の run は読めない。上の表は、同じ定義で手で計算した値。
5. 条件 2 の下の 0.95 未満の窓(7〜8 窓)は、マウス移動と同じ時間帯に集中しているかを、この表から判断していない。
