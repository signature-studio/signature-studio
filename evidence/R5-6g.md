## 7 PEQ2 が ILVideo を何のために呼ぶか(事実と推測を分ける)

事実(生成 C `work-r56e/gen2/src/m11-02.c`。PEQ2 の RVA で示す):
- ILVideo の関数表は **22 本**の名前で GetProcAddress する(`0x91d9390` → `0x91d9340`。名前は UTF-16 の文字列、RVA 0x1d96d4 以降)。表の名前は `ILVideo_createDecoder`・`ILVideo_openFile`・`ILVideo_startDecoder`・…・`ILVideo_LoadBitmap`・`ILVideo_SaveBitmap`・`ILVideo_createEncoder`・…・`ILVideo_GetAudioDuration`。**ILVideo の 26 件の export のうち、この 22 本が全部ある**(`ILVideo_x64.dll` の export 名表。欠けは 0 件)。
- 呼び出しは `0x2155b0` の 1 か所だけ(`f_91d9390` の呼び出し元。`m11-02.c:110837`)。そこから表の `ILVideo_LoadBitmap`(表の slot `0x935f220`。`m11-02.c:110847`)を呼ぶ。
- 呼び出し元の判定: `0x2155b0` を呼ぶのは 2 箇所。`0x9214988`(`m11-02.c:109980`。`0x2148b0` の本体の中)と `0x9214955`(`m11-02.c:109997`。`0x921494c` の中。その呼び出し元は未特定)。後者は同じ引数の並びを使う。`0x2148b0` は拡張子の表(UTF-16 の 4 件: `.BMP`・`.PNG`・`.TGA`・`.WEBP`。`0x92149e4` 以降)と `0x91adfa0` の比較で分岐する。`0x91adfa0` は 0 始まりの添字を返し、一致なしは −1(`m11-02.c:20327`〜`20361`)。比較は Delphi の文字列の等しさ(`0x9010840`)。
- **結論(読み)**: 拡張子 **`.WEBP`(添字 3)** のとき、`ILVideo_LoadBitmap` が呼ばれる。`.BMP`・`.PNG`・`.TGA` は、ILVideo を使わない別の経路(`0x91339d0`・`0x9214dd0`・`0x92151e0`)。

## 8 lazy の選択肢(事実。判定は main)

- 事実: 線形メモリの DLL の image は、起動時に全部写される(`main_two.c` の image 読み込み)。wasm のコード(S1 の分子)は、遅延にしても減らない: S1 は lift したコードの大きさを数える。

- DLL pack の非コード部だけ配る案(0320 B)は、**未確認の仮説**(engine がコードの bytes を読まない前提)。
- S1 を守る唯一の道は、wasm を分けて、閉包を別の wasm の単位にすること。その場合、S1 の分子を『本体の wasm』にするか『全部の wasm』にするかは、S1 の定義で決める必要がある(`performance.md` の S1 の文言は読んでいない → 未確認)。
