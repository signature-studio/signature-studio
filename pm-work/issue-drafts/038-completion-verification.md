## 目的

完成の条件(台帳 L-033)の最終の判定。6 つの課題(C-1〜C-6)と、P1・P2・P3 の最終の実測を、同じ道具で行い、判定の語(「受理」「差し戻し」「未確認」)を付けて報告する。

## 規模

規模: 大(想定 6 時間。最終の実測は、P3 の 3 回の再生と、P1 の 3 回の起動を含む)

## 背景

- 判定の基準(各子 Issue の基準を、ここでまとめる):
  - C-1 HiDPI: 拡大率 1・1.5・2 で canvas の幅と高さが CSS × 拡大率(±1 画素)。(子 006)
  - C-2 描画の分離・P3: 描画の Worker の分離が実測で確かめられ、所定のプロジェクトの underrun が 0(n=3)。(子 002・004)
  - C-3 必要な物: 言語・テーマ・テンプレートが、インストーラの一覧と件数が一致し、見つからないファイルが 0。(子 013・016・017)
  - C-4 内蔵: 全件(VFX 系を除く)が起動確認を通り、起動後に届く。(子 019〜023)
  - C-5 外部: Serum 2・OTT・Vital が既定の経路で読み込まれ、1 ブロックの音声を処理する。(子 025〜029)
  - C-6 トップバー: 3 部品でメニューが出て、項目を選ぶと値が変わる。(子 010・011)
  - P1: 起動の中央値(n=3)が 10 秒以内。(子 034・035。測り方は 034 で確定)
  - P2: 120 fps と、入力から画面の p95 が 17 ms 以下(子 007・008。60 Hz の表示の扱いは QUESTIONS 7)。
- 入力: 所定のプロジェクト(子 004 と同じ入力)。

## 読む物

- 各子 Issue の成果物(測定の道具の出力)
- `pm-work/milestones.md`(完了の条件)

## やること

1. 子の Issue の結果を、判定の表にまとめる(課題・基準・測定の値・判定)。判定は、出力の行で示す。
2. 最終の実測を行う。P1(3 回)、P2(拡大率 1 と 2)、P3(所定のプロジェクト、n=3)。同じ道具で行う。
3. 判定の表を報告に書く。「受理」でない物は、理由を書く。
4. 判定の確認の道具 `tools/final-verify/run.sh` を作り、上の基準を全て確かめる。run.sh の基準は、この本文の基準と一致させる。

## 受け入れ

```accept
bash tools/final-verify/run.sh
```

判定の基準: run.sh の終了コードが 0(C-1〜C-6 の全てが受理。P1・P2・P3 の最終の値が基準を満たす)。run.sh の判定の数値は、この本文の「判定の基準」と一致していること。

## 報告の規則

- 1 行目は「実エンジン: <何を実行し、どの出力を観測したか>」で始める。
- 測定の値には「runner の値。この機械とは別枠」と書き、nproc と loadavg を添える。
- 「達成」と書かず、「受理」「差し戻し」「未確認」のいずれかにする。出力の行を付ける。
- 判定の表(課題・基準・測定の値・判定)を報告に書く。判定が「受理」でない課題は、理由を書く。
- 耳の確認は行わない。「音が途切れない」とは書かず、underrun の数で書く。

## 制約

- 製品に新しい環境変数・#ifdef・URL パラメータ・ビルド変数を足さない(L-002)。
- 依頼者の個人のプロジェクトを、リポジトリに入れない。
- ベンダー名と Cloudflare の識別子を書かない(L-005・L-006)。
- 作業者に依頼者の個人の資格を置かない(L-011)。
- sleep・timeout・nohup・末尾の `&` は使わない。
