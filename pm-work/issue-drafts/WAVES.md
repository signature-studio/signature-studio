# 起票の波(持続的な起票の計画)

起票は初期投入で終わらせない。目標: ブロッカーの無い task を常に 60 件以上にし、60 の作業を動かし続ける。起票は PM が行う。

| 波 | 起票の合図 | 起票する内容 | 件数(目安) |
|---|---|---|---|
| 初期 | 依頼者の承認 | 下書き 39 件(INDEX.md)。即時に起動するのは 10 件 | 39 |
| 第 2 波 | #{{125}}・#{{126}}・#{{127}} が閉じた後(`lift/plugins/` の仕組みと、2 本目の確認と、道具が main に在ること) | 内蔵プラグインを、プラグインのフォルダ単位で 3 フォルダずつ束ねた Issue にする(45 束。Effects 29 束・Generators 16 束。`pm-work/tools/gen-wave-plugins.mjs` が `inputs/plugin-classes.tsv` から作る)。フォルダは、本体の DLL と、その補助の DLL を含む(同じフォルダに在る)。各 Issue に、フォルダごとの本体と補助の DLL(名前・大きさ・SHA-256・export・import・hook の要否)を本文に入れる。除くのは、#{{015}}・#{{019}} が扱う 3 フォルダと、VFX 系のフォルダ 7 件(OpenGL を import する DLL を持つ。#{{039}} で後から入れる)。hook 点の表(#{{104}} の `inputs/plugin-hooks.tsv`)に行が在る DLL は、その 3 つの RVA を使う。#{{125}} の仕組み(`lift/plugins/<名前>/plugin.tsv` を足すだけ。共有のファイルは変えない)を使う | 45 束(対象のフォルダ 131 件) |
| 第 3 波 | #{{031}} が閉じた後 | 命令数の分布に基づく性能の Issue(関数の塊ごと。1 関数 1 タスクにしない) | 未定 |
| 第 4 波 | #{{025}} と #{{026}} が閉じた後 | 外部プラグインの個別の Issue(3 件。作業が大きければ分ける) | 未定 |

- 第 2 波を #{{101}}・#{{102}}・#{{103}} の後に置く理由: 今のエンジンは、内蔵のプラグインを 10 モジュールと一緒に 1 つの wasm(engine.wasm。約 169 MB)に連結する。内蔵を足し続けると、単一の wasm がブラウザの読み込みの上限(約 1GB。依頼者の指示)を超える見込みで、起動(P1)にも効く。そのため、像の読みを要求の時まで遅らせ(#{{101}})、プラグインのコードを wasm として分ける型を作ってから(#{{102}})、束の Issue を起票する。#{{103}} の分類で、束の単位をプラグインのフォルダに決めた。#{{104}} は、各本体の hook 点の表を作る。
- 第 2 波の各 Issue の blocked_by は #{{125}}・#{{126}}・#{{127}}。各 Issue が足すのは、自分のフォルダの `lift/plugins/<名前>/plugin.tsv` だけ。共有の表(`ci/extract-dlls.tsv`・`lift/harness/b2d2/modules.tsv`・seed・`lift/harness/web/pack.args`・一覧)は、生成の段が `lift/plugins/` から作るので、どの Issue も編集しない。
- 2026-11-24 の改訂: 第 2 波の型を、共有のファイルを編集する形から `lift/plugins/` の仕組みに変えた(#{{125}}・#{{126}}・#{{127}})。共有の表を 45 件が並行に編集すると、衝突でほぼ全てが失敗する(#{{101}} と #{{102}} の試行の先例)。生成器 `pm-work/tools/gen-wave-plugins.mjs` は、この型の本文(`wave2-template.md`)で、下書きを作る。
- #{{020}}(抽出の表を揃える)と第 2 波は、表の同じ箇所を変える。どちらで行うかは、第 2 波の起票の時に PM が決める。
- 第 2 波は 45 件で、60 件に届かない。第 3 波・第 4 波で補う。
- 閉じた Issue を見て起票するのは PM。作業者は起票しない。
