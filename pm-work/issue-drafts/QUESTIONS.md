# 依頼者の入力が要る点(一覧)

本文の中の「QUESTIONS n」は、この一覧の番号を指す。質問の形では書かず、入力が要る点だけを並べる。

1. 要入力: P3 の所定のプロジェクト(依頼者の個人のファイル)を、作業者が使える形で渡す経路。リポジトリに入れない前提で、取得の経路を決める。対象: 004・031・038。
2. 要入力: 外部プラグインのインストーラ(3 件。`ci/artifacts.lock` の 2〜4 行)を、作業の段が取る経路。案は (a) extract の段で取り、抽出の木に置く(既存の鍵の所在のまま)、(b) 作業の段に読み取りの鍵を渡す(台帳 L-011 に照らして判断が要る)。対象: 025・024。
3. 要入力: 内蔵の件数の確認。依頼者の申告(Effects 約 90、Generators 約 51。台帳 L-034)と、インストーラの実数の差。013 の閾値(Effects の DLL 85 以上、Generators の DLL 45 以上)は、申告から余裕を取った案。実数で閾値を直してよいか。対象: 013。
4. 要入力: OpenGL を使う VFX 系の後回しの範囲(台帳 L-034)。import に opengl32 を含む物を後回しとする案の承認。判定の結果(件数と名前)を見てから決めてよいか。対象: 023・020・039。
5. 要入力: 起動時の「使用状況の送信への同意」の確認ダイアログの扱い。製品の既定の動作を変えるか、測定の道具の中だけで閉じるかの判断。対象: 010・011。
6. 要入力: P1・P2・P3 の定義の出典。`docs/ops/fidelity-and-performance.md` は、リポジトリの履歴に一度も存在しない。旧 ci タスクの記述(P1: ページを開いてから最初の idle まで 10 秒以内。P2: 120 fps と入力から画面の p95 が 17 ms 以下。P3: 所定のプロジェクトで underrun 0)を採用してよいか。対象: 003・004・007・008・034・035・038。
7. 要入力: P2 の 120 fps の判定方法。旧の記録では、この機械の表示は 60 Hz だった。60 Hz の表示で 120 fps を満たせない場合の判定(表示の上限として扱うか、測れないとして「未確認」にするか)。対象: 007・008・038。
8. 要入力: 起動前に取る量の予算(圧縮後の大きさか、圧縮前か)と、engine wasm の大きさの目標(バイト)。対象: 033・035・036。
9. 要入力: M7 の目標値。P3 の再生中の命令のうち、直接 wasm でない関数の割合の上限(%)。対象: 030・031・032(マイルストーン M7 の完了の条件)。
10. 要入力: Epic・Sub-Issue・ラベルの運用案(`pm-work/issue-drafts/LABELS.md` と `GRAPH.md` の起動の規則)を承認するか。承認まで、GitHub に書き込まない(台帳 L-040)。
11. 要入力: インストーラの一覧の置き場所(案: リポジトリの `inputs/fl-installer-files.tsv`)と、作業の段がそれを commit することの承認。対象: 013・017・020。
12. 要入力: 外部プラグインの対象。Serum 2・OTT・Vital の 3 件で足りるか(台帳 L-033 の「多数」の範囲)。対象: 024。
13. 要入力: 抽出の段の鍵(キャッシュの鍵)を変えてよいか。変えると、全件の抽出し直しになり、作業の時間が増える。対象: 020。
14. 要入力: 「100 以上」(L-033)と「約 141」(L-034)の数え方。DLL の数か、名前の数か。対象: 018・021・022。
15. 要入力: Vital を対象に含めるか(台帳 L-033 の「Serum 2・OTT など」に入るか)。含めない場合は、029 を閉じる。対象: 029。
16. 要入力: 完成の判定に、人による耳の確認(音が途切れないこと)を入れるか。この作業は underrun の数だけで判定する(耳の確認はしない)。対象: 004・038。
