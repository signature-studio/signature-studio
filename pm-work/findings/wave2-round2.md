## PM が決める点

1. 上限の向き: 新しい上限は「直した後の値 × 1.05」。直した後の値が現行より小さければ、上限も下がる。残りが大きければ、上限は現行より上がる。
2. 1 MB の比べ: 足す前の bundle は作らない(engine のビルドが 1 回 40〜75 分で、時間が足りない)。259 は、起動の前の 4 種の中のプラグイン由来の大きさを、1 回の bundle の内訳で求める。
3. 261 は、blocked_by に 260 だけを持つ(指示どおり)。ただし、261 の受け入れは `startup-cap-bytes` を読むので、259 が閉じていないと流れ A〜D が上限を超えて落ちうる。
4. 親: 259・260・261 は、親の #1322(内蔵エフェクト)の sub-issue にした(#1537 と同じ)。
5. 259 の受け入れの「道具の 5 行」は、Effector・Emphasis・FL Studio Mobile Rack FX・Fruity Balance・Fruity Filter(main に在る効果)を使う。Sytrus は、道具が効果だけを扱うので使えない。

## 起動の前の取得量の上限(PM の決定。2026-11-29)

- 上限を 314,368,711 から **330,000,000** に直した(`startup-cap-bytes`)。理由: **main の HEAD 自身が 322,450,358 B で、旧い上限を 8,081,647 B 超えていた**(#1545 の実測。engine wasm 175,841,173・DLL pack 77,444,112・seed pack 66,851,297・glue 2,313,776)。プラグインの DLL・wasm・seed・Data は、既に lazy で、起動の前に入っていない(#1545 の実測)。**プラグイン 1 本あたりの起動前の増加は、約 83 KB**(#1439 の 3 本で 250,750 B)で、engine wasm に、プラグインの C 化した部分(98 ユニット。obj で 22,077,694 B)がリンクされているため。
- 起動の前の取得量の削減(プラグインの C 部分を、プラグインごとの lazy の wasm に分ける)は、P1・大きさの別の Issue が受け持つ。
