## 1. File→Open の経路

### 1-1. 本番でネイティブのファイル選択が出る理由(読み)

1. FL の Open は COM の `IFileOpenDialog::Show` を通る(`lift/runtime/fle_filedlg.c:1298-1318`)。1318 行で、wasm では `browser_picker` を使う。
2. `browser_picker`(同 922-1009)は、要求を JSON にして `fle_filedlg_host_pick` でページへ渡し(同 951 行)、答えを `fle_filedlg_host_poll` で待つ(同 953-957 行)。JS 側は `lift/harness/web/filedlg/fle_filedlg_lib.js:12-13`。
3. Worker からページへは `app/src/main.ts:732` の `fileDlgView.show(id, request)`。
4. `app/src/ui/filedlg.ts:75-89` が `<input type="file" id="filedlg-input" multiple>` を作り、`openChooser`(同 92-98)が `input.click()` を呼ぶ(同 93 行)。ユーザー操作の直後なら即座に、そうでなければ次の pointerdown・keydown で。

**native のファイル選択が出るのは、`app/src/ui/filedlg.ts:93` の `input.click()`。** ブラウザは、この click を開いた選択窓として出す。

### 1-2. 経緯(読み・git)

- `c409b2db`(#1481。2026-11-25 22:33 UTC)が、`select` の hook と、`EngineFiles`・`mountFiles`(Files ボタンと OPFS の窓)の配線を外した。コミットの説明は「Files ボタンと Files の窓を作らない。FL の Open は、ブラウザのファイル選択(hidden の input、複数可)で受ける」。

- この設計の元は `pm-work/issue-drafts/wave1ax/195-page-no-html-chrome.md:49` の (a)(「FL の Open ダイアログが、ブラウザのファイル選択を開く」)。#1481 は 195 の下書きから作られた(`pm-work/created-issues.tsv:176`)。2026-11-27 の依頼者の指示は、この (a) と逆。

### 1-3. OPFS の窓が出るところ(読み)

- 今は、どこからも出ない。Files ボタンは `mountFiles` の中にあり、`main.ts` は呼んでいない。窓(`app/src/files/explorer.ts`)の drop の受け口(同 142-144)は、窓の中だけ。
- 配線を戻せば出せる経路は 2 つ。(i) Open・Save の答え(`select` の hook の復活。233)。(ii) メニュー項目からの `FilesHandle.openWindow()`(`mount.ts` の公開の API。235)。

### 1-4. Save・Import・Export(読み。推定を含む)

- Save(`IFileSaveDialog::Show`)も `FileDialogView.show` を通る。`request.save` なら `saveNow`(`app/src/ui/filedlg.ts:48`、`68-73`)。ネイティブの選択は出さず、推定名で答え、`SavedFilesView.add`(同 142-152)が `<a download>` の click でブラウザのダウンロードに渡す。
- Import は Open の型(`IFileOpenDialog`)と推定。書き出し(Export)は Save の型と推定。確かめたのは `Show` の分岐までで、各メニューの呼び出しは確かめていない。
- `GetOpenFileNameW`・`GetSaveFileNameW` の実装は `lift/runtime`・`lift/harness/web` に無い(`grep`)。ダイアログは、COM の共通の窓の経路だけ。
- したがって、ネイティブの選択を出すのは Open 系(Open・Import。推定を含む)だけ。Save 系は、OPFS の窓も無く、推定名で保存してブラウザのダウンロードに渡すだけ。

### 1-5. E2E がこの欠陥を見落とした理由(読み)

- 推定: 選択窓は interception で表示されずに止まり、E2E はファイルが読まれたことだけを見て通る。
